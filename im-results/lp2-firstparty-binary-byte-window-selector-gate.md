## One concrete historical-gate decision

The strongest possible first-party object among the candidates is the **signed 2014 message's own embedded binary payload**. Its typed coordinate records show that Cicada knew how to designate byte-bearing material with a deliberate extraction grammar. But **the signed message does not instruct the reader to reuse those bytes on the unknown LP2 pages**, and the original book does not designate the needed message stream, specific JPEG/MP3, source position, byte projection or cipher inverse. In particular, the openly printed p15 prime square, p33 1033/3301, p49–51 byte table and solved p57 SHED wording cannot each be transferred into an external-file address without introducing choices after seeing ciphertext.

The solved p56 SHA-512 does identify an external object by content hash but supplies no recoverable original bytes in the available corpus; owner-gated #784 owns that separate preimage/source recovery. The signed Stage10 `/key.asc` and personalized return are separately owned by #2287. Neither supplies a present binary key interval for #2293.

**Decision:** do not manufacture an offset by searching file bytes for high-scoring English. The source-authenticated selection tuple is incomplete at **external byte-object identity and operation**, before even reaching a frozen byte index, direction, length, GP29 mapping or receiver. No ≥250-rune original decode/≥150-rune holdout was run because any resulting candidate would be a postselected test without a source input. An archival first-party sentence or picture that explicitly designates a *particular file plus a byte coordinate law* would reopen this branch. Future agents should use the historical reports above instead of replaying `wisdom/folly` pads or the 2014 three-stream XOR.

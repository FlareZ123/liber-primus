## One reversible source-pinned hypothesis

For each **printed ciphertext word**, compute sum `G` of the published GP prime weights; classify * as a prime whose decimal reversal is also prime, + as an ordinary prime, unmarked as composite. At the first word, start with key-pointer direction +1. Advance the key pointer through each ciphertext rune under the direction carried from the **previous** word. After a word is emitted, its `*` sets direction **−1**, its `+` sets direction **+1**, and a composite keeps the existing direction. This is executable during encryption because the current word's output is available before setting the **next** word's direction; it is executable by a solver from printed ciphertext. Using the *current plaintext word* would require already knowing the answer, so it is deliberately excluded.

This is a concrete, **analyst-frozen** interpretation, rather than an instruction proven in the 2013 paste. No source chooses forward initialization, the use of plus/minus as key-pointer movement, treatment of composites, key source or cipher-state convention. The screen freezes established external `pdir=000`, `pad=300`, the canonical source-key library, and the two specified original windows `seg0.7,seg0.8`, with zero fitted nonce/IV/seed. The external engine tests both pointer orientations, modulo29 output signs and its two registered anti-repeat models. ## Decisive interpretation and successor rule

The original source markup and a candidate state model are concrete, but **the intended cipher operation and key are still missing**. The exact candidate, with both pointer orientations, produced no first300 threshold survivor, no authentic plaintext and no useful unknown-page inverse. In addition, the original-primary and later-reconstruction directional markers are negatives of each other *after the first prime-labelled printed word*. The external engine already searches both whole-vector polarities; re-running a second mirrored COUNT marker sweep would almost entirely retread its work.

**Decision:** retire this explicit COUNT2013 prime-class → carried pointer-direction consumer. Reopen only if a contemporary, attributable creator instruction or a new independent 150+ rune original plaintext inverse actually chooses this pointer/key mapping; without that selector, try a different causal route instead of more salts, phases or reversed labels.

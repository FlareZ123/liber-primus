# Historical clue grammar: role recognition does not recover a cipher operation

**Agent17, 27 November 2026, Director #3152. Decision: no transferable executable LP2 selector established.** This is a source-disjoint retrospective rule evaluation, not a genuinely blind solver trial. The rule and extra holdout filenames were committed before reading the additional six signed bodies ([frozen rulebook](../workplace/cicada-clue-grammar-frozen-agent17.md), commit c7168f7d12fa29f29f217dee2506a68d2dea227f). Public solution familiarity and pre-read LP1/LP2 sources are limitations; no claim of statistical generalization.

## Training, independent evidence, and rival rules

Training used 2013 signed TCP protocol reconstruction (BASE29/DH/NEXT), the actual 2013 signed ICMP metaphor, 2012 signed MIDI/Chorus and 2014 signed upload/key/locator texts. Existing [historical operation contracts](cicada-authenticated-solvepath-operation-contracts-2012-2016.md) already document their solutions. The novel decision is whether a rule written on these sources predicts *actual operators* on source-disjoint examples rather than merely assigning roles.

Frozen rule: explicit operation plus bound typed input/output earns an executable classification; incomplete bindings earn partial; metaphor or imperative without typed operands earns clue/semantic; adjacent structured literals are data/destinations, not opcodes; formulaic terminal signoff does not become key material. Rivals: imperative or operation-like noun suffices for a computational command (A); literal numbers suffice for key/parameter (B). Separate correctness of role from actual decipherment.

Use the repository [solved reference](../resources/liber-primus/lp1-plaintext-reference.txt), original page/solution records in the operation-contract study and the exact source-derived p5/p16 squares. These examples were known before the freeze; they do not qualify as blind validation.

No independently verified cipher operation is selected by those imperatives. Rival A creates three false executable proposals if it treats these headings as computational opcodes.

- LP2 p56: hash text binds an output digest to an external page and a search goal, but gives no exact hash algorithm/serialization/host. The rule does not recover the known p56 prime-totient-minus-one cipher with transparent F. Second missed implicit operation. Do not count correct digest role as recovered cipher.
- LP2 p57: parable wording identifies a metaphorical instruction, not a source-fixed circumference-removal algorithm or a key. No cryptanalytic operation validated from it alone.

Resolved additional historical items: three (scheduled return, explicit RSA procedure, literal locator), only one is a cryptanalytic operation; it is named verbatim. The two retrospective implicit operations (p5 GP sums, p56 prime schedule) are not predicted. No numerical classification accuracy is warranted for the non-independent sample or unresolved action items.

## Decision and next action

The rule is useful for filtering category errors (especially literal number vs key and instruction vs executable relation), but fails the primary gate: no independently predictive rule recovers an unnamed operation on solved LP1/LP2. It is therefore **not** a transferable cryptanalytic grammar and does not authorize an unknown-page receiver. Existing LP2 p32/2016 words-map and p49 table studies already articulate missing typed operations; do not use this rule to reopen them. Reopen only if a source-visible construction predicts a specific unseen operation and operand, or a genuinely independent blind human solve supplies it.

No unknown plaintext or new key recovered. No new corpus-wide source sweep, cipher fitting, or provenance replay.

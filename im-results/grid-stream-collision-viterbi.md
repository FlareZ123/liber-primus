# LP2 original-rune Viterbi: grid-column AES/ChaCha streams with collision-driven key consumption

**Classification (2026-11-10, Agent 37):** a directly invertible, clue-constrained cryptanalytic model with an extremely strong planted real-key control and a calibrated original-ciphertext negative result. **No original LP2 plaintext or genuine key was recovered.**

## Research question

Prior work already tested ordinary fixed-position AES-256-CTR and ChaCha20 keystreams from the eight 256-bit numeric table columns. That direct-stream assumption is fragile if an encipherer occasionally *consumes* a key symbol without emitting a ciphertext rune, for example when a tentative output repeats the preceding published ciphertext rune. The original LP2 has a severe adjacent-rune-repeat deficit. A cipher whose rejection policy depends on its previous output can have a dramatically different keystream phase from conventional fixed indexing.

This experiment therefore attempts a real inversion with latent, data-justified key skips. It differs from the previous direct grid-stream screens and from `grid_keyskip_viterbi.cjs`, which only used a literal repeating copy of the 256 table values rather than an AES/ChaCha keyed generator.

## Exact generative model and recovery

Use the canonical LP2 master and the original `resources/liber-primus/base60-grid.json` bytes, fingerprinted with SHA-256 `3b9b07d9a26e6d55c432d94d2661fdff3c2b348daed06821f2bdb23184a4b290`. There are eight meaningful text sections after the independently recorded red headings; the brief nine-rune numeric-grid bridge is discarded completely.

For each original section use the **first 300 runes after its red title**. Eight original 32-byte vertical table columns supply eight candidate symmetric keys. Test 16 fixed extraction settings: AES-256-CTR / ChaCha20, forward / reversed key bytes, generated byte `b%29` / `floor(29*b/256)`, GP arithmetic `C=P+K mod29` / `C=P−K mod29`. All streams start from a zero 16-byte IV. The eight distinct key columns may be assigned to eight text sections in any order, optimized exactly over **8!** one-to-one assignments per 16-mode family.

A tentative key `K_j` may be rejected **only when applying it to the same underlying plaintext rune would emit the immediately preceding ciphertext rune**. Such a rejection advances the key position once without printing a rune. One rejection per published rune, with no more than 34 extra consumed draws over the 300-rune window, is allowed. Skipping an eligible key incurs log-score penalty **3.5**. This finite architecture includes an ordinary no-skip decoding path exactly, as well as collision-driven phase drift.

The inference algorithm `sims/grid_stream_collision_viterbi.cjs` is an exact second-order Viterbi dynamic program over state `(total_skipped_draws, was_previous_rune_a_skip)`. It scores candidate decoded rune sequences using smoothed GP trigram log probabilities trained on the first 200,000 characters of the independent committed Shakespeare control. Per-key/section log-likelihood matrices are converted to the optimal eight-column assignment with a complete subset dynamic program. The implementation prints the first 70 decoded runes per selected section.

## Executed original-book result

The winning original setting is **ChaCha20, reversed grid column bytes, scaled byte-to-29 reduction, `C=P+K`**, and column-to-section assignment `[1,5,4,2,7,3,6,0]`. Its average 300-rune GP trigram log score is **−5.603721547 per rune** across all 2,400 runes. The eight selected section log scores range approximately **−5.2722** to **−5.7539 per rune**. The independently printed rune strings are nonlinguistic and exhibit conspicuous triple repetitions absent from genuine source prose. This is a selected statistical fit, with no plaintext evidence.

Sixteen seeded null replicates independently shuffle the 32 *bytes inside each grid column* and rerun the entire 16-mode / optimal-eight-key-assignment search on the **same original LP2 ciphertext**. Their maximum-score median is **−5.63534/rune** and highest **−5.59432/rune**. One of 16 null searches scores above the original column keys, yielding add-one upper-tail **p=2/17=0.11765**. This small null is insufficient for precise tail estimation and shows no convincing advantage for the authentic table; the result is conditional on the source English-language model and declared skip constraint.

## Powered, independently sourced planted control

Extract 2,400 GP rune values from Shakespeare characters **205,000 onwards**, disjoint from the language-model training prefix. Encrypt in eight 300-rune sections using the *genuine original grid keys*, secret permutation `[6,2,4,0,1,7,5,3]`, AES-256-CTR, forward key bytes, remainder-29 reduction, `C=P+K mod29`. On a repeat-collision, reject the tentative key with probability 0.81, consuming the next key position and using its candidate. Fixed seed `0x371e811` causes actual extra draws **[4,11,7,5,10,7,10,12]**.

The *identical* 16-mode, complete eight-assignment inversion recovers the precise true cipher family and all eight key assignments from the planted cipher. Viterbi reconstructs **2,399 / 2,400 plaintext GP runes (99.958%)**, with all eight skip counts correctly inferred. Its recovered log score is **−2.510643/rune**, sharply higher than the original LP2's **−5.603722/rune**. The rare one-rune planted error confirms this is a realistic statistical latent-state recovery rather than a scripted inverse. This is a substantial positive of the *specific hypothesized scheme*, not a plaintext for Liber Primus.

## Cryptanalytic consequence

The authentic grid columns, used directly as AES/ChaCha stream keys with collision-conditioned extra key consumption, have not decoded an original LP2 passage. The original scores lack natural GP-English evidence and are compatible with shuffled columns despite strong power to recover the planted scheme. Further unconstrained tuning of the same cipher family is unlikely to be profitable without new evidence tying a particular column, IV, page or rune transformation to an original plaintext position.

Unexcluded possibilities include externally derived nonzero IVs, a different nonce/KDF, per-section transformed rune alphabets, more than one inserted or deleted key per position, a different source-language register, and a richer stateful generator. Such proposals should supply an independent constraint and a full actual-rune inversion, rather than relying only on a short high-scoring snippet.

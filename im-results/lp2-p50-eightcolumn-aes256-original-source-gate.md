# Eight original p50 columns as eight literal AES-256 master keys: complete section-language test

**Agent11, 22 November 2026. Evidence class: original-cipher test, negative in its specified finite family. No plaintext or key schedule recovered.**

## Why this mechanism, and its strongest rival

The original 2014 LP2 has exactly **eight** cipher-bearing `$`-delimited sections. Separately, the original numerals printed across physical pp49–51 form precisely **eight columns of 32** base60-encoded bytes per column. An especially economical explanation of the table would be one literal **256-bit master key** for each of the eight source sections; AES-256 was a standard cipher available to a 2014 creator. The table physically supplies every candidate key byte, unlike an unconstrained password search.

The strongest rival is that eight-by-thirty-two is coincidental formatting, or that the table is a different encrypted binary object. No first-party source actually prints the words AES, CTR, a nonce, or an explicit instruction to treat the table columns as keys. The source-shaped idea therefore earns a *bounded direct decipherment attempt*, not a presumption of authored intent.

## Independent direct ChaCha20 stream key screen

The same 32-byte table blocks are also valid raw **ChaCha20** secret key widths. This **historically plausible second streaming primitive** was first published before the 2014 LP2 release and avoids a model-specific AES assumption while preserving precisely the same eight-source-section geometry, nonce choices, GP29 output mapping, eight full original section lengths, original printed words, synthetic complete native-GP positives and nonspaced IoC gate. Node's native ChaCha20 stream cipher exposes an exact 16-byte counter/nonce IV; its byte layout is [documented by OpenSSL](https://docs.openssl.org/3.0/man3/EVP_chacha20/). As with AES, the source gives neither an explicit ChaCha instruction nor nonce.

[Standalone original SFT](../sims/lp2_p50_eightsection_chacha20_keys_original_sft.cjs) and [successful Windows Node22 run 45002063294](https://github.com/FlareZ123/liber-primus/actions/runs/45002063294) execute all 32 directly parallel key-geometry/nonce/conversion/direction choices, with the same full-size planted original-word positive control (83 A/I, 448 THE, 720 AND exactly recovered). The **maximum full-manuscript GP29 IoC is only 0.03452296279578931**, and the next best are 0.034519495, 0.034519090, 0.034515944, 0.034510511. The original unknown cipher is 0.034478398; authentic clear p57 is 0.062709966. The highest weighted printed-word configuration recovers only **6** A/I, **2** THE and **0** AND across all sections. No source-selected variant reveals complete GP29 prose.

**Decision:** eight direct ChaCha20 keys taken literally from the p50 table do not decrypt the original sections under the 32 fixed physical interpretations and unchanged GP29 register. This is a bounded negative with no authentic plaintext; it does not rule out a separately authored key derivation, nonce, alternate encoding or different cipher. Its independent failure corroborates that the mere 8×32 table shape does not by itself identify the 2014 operation.

# The 2013 CicadaOS authored byte coordinates against unchanged LP2

**Decision, 15 November 2026, Agent 24:** Two exact source-directed original-manuscript tests are now executed. Neither the historical fixed-offset 2013 binary-key reading of original LP2 runes nor the historically used bitwise-XOR transfer to the printed 256-byte table recovered an unknown plaintext, recognizable file, original cryptographic key or continuation address. These are bounded negatives for the precisely declared operators; the 2013 authors did not direct either operation toward the 2014 LP2 artifact.

## Why these four file addresses were selected before inspecting outputs

The preserved [2013 original-ISO source](https://github.com/neuroretransmit/cicada/tree/ade9a02889ef8acbc8cde8edbfd0a785c369f4c3/2013/002-3301/3301-contents/data) supplies two binary tapes. In the historically reconstructed [first-onion CLUE](https://github.com/neuroretransmit/cicada/blob/main/2013/004-first-onion/README.md), solvers XORed the decoded clue with **`_560.00` at byte offset 0** and recovered the PGP-signed “forest ... trees” message. In the separately preserved [third-onion telephone challenges](https://github.com/neuroretransmit/cicada/blob/main/2013/006-third-onion/README.md), original messages explicitly specified **dataset 17 = `560.17`** at offsets **617, 33461 and 77977** as operands for bitwise XOR, producing distinct onion addresses. Their meaning belongs to the 2013 challenge; transferring them to LP2 is a hypothesis.

Source byte integrity was checked on the runner against pinned source Git commit `ade9a02889ef8acbc8cde8edbfd0a785c369f4c3`:

## Experiment A: exact original rune inputs with source-selected binary coordinates

**Fixed before decoding:** at each of the four source addresses above, obtain the next 8,192 original bytes; project them into a 4,096-symbol GP29 running key by (i) `byte%29`, (ii) `floor(29*byte/256)`, or (iii) MSB-first 5-bit values with 29–31 discarded. Read unchanged physical LP2 p0 (**262 ciphertext runes**) and continuous p54–p55 (**308 runes**) as two independent starts. For both additive signs and optional GP29 Atbash, decode each target with the independently source-pinned [Campaign XVIII collision-key-skip decoder](https://github.com/Dukotah/cicada3301/tree/f63501d8f2d835b80c30230eb89a1110fb9197d2/liber-primus/analysis/campaign18_skip), bounded at `MAXSKIP=3` between output runes. Fixed screen is the first 90 original runes, beam width 400, and source decoder's threshold **−6.0** normalized quadgram score. A surviving screen would receive a full-passage beam and independent exact reencipherment.

The source-specific screen covers **4 addresses × 3 reductions × 2 target intervals × 2 arithmetic signs × 2 Atbash modes = 96 configurations**. The decoder gate recovered a known 212-GP-rune planted English source under a real six-skip stream before running the original test. Four additional source-specific 240-rune Shakespeare plants recovered **240, 240, 240, 237** exact runes respectively; the fourth's 98.75% power limits the breadth of any negative inference. Every original screen output had a legal forward-reencipherment trace.

**Original result:** **0/96 screens** cleared −6.0; **no full-passage candidate was promoted**. The highest screen score was **−6.7164428372302565** from `560.17` offset 617, five-bit rejection, p54–p55, subtractive sign, Atbash on, with nonprose prefix `IGOESANISMOEIANIARGEAEOOENIURNFIAIASGHFHR...`. The best-scoring text was itself selected from the experiment's alternatives, so it is evidence of the search ceiling and not a partial decryption.

## Experiment B: actual 2013 bitwise-XOR operator on the 2014 256-byte table

The complete printed p49–51 table has **32 rows × eight cells** and its canonical base60, row-major working transcription is stored in [`lp2-grid-256.json`](../resources/liber-primus/lp2-grid-256.json), with SHA-256 `3b9b07d9a26e6d55c432d94d2661fdff3c2b348daed06821f2bdb23184a4b290`. The historic 2013 operation was **bytewise XOR**, so take exactly 256 original pad bytes starting at each of the same four author-selected addresses and compute `output[i] = table[i] XOR source[offset+i]`. The identical operation restores the entire unmodified table from every result. No phase, offset, mask, page rearrangement or post-selected key is fitted.

None of the four extracted 256-byte results begins with the standard PDF, PNG, GIF, ZIP, gzip, bzip2, xz or ELF signatures, and none forms a zlib-compressed stream. Their first 32 bytes, complete hashes and exact source checksums are preserved in the CI JSON report. The *OpenPGP high bit* at one arbitrary first byte does **not** by itself recognize a valid OpenPGP packet. The historical XOR transfer produces no independently recognizable artifact here; it could in principle yield nonfile binary key material under some other authored framing.

## 2016 `560.17` / first-seventeen-page hypothesis: original file and historical source gate (Agent20, 16 November 2026)

The original 11 January 2016 `#cicadasolvers.freenode.2.log`, at lines **246962** and **246982–85**, preserves a participant asking whether `560.17` from the earlier ISO had been used and later speculating that 17 might refer to the first seventeen Liber Primus pages. This is the **origin of the 560.17 / LP2-p0–16 hypothesis**, not an attributed or signed Cicada instruction. Importantly, the source itself says `560.17` was separate from the **2013 phone-number XOR file `560.13`**, whose exact bytes and role were independently resolved under [the historical 560.13 source gate](lp2-2013-56013-dense-direct-offset-gate.md). The 2016 speaker apparently did not know the prior original third-onion source had **already used Dataset 17**.

**Exact 2013 operand was already present and tested here:** `DATA/560.17` is an independently authenticated **1,183,811-byte** source file, Git blob SHA1 `49df8e57f8e6052eb2d5c2b483282461e53ef5ff`, SHA256 `d5676b1e01fd371cb13415b59b2eca4336e96f7bb05e789198b8d6baab580c19`. Its original, documented 2013 phone/IVR dataset addresses are **617, 33,461 and 77,977**, with **bitwise XOR** as the historical receiver, as recorded in the preexisting experiment above. Neither file length, filename, nor the archived 2013 instructions designate the seventeen LP2 pages published in 2014. The already completed **96 authored-offset GP29 configurations** and **four historical-byte-XOR table controls** recovered no unknown LP2 plaintext.

An additional [byte- and Git-blob-verified, original Freenode scan](../sims/lp2_2014_56013_source_link_sft.cjs) tested every occurrence of the exact `560.17` filename in the three preserved IRC logs:

- **Zero** exact literal `560.17` references in the **76,639 May–August 2014 source-dated lines** across both contemporaneous channels.
- In the earlier January 2014 primary channel, **nine** mentions occur, including **20 January L64310**, where a participant observes multiple byte pairs `FF D8` in the original file and speculates about image fragments. The separate original `#33012014` source has **one** early-January mention. These precede the May LP2 release.
- The post-2014 secondary log contains **three** exact mentions: one 2015 question about ISO contents and two 2016-01-11 messages by `LuaKT`. In particular **L246985**, near the second mention, is an *investigator's number-to-page suggestion* and supplies no filename-to-LP2 receiver, byte address, page-clock definition, GP29 translation, or plaintext prediction.

The dated **January 20** `FF D8` hint does motivate one additional, finite, typed-output test. [An exact-original-file single-run parser](../sims/cicada2013_56017_jpeg_source_gate.cjs) found **15** `FF D8` start-of-image byte pairs and **18** `FF D9` end pairs within 1,183,811 source bytes, but **none of the 15 SOI sites was followed by a required JPEG marker-prefix byte `FF`**. Accordingly **zero** candidates pass even a *standard SOI/segment/frame/SOS header* check. The same implementation correctly parses the original **580,041-byte LP2 p27 image** `resources/liber-primus/44.jpg`, locating `FF D8 FF E0`, all finite JPEG header segments and SOS. The verified 2013 original SHA256/Git blob and the native positive control passed in [manual Windows-independent Node22 workflow 43849402579](https://github.com/FlareZ123/liber-primus/actions/runs/43849402579). This narrowly excludes **standard self-contained JPEG streams beginning at those `FF D8` sites**, not encrypted/steganographic images or arbitrary binary payloads. It requires no guessed offsets or graphics-to-rune fitting.

### Independent May 2021 source mirror and literal reversed-file control (Agent5, 16 November 2026)

The 2013 original `560.17` has now been checked against an **additional dateable public archive**, independently from the already reproduced 2022 `neuroretransmit/cicada` file and the modern 2026 aggregate. Two distinct Git histories preserve **identical original 1,183,811 bytes**, with Git blob SHA1 **`49df8e57f8e6052eb2d5c2b483282461e53ef5ff`** and SHA256 **`d5676b1e01fd371cb13415b59b2eca4336e96f7bb05e789198b8d6baab580c19`**:

- The archival copy was committed **8 May 2021** in [`cijhho123/cicada3301` at commit `36caea4`](https://github.com/cijhho123/cicada3301/commit/36caea400b2b431e467928b4b5aecc31af5fd6b2).
- The separate [`neuroretransmit/cicada` source was committed **4 December 2022**](https://github.com/neuroretransmit/cicada/commit/1a3fb4acba0c718a932c6f602112446a6459e677) and has the same exact Git blob SHA1. The two histories and preservation dates are distinct, though they can still derive from the same original distribution and are not independent Cicada signatures.

The May 2021 archive additionally contains `DATA/560.17.rev`, Git blob SHA1 **`0ea9873a0656731e7c3ae1be1f4977d65642657b`**, SHA256 **`83fe92048a6d8a6efe8d8ab27f6d223eb27a165f88cb6b2f7b5d0852b20627d1`**. This is **exactly the forward object's byte sequence reversed** across the complete 1,183,811 bytes, rather than a distinct second pad, bitwise complement or decrypted message. On the unmodified forward object, bytewise XOR with the two historically recorded Dataset17 telephone inputs at source offsets **33,461** and **617** yields respectively full ASCII **`y2wyuvrqraowagc5.onion\\n`** and **`ll5afyskb6v6g7ga.onion\\n`**, byte-for-byte, including the terminal newline. All 256 possible byte values occur; entropy is **7.9998294556 bits per source byte**, consistent with the known pseudorandom-pad use and without a literal file-format header at source offset zero.

This **source-integrity and `.rev` equivalence update is distinct from any new LP2 decoding**. The original 2013 XOR examples and first-party dataset addresses had already been reproduced above and by [the earlier original-source Python SFT](../sims/lp2_2013_56017_original_source_gate.py). The new independent 2021 mirror, exact whole-file reversal check and cross-archive integrity confirmation are reproducible with [the standalone Windows Node22 SFT](../sims/lp2_2013_56017_original_iso_source_sft.cjs), [successful original-source CI run 43851837497](https://github.com/FlareZ123/liber-primus/actions/runs/43851837497). The 2016 **first seventeen LP2 pages** suggestion was made by a participant; no independently authenticated message selects this source, offset, byte conversion, or LP2 cipher inverse. The appropriate research decision is to **stop direct transfer** until such a receiver exists.

### Cryptanalytic boundary and next decision

The **historical source** establishes 2013 source file names, exact binary operands, byte offsets and a *bytewise XOR* operation for earlier challenges. Experiment A above separately hypothesizes a transfer from bytes into a GP29 additive collision-skip cipher; that GP29 interpretation has no 2013 instruction. Experiment B preserves the historical XOR operation but the recipient LP2 table is unlicensed by that stage. The 2016 first-17-pages link is a **participant conjecture**, with no sourced LP2 receiver, and the historical 2014 `FF D8` byte-pair image interpretation has a direct original-byte negative.

**Stop these source-to-LP2 transfers under their exact stated scopes.** An authentic `560.17` dataset is readily recoverable; its absence is **not** the obstacle. The missing step is a first-party instruction mapping its byte offsets and a reversible GP29 transform to an original 2014 LP2 chapter, page or word. Another direct source-byte scan, free offsets, adjusted PRF salt, or made-up JPEG carving format would repeat already unselected work. The manuscript's **56 unknown physical LP2 pages remain undeciphered** under these tests.

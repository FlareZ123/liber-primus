# 2014 Ahmia public fixture: historically dated onion metadata, no AN-END response bytes

**Decision (18 November 2026; Agent6 / Director #1443).** A genuinely contemporary, newly examined public capture-adjacent lane exists in the *original Ahmia search-engine development repository*: its June 2014 fixture preserves onion-host and description metadata from the manuscript's immediate publication era. It does **not** preserve the raw HTTP response bodies needed to hash a candidate for the LP2 p56 AN-END target. No original p56 target page, key, or continuation was recovered. This is a bounded public-source decision, not a negative over all onion sites or a general preimage search.

## Independent source and exact corpus

- First-party [Tor Project post, 8 September 2014](https://blog.torproject.org/ahmia-search-after-gsoc-development/) by Ahmia developer Juha Nurmi describes the then-operating search engine, OnionBot/Scrapy crawler, Solr full-text database, separate OnionDir domain descriptions and metadata, and Tor2web traffic statistics. It does not announce publication of its per-page original HTTP archive.
- Historical [Ahmia commit `7db4e805c072ff3e133aaab174815aaa1abb86d6`](https://github.com/juhanurmi/ahmia/commit/7db4e805c072ff3e133aaab174815aaa1abb86d6), **10 June 2014 10:18:29 UTC**, explicitly adds `ahmia/fixtures/initial_data.json`. Pinned Git blob: `08102c19f74df5d47771dfae8f85ddd8b8b7173d`, 2,759,554 bytes. At the 30 December 2014 repository tree this same blob remains. It contains 7,136 Django fixture records: **1,410** `ahmia.hiddenwebsite` host records, **4,234** `ahmia.hiddenwebsitedescription` metadata records, **1,391** `ahmia.hiddenwebsitepopularity` popularity records, and 101 remaining internal application records. Site-record `updated` dates range from **17 May to 10 June 2014**. Description records include some earlier dates; their update timestamps are not necessarily original capture timestamps.
- A second original `ahmia/tests/example_addresses.html` sample [in the same historical source tree](https://github.com/juhanurmi/ahmia/blob/c2e2aa4beef0f9fbad542eb2c15d4f0fc2760bc0/ahmia/tests/example_addresses.html) has pinned blob `548f8970a89ae780eb504852993261c655a9cb31`, 1,142,829 bytes. It is a rendered *directory listing with descriptions*, not raw captured original onion-page HTML. The HTML contains no original response body or URL-to-body serialization suitable for an exact p56 hash.

## Causal limit and Director decision

This is a **real 2014-era public metadata snapshot**, but it has no per-page source bytes, response boundary, MIME, headers, or capture-specific AN-END candidate. Its failure to mention the seven known Cicada hosts cannot exclude an *unnamed* target host, especially where the 2014 directory indexed only a subset of reachable onion sites. The contemporary OnionBot Solr database is a *different storage system* and no public 2014 per-page Solr export was retrieved from this route. **Zero SHA-512 candidates were available**; there is no legitimate mismatch claim.

To reopen this lane, obtain a public *2014–2016 source-dated original response body* and its exact URL/representation, or a contemporaneous published raw Solr/export object that names the target with independently preserved page boundaries. Searching more generic descriptive fields, or trying arbitrary hostnames against the printed digest, has no causal pathway. Distinct private-custody studies remain within maintainer-approval Issue #784; the known onion7 distributor is not authenticated as the AN-END target. This report does not change the overall undeciphered status in `results/README.md`.

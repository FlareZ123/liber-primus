### Standard MP3 private/ancillary bit audit

The source-frozen SFT now parses the **17-byte stereo side-information block** and **51-byte main-data region** of every frame. Across all 129 frames:

- All **258 private bits** (two per frame) are zero.
- The two channel `part2_3_length` fields account for **49,765 audio-data bits**.
- The **443 inter-frame unused/ancillary bits** are exactly alternating `0101…` (55 bytes of `0x55`, followed by the final three bits `010`).
- The remaining **303-byte terminal region** contains `LAME3.98.2` at offsets 0 and 48 and `0xAA` at every other byte.
- The accounting is exact: `49,765 + 443 + 303×8 = 52,632` bits, the complete 129×51-byte main-data area.

Thus the standard MPEG private-bit and ancillary-data channels contain no hidden payload or magic square. **Scope:** this bitstream audit does not test steganography in spectral coefficient choices or the participant's proposed musical-note encoding; those remain distinct, unverified hypotheses.

### Historically standard B-A-C-H note cryptogram: source-selected necessary-condition test (Agent27, 15 November 2026)

A genuinely conventional composer-linked readout is **B-A-C-H** in German musical notation: B-flat, A, C, B-natural, whose consecutive semitone differences modulo 12 are **[11,3,11]** (equivalently −1,+3,−1). Unlike inventing note-to-GP mappings, this is a definite historical musical operation, independent of the LP2 ciphertext. The [Library of Congress educational note](https://blogs.loc.gov/nls-music-notes/2016/03/games-composers-play/) and the [Bach-cantatas motif study](https://www.bach-cantatas.com/Arran/L-BACH.htm) both describe the exact German note convention.

Apply the literal motif and its one-step **global transposition-invariant interval signature** to every consecutive four-note window **within each separate original 2014 participant-transcribed voice**, in its written direction and backwards. The authentic saved list has **7+8+5=20** events, in flute1, flute2 and harpsichord order. Across the three voices there are **4+5+2=11** four-event windows in each direction. The seven distinct named pitches are **{A,B,C,D,E,F-sharp,G}**: no B-flat occurs. There are **zero literal B-A-C-H occurrences, zero global-transposition-equivalent [11,3,11] windows, and zero such retrograde windows**. An independent exactly specified planted B-A-C-H four-note string and transposed D-C-sharp-E-D-sharp string each satisfy the same matcher. [Reproducer on the preserved original note list](../sims/lp2_2014_bach_cryptogram_source_gate_sft.cjs).

This refutes **only** identifying the famous B-A-C-H melodic cryptogram as an embedded readout in the period participant's *specified three-voice note list*. It cannot exclude motifs in untranscribed audio, a nonliteral musical-number convention, or another separately instructed operation. The original signed 2014 audio/image/book-code packet already gives a complete historically solved GEB book-code route to the sixth onion; it does not identify any LP2 ciphertext receiver for a second Bach-derived key. The participant allegation of a magic square “encoded the same way Bach encoded his” provides no definition of that operation. Consequently this musically natural source test supplies **no authentic LP2 key, algorithm or plaintext**, and it does not justify tuning other note ciphers on original unknown pages.

## Cryptanalytic decision

The original source image, the period-linked melodic note list and the explicit six **participant-proposed numerical representations** are now retrievable. This materially removes the prior missing-source blocker and fixes several candidate numerical strings before touching LP2 ciphertext. It does **not** establish that Cicada embedded a magic square in the 3.096-second signed Bach clip, or that any of these participant keys were intended for LP2.

In the bounded **executed** original-input test, the literal 19-term GP-prime key, its independently corrected 20-note alternative and the five other historically printed variants (nine key streams total) all remain ciphertext-like under direct native GP29 addition/subtraction. **All 36 independently source-determined direct inverse choices** (9 keys × 2 signs × 2 key clocks) yield GP rune IoC near **0.0345** over the unchanged original 12,956 runes; the highest is **0.03452565575687757**, while clear source p57 yields **0.06270996640537514**. A source-native 95/95 planted GP-rune inverse recovers exactly. These checks executed with Node22 on [successful source-pinned CI run 43726004130](https://github.com/FlareZ123/liber-primus/actions/runs/43726004130). This excludes **direct unchanged-boundary GP29 additive decryption with these key streams, both signs and original-global/page-reset clocks** as the immediate plaintext path; it cannot exclude additional layers, unrelated key derivations, or more complex ciphers. See the [source-pinned executable SFT](../sims/lp2_2014_bach_pastebin_key_original_sft.cjs) for every input, 19/20-note reconstruction, GP key mapping, positive plant and exact original-input result. An IoC gap for these fixed keys is a narrow native-plaintext exclusion and is **not** a general cryptanalytic impossibility theorem.

**Decision:** retire the participant score as an LP2 selector. The first-party signed material authenticates the 3-second audio only; it does not select BWV 1039, bar 18, the score image, the note table or any mapping. Direct additive key tests already fail; standard private/ancillary bit channels are empty. No source-selected musical or spectral operation is currently justified. Do not continue musical-square, pitch-permutation or note-to-GP searches unless an independent Cicada-authored instruction selects the score or predicts an original ciphertext feature. A future MP3 test must specify an independently source-selected encoding and a blind predicted pattern before touching LP2 ciphertext.

# 2013 CicadaOS original binary files as LP2 PRF seeds: skip-aware original-cipher gate

**Decision, 15 November 2026 (Agent 24).** The previously unexecuted source-pinned PRF-seed gate is now complete. All **576 fixed direct source-seed derivations** ran against the unchanged original LP2 ciphertext with the source-pinned collision-key-skip decoder; **zero** candidates cleared the established original-head English screening score. The best attempt remained unreadable on independent pages and on the full continuous stream. This does not recover plaintext, an original LP2 key, or an intended continuation.

## Source premise and exact inputs

Earlier Cicada 3301 puzzles supplied genuinely random-looking binary tapes in their 2013 bootable `3301.iso`. Their actual historical use involved XOR at source-dictated byte addresses. A separate, historically possible LP2 hypothesis is that the byte files served as **PRF/KDF seeds** for a GP29 running key, rather than appearing directly as ciphertext or as a literal pad. There is no original 2014/2016 Cicada instruction to use any of the PRFs below, to assign the binary files to LP2, or to reset their state between pages. This test is an operator-family gate, not a claimed author-selected route.

The original bytes were checked against the pinned [2013 archive source](https://github.com/neuroretransmit/cicada/tree/ade9a02889ef8acbc8cde8edbfd0a785c369f4c3/2013/002-3301/3301-contents/data): `_560.00` (3,992,970 bytes; SHA-256 `a24051a87f0eb25ca21accbd3158fdf7b4911243e5ee1b9778b81182f0d36573`) and `560.17` (1,183,811 bytes; SHA-256 `d5676b1e01fd371cb13415b59b2eca4336e96f7bb05e789198b8d6baab580c19`). Both are distinct from the much larger `560.13` data file already studied elsewhere. Source commit and Git blob fingerprints are recorded by the runner.

## Exact candidate family and inverse

For each complete original 2013 binary input, seed deterministic byte-stream generators from the **raw bytes**, `SHA256(file)` or `SHA512(file)` under the 12 exact pinned `stream_specs()` entries. The distinct generator types comprise SHA256/SHA512 counters, their HMAC counterparts, SHAKE256, CPython MT19937, AES-256-CTR, ChaCha20 and RC4. Project each 70,000-byte generated stream to GP29 by `byte mod29`, `floor(29*byte/256)` or MSB-first five-bit rejection of values 29–31. Admit forward and reversed stream direction, both arithmetic signs, and optional GP29 Atbash. This is **2 files × 12 stream specifications × 3 reductions × 2 stream directions × 2 cipher signs × 2 Atbash modes = 576** fixed candidates. All key streams begin at offset zero; no fitted phase, secret salt or recipient-specific seed is permitted.

The decoder is version-fixed at [Dukotah/cicada3301 `f63501d8...`](https://github.com/Dukotah/cicada3301/tree/f63501d8f2d835b80c30230eb89a1110fb9197d2/liber-primus/analysis/campaign18_skip). A collision-skip inverse searches GP29 running-key advances under `MAXSKIP=3` and 400/500 beam widths. This model explains how a correct 1:1 keystream might be desynchronized by ciphertext adjacent-equality suppression. Before original tests, the external decoder's internal positive recovered all **212/212** known GP29 plaintext runes of a synthetic six-skip ciphertext; its rigid decode recovered only **8.5%**. The additional PRF script's source-native positive recovered its own planted text, but the latter generated zero skips and should not be mistaken for extra skip-power calibration.

## Original LP2 result and independently checked continuation

All **576/576** candidates generated a first-90-rune output on original p0. The highest screen score was **−6.598893858642317** against the source decoder's screen threshold **−6.0**. Its unmodified source specification was `_560.00:raw/python-mt19937:mod29:forward`, subtractive sign, Atbash on. The candidate begins `CBAEXEOOENEONJOEYROEHAEIEANGEOFAEHPARCYJEXDPOW...`; this is neither coherent runic English nor a decrypt.

The top 20 head-ranked candidates were further tested as page-reset GP29 keys on a fixed ten-page set: original physical **p0, p1, p8, p15, p23, p27, p33, p40, p54 and p55**. The best mean normalized page score was **−7.1794316397785956**; no untouched full page provided a sustained readable passage. The top four head candidates were separately run as one continuous GP29 stream across all **12,956 unknown cipher runes**, preserving the last ciphertext symbol across page boundaries. Their four full-stream scores were **−7.255699224428933, −7.231219267018549, −7.281491788080252, −7.322913378235672**, respectively. Only **one of four** 12,956-rune beam outputs passed the strict independent key-skip forward re-encipherment verifier (the RC4 variant, 281 skipped key symbols, ending key cursor 13,237); the other three are decoder-produced score probes which do *not* independently establish executable inverses. None contains an authentic unknown plaintext passage.

The source-pinned test uses reproducible original file SHA-256, interpreter dependencies, original LP2 `lp2-corpus.json` and full JSON reports. ## Boundary and next decryptive decision

The original-head screening threshold is **English-register-dependent**; it can miss non-English plaintext or decode under a different stream/filter model. The test holds all source-phase starts at zero, and the external beam is heuristic rather than a complete proof against every path. **Only** the named source-derived deterministic PRF families, reductions and clock choices are screened; all other possible binary interpretations remain logically open. The key absence is especially important: no original 2014 clue selects these particular 2013 file-derived generators.

For the independently **source-authored 2013 byte offsets** (rather than guessed PRFs or source-local zero offset), a separate original LP2 test covers 96 GP29 key-skip readings and four exact historical XOR transfers to the 2014 table. Both are also negative: [original-offset scope and results](lp2-2013-cicadaos-authored-offset-skip-and-xor.md). Do not rerun the same seed grid with fitted salts or shifts. Further work needs a first-party operation that fixes an actual LP2 recipient, file address or cipher key. The **56 physical unknown LP2 pages remain encrypted** under these tests.

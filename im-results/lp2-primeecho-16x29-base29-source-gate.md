## Decision

The 464-prime Cicada OS stream forms an exact 16 x 29 token table in emitted order. Its two authored two-second holds fall at the ends of rows 6 and 16 because their ranks are 174 = 6 x 29 and 464 = 16 x 29.

Applying the authenticated 2013 BASE29 numeral conversion to every prime gives a reversible table of variable-width numeral strings. The signed protocol defines numeral conversion only. It supplies no Gematria mapping, ciphertext combination rule, target span, clock, or state convention.

The direct flattened digit sequence contains **1,237 base-29 digits**. No original unsolved physical page has 1,237 runes. None of the nine original visual chapters has that length. No contiguous block of whole physical pages p0-p55 sums to 1,237 runes.

Close #1658 on the negative fork. Preserve 16 x 29 as a natural description of the historical stream. A first-party clue would still need to supply a reversible LP2 receiver before this object can act as key material.

## Exact construction

The preserved shell source contains 464 prime outputs from 2 through 3301. Ordinary delays are 0.05 seconds. The only two-second delays follow 1033 and 3301.

The signed 2013 TCP-server challenge documents the BASE29 digit alphabet 0123456789ABCDEFGHIJKLMNOPQRS and the worked conversion **3301 -> 3QO**. The preserved participant exchange separately records **1033 -> 16I**.

Partitioning emitted primes into consecutive rows of 29 places:

- rank 174, row 6 column 29: 1033 -> 16I;
- rank 464, row 16 column 29: 3301 -> 3QO.

The converted row character counts are:

`49, 58, 58, 58, 58, 86, 87, 87, 87, 87, 87, 87, 87, 87, 87, 87`.

Flattening the numeral digits in source order gives exactly **1,237 numeric base-29 digits**. Retaining all 464 cell boundaries permits exact conversion back to the prime values. Discarding those boundaries introduces a new serialization convention absent from the source.

## Source-preserving null

The pause locations are authored at ranks 174 and 464. Once width 29 is chosen, both ranks are row endings by arithmetic identity. BASE29 conversion contributes nothing to that alignment.

A matched null that keeps the two hold positions fixed while permuting the other prime values preserves both row-boundary holds in every sample. The exact null probability of the boundary property is therefore **1**.

The total BASE29 digit count is also invariant under every permutation of the same 464 prime-value multiset. Sequence-order randomization cannot transform the 1,237-digit object into an exact source-native LP2 section length.

## Receiver gate

A usable LP2 inverse still needs four source decisions: a mapping from BASE29 numeral characters or digit values into GP runes, an original ciphertext target, a reversible combination operation, and a clock convention for variable-width tokens. The authenticated historical sources provide none of these decisions.

I therefore did not run language-scored unknown-page decodes under invented additive signs, modulo reductions, repetitions, truncations, resets, or digit reversals.

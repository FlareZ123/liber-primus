# Independent LP2 JPEG-to-rune component audit (13 November 2026)

## Decision and scope

The original physical LP2 page images (archive scans `17.jpg`–`74.jpg`) and repository's existing `lp2-corpus.json` were compared through a new image-first glyph reader. **11,796 independently segmented rune-shaped components match the canonical 29-symbol transliteration in printed order. No contradictory classification was detected in the admitted components.** The remaining **1,340/13,136** rune positions cannot be compared using this segmentation, principally because of linked glyph components, oversized red initials, dropped heading lines and image-layout exclusions. This result strongly supports the currently available transcription on the large automatically readable subset; it does not prove transcription correctness at all positions or recover an unknown plaintext, key or cipher.

## Operation and exact reproducibility

[Single-file SFT](../sims/lp2_original_jpeg_glyph_audit_sft.py) reads the original 58 JPEGs directly from `resources/liber-primus/`; it has no remote inputs or saved model parameters. It finds horizontal text bands of approximately original glyph height, extracts separated foreground columns, normalizes each component to 48×96 pixels, and represents it as 4,608 binary pixels. Physical p9 provides a convenient *complete* original-source type specimen: 268 standalone GP29 runes containing all 29 distinct signs, plus a decorative terminal right-margin twig. The reader learns a medoid raster for each rune from p9 without seeing another page. Every other page is classified using the nearest of those fixed 29 medoids and a 314/4608 pixel-difference acceptance cutoff. A simple fixed-score order-preserving global alignment permits missing foreground components, but records contradictory rune identities, inserted or omitted observations separately.

The source has 13,136 LP2 rune positions in physical pp0–57 (including 180 in solved pp56–57); the reproduced totals are exactly **matched 11,796; contradictions 0; spurious accepted image symbols 0; excluded/unsegmented 1,340**. Page p50 has no runes and passes as an empty page. Full 121/121 image rune recovery on original p32 and 268/268 on training page p9 are useful exact controls. The script asserts these four totals and prints one result line per physical page. Dependencies are Python, NumPy, Pillow and OpenCV; the source files are those already present in the repository.

## Consequence for solving

This audit provides a reproducible alternative to manually trusting the inherited transcription for most original rune identities. It specifically checks **source glyph identity**, not the presence of hidden data in fine raster noise, page spacing, punctuation, word breaks, alternative reading order or the unsegmented 10.2% of positions. It also cannot detect a glyph that the manuscript originally intended the reader to interpret using a different phonetic mapping. A remaining candidate decoder should be evaluated against the original ciphertext and a concrete source-selected operation. Further large-scale transcription checking is lower priority absent a pointed discrepancy or a need for accurate glyph coordinates in a newly motivated visual clue.

# Original Artifex ICC profile as a five-cycle GP29 pad

**13 November 2026, Agent 10. Source-exact bounded key transfer.** A striking exact length match selects a real embedded 2,576-byte sequence as a possible original-data key. The **complete 12,880-rune original input** rejects its two direct GP29 additive signs and two natural stream clocks as recognizable native-GP prose. This produces no recovered unknown-page plaintext, original-key schedule, or Cicada destination.

## Original-artifact selection, without key search

Each of the 58 original LP2 JPEG scans contains an identical ICC colour profile. The exact byte body excluding the 14-byte JPEG APP2 `ICC_PROFILE` wrapper is **2,576 bytes**, SHA-256 `942e0f66212eb8ad252706559da5007d893d7350652704f8d115d5e6074479d0`. Existing [source-only extraction](../sims/lp2_artifex_icc_source_sft.cjs) established that the profile is the common 2011 *Artifex Software sRGB* profile generated by the rendering toolchain; it is not a known Cicada-authored key. Its presence in the actual artifact makes it available to historical investigators, but the renderer explanation is a strong objection to intentional use.

The independently transcribed **55 original pages p0–54** (including numeric-only p50, which has zero rune symbols) contain exactly **12,880** GP29 runes. Physical p55, the final encrypted page, contains exactly **76** more. Consequently:

\[
12{,}956-76=12{,}880=5\times2{,}576.
\]

The original image and plaintext layout, not fitted offsets, fix both sides. Other page-boundary cycles do not coincide with each 2,576-rune multiple: this is an end-of-p54 alignment, not five explicit 11-page frames. Both the 2,576 length and the p55 truncation were noticed retrospectively amid many candidate numerical clues, so this exact arithmetic identity is **not proof of authorial intention**.

A historically simple interpretation is to subtract an original-byte stream reduced modulo 29 from the matching GP29 ciphertext: `P[i]=(C[i]-ICC[i mod2576]) mod29`. Cicada had already used GP29 modular addition/subtraction on solved pages and the original manuscript contains the profile as its own bytes. Also test the sign-reversed operation; a key stream could either be added or subtracted by its creator. A page-local reset is an independent natural clock because every physical JPEG carries the identical profile. These are four *fixed* tests, with **no phase, key offset, passphrase, KDF, affine fit, alphabet permutation, padding or plaintext search**. The profile's 14 JPEG wrapper bytes are never used as a key because they are transport metadata rather than profile data.

## Complete source results and known-page control

The [self-contained CommonJS source test](../sims/lp2_artifex_icc_5cycle_original_key_sft.cjs) checks every image byte, source page length, ICC hash and output reconstruction. It ran successfully under Windows/Node 22 in [GitHub Actions run 43338244469](https://github.com/FlareZ123/liber-primus/actions/runs/43338244469).

The original p0–54 ciphertext's whole-corpus IoC is **0.0344821412**. A genuinely solved native-GP control, p57 **PARABLE** (95 runes), has IoC **0.0627099664**. As a separate implementation positive, the script encrypts those 95 known p57 plaintext GP indices using the exact original ICC stream and then recovers **95/95** without knowing them inside the inverse. All original outputs reencrypt to the original 12,880 GP rune indices exactly. Source/native positive controls establish arithmetic correctness; they cannot establish an unknown-page key.

The first 30 original decoded GP runes under the continuous subtractive clock transliterate to `SHHTGMIAFPIENGEOHJHUTOMTHWEAGEWBASOE`; with the additive sign, they begin `SHEAMGMIAFBPENGIAAEJRLPMAERJCEOEWBASOE`. Neither reading produces the expected title or body-level language. A superficially readable fragment obtained by including one wrapper byte and concatenating GP rune labels is not a native-GP word and fails whole-page frequency checks. It is not accepted as plaintext.

## Decision

The source-native length relation merits preservation, but using the original profile bytes as an unaltered, repeated GP29 additive key produces **no recognizable decryption under either original clock or sign**. That direct mechanism is retired. Do not infer a salt, secret stream phase, SHA-based expansion or byte mutation from the exact size coincidence; such an additional operation requires a clue from the artifact or an independently verifiable plaintext prediction.

This decision is independent of the previously exhausted 256-cell numeric table key phases and the separate historical 2013 `ssss` XTEA whole-secret inverse. No authentic key or unknown LP2 passage was recovered.

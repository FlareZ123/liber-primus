# An independent 2014 HTML source for the red119 number 133

**Agent 5, 14 November 2026. Evidence class:** original-source numerical crosslink with an independently tested direct-cipher negative. There is no recovered unknown LP2 plaintext, key, historical decoding instruction or destination.

## The preserved human-visible source

The historically archived [2014 onion7 Liber Primus delivery index](../resources/cicada2014-onion7-index.html) exposes literal HTML title **133** and div identifier **331**, alongside 58 image references for the 2014 pages, named 0.jpg through 57.jpg. This **1,640-byte index** is byte-for-byte identical to the independently preserved `resources/historical/stage11-2014-index.html`; the associated [historical source manifest](../resources/historical/stage11-2014-index-manifest.json) pins original Git blob SHA-1 **303db130705f0ef9be2a738f4336d5cfcebde80c** at participant archive commit **6c3421a4d245596e403c88e037509d162a2afd17** dated **11 May 2014**, with an independent archived mirror. This is documented historical participant-archive evidence; the HTML bytes themselves are not PGP-signed. The identifier **331** independently equals the *center* (fourth row and fourth column) of the previously recovered [2014 second OpenPuff 7×7 magic square](../resources/cicada2014-openpuff-magic-squares.txt). Decimal digit reversal transforms 331 to 133. These two source numbers existed before analysis of the LP2 red spans and are independent of ciphertext-trained parameters. The HTML itself does not say to reverse digits or use 133 as an LP2 key.

**Competing pre-publication interpretation (Agent31, 16 November 2026):** A 28 April 2014 participant comment, [Cipherbrain discussion #111](https://scienceblogs.de/klausis-krypto-kolumne/2014/01/23/cicada-3301-wer-knackt-das-neueste-raetsel/#comment-111), explicitly observes that removing the **0** from the prior 2014 magic-square targets **1033** and **3301** produces **133** and **331** respectively. This predates the archived Stage11 index of 11 May 2014, and supplies a simple human-visible *non-LP2* explanation of both HTML labels. The comment is participant conjecture, not signed author instruction; it also incorrectly calls 133 prime (133=7×19). The exact zero-deletion correspondence reduces the significance of matching those already familiar HTML numbers to the retrospective p3/p39 red-span subtraction. There is still no original selector joining either HTML value to these runes or a decoded plaintext receiver. See [consolidated p0 alternative explanation](../workplace/p0-red331-distributor-crosslink.md).

**Period-original archive cross-check (Critic, 14 November):** The retained HTML blob is byte-identical at Git blob SHA `303db130705f0ef9be2a738f4336d5cfcebde80c` to `stage11/ky2khlqdf7qdznac.onion/index.html` in the independent public `micheloosterhof/cicada-2014` repository, at [commit `6c3421a4d245596e403c88e037509d162a2afd17`](https://github.com/micheloosterhof/cicada-2014/commit/6c3421a4d245596e403c88e037509d162a2afd17), authored **11 May 2014, 18:33:43 UTC**. The local file's own blob SHA is identical. This anchors both literal numbers to a genuinely period-dated archival repository, not merely a recent derivative; the commit timestamp is archival evidence, not an independently preserved Tor HTTP response or cryptographic Cicada signature. It upgrades source provenance only. The subtraction/reversal and any LP2 decoding operation remain unsupported.


The only two *isolated red three-rune spans* in the [original-page ink inventory](../resources/liber-primus/lp2-ink-annotations.json) start at zero-based rune offset **119** on physical LP2 pages **3 and 39**; both are framed by red 13-dot marks. At the further one-based rune offsets 137 and 173, the p33 target is a word start (TJ) whereas the p40 target is **inside** FDREAG, at D immediately following F; no common word-start operation is established. **Crucial limits:** this is a newly identified *independent source coincidence* and a viable intended-player-path hypothesis. No original authorial instruction specifically selects subtraction of the one-based physical page number. The original image filenames are *zero-based*, in which case subtracting page index gives **134** for both groups. The prime-ordinal navigation and decimal reversal are possible operations, neither verified as intended. This is no discovery-corrected significance claim.

## Original-period HTML consumer audit (Agent23, 14 November; Director #965)

An independent first-party *operation* would be much stronger than the arithmetic crosslink above. This explicit source inspection separates **what the original 11 May 2014 browser page actually does** from later cryptanalytic interpretations of its numeric labels. The original-period [archived directory](https://github.com/micheloosterhof/cicada-2014/tree/6c3421a4d245596e403c88e037509d162a2afd17/stage11/ky2khlqdf7qdznac.onion), at the same commit already pinned above, contains **59 files**: one `index.html` (1,640 bytes) and exactly the **58** images `0.jpg`–`57.jpg`. There are **no sibling CSS, JavaScript, template, or data files** preserved in that original-period directory. Three independently placed research copies of the source index in this repository share the same original Git blob ID `303db130705f0ef9be2a738f4336d5cfcebde80c`: `resources/cicada2014-onion7-index.html`, `resources/historical/stage11-2014-index.html`, and `resources/external/cicada2014-stage11-onion7-original-index.html`. These are **three copies of one byte-identical version**, not three independent original variants.

**Complete static DOM behavior:** the HTML consists only of an `html` element; `head` with plain text `title=133`; `body` containing a single `div id=331`; the 58 consecutive image elements with relative `src=N.jpg` each followed by `br`; closing tags. It has **zero** `script`, `link`, `style`, `a`, `form`, event-handler, or CSS-rule elements/attributes; zero links using `#331`; no use of `133` as an index into the image sequence or as a cryptographic or scripting parameter. The title renders as tab/window title; the div ID creates a potential fragment-anchor target, but **no internal link or action addresses that anchor**. Browser rendering in normal source order displays exactly 58 images independent of both integer values. Replacing `133` with another title changes only that title display; renaming `331` changes only the unused anchor's identity. Neither operation changes which images load or their order.

**Original-period version and sibling-page discriminator (15 November; Director #1008).** An exact GitHub [path-history query](https://api.github.com/repos/micheloosterhof/cicada-2014/commits?path=stage11/ky2khlqdf7qdznac.onion/index.html&per_page=100) against the period participant archive returns **one reachable commit touching this exact index**, the initial 11 May 2014 `6c3421a4d245596e403c88e037509d162a2afd17` addition. The [complete tree at that commit](https://api.github.com/repos/micheloosterhof/cicada-2014/git/trees/6c3421a4d245596e403c88e037509d162a2afd17?recursive=1) is not truncated (169 entries). Hence the public reachable path history contains **no alternate HTML revision**, and copied mirrors do not constitute separate designs. This does not exclude lost Tor HTTP captures or uncommitted variants.

**Sibling-stage cross-check at exactly the same 2014 commit:** [stage2/index.html](https://github.com/micheloosterhof/cicada-2014/blob/6c3421a4d245596e403c88e037509d162a2afd17/stage2/index.html) has a prose Blake-derived title; [stage3](https://github.com/micheloosterhof/cicada-2014/blob/6c3421a4d245596e403c88e037509d162a2afd17/stage3/index.html) starts with a `Patience is a virtue` HTML comment before a hex block; [stage4](https://github.com/micheloosterhof/cicada-2014/blob/6c3421a4d245596e403c88e037509d162a2afd17/stage4/index.html) starts with the literal `1033` comment, and [stage5](https://github.com/micheloosterhof/cicada-2014/blob/6c3421a4d245596e403c88e037509d162a2afd17/stage5/index.html) with `3301`. Their structures differ, so the Stage11 `133`/`331` tags are **not demonstrated boilerplate copied from those stages**. More decisively, [stage10/index.html](https://github.com/micheloosterhof/cicada-2014/blob/6c3421a4d245596e403c88e037509d162a2afd17/stage10/index.html) explicitly directs players, inside a PGP-signed message, to paste magic squares into a form. Its actual form submits to `/cgi-bin/squares` and names the numeric inputs `53301`, `71033`, `51033`. These are active, independently typed inputs. The **separate** preserved [post-square image response](../resources/external/2014-stage10-post-square-response.html) shows `107.jpg`, `167.jpg`, `229.jpg` without a `133`/`331` pair. By contrast, Stage11 has no form and no fragment link targeting its `331` ID. The fact that earlier stages sometimes surface deliberate numerical hints does not authenticate a decoding operation on the later numbers. The original Stage11 labels could still be author-selected mnemonic numbers or external selectors; neither conclusion is justified by their static DOM alone. Original-live server response headers, server-side template source and older unpreserved versions remain outside this archive and cannot be inferred. A remote `#331` fragment would navigate to the div by standard HTML behavior. Crucially the preserved [PGP-signed Stage11 transfer message](../resources/historical/cicada2014-stage11-message.asc) supplies the bare `ky2khlqdf7qdznac.onion` hostname **without a `#331` fragment, query parameter, or image address**. Neither preserved author-facing handoff selects a follow-on image/rune address via that ID.

**Decision:** the archived, source-dated HTML provides **no operational consumer for 133 or 331**. Retire new transformations whose sole premise is that these particular numbers actively index or decrypt LP2 *because they appear in an HTML title and ID*. Continue only if independently dated author instruction, an actual archived alternate script/template or a locked ciphertext prediction specifically connects the numbers to a chosen operation. This refines the source status; the earlier source-native crosslink, 331's original square-center position, and all negative p33/p40 original inverses remain exactly as reported.

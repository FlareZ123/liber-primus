# 2012–2014 Cicada sources do not establish zero-based row-major addressing

**Decision (Agent41, Director task #1570, 18 November 2026):** No preserved authenticated 2012–2014 Cicada instruction, protocol, or creator-side code reviewed here specifies a zero-based row-major table/grid address rule. The zero-based row-major choice in #1540 remains an **empirically selected convention within its frozen eight-way comparison**, not an independently authenticated historical instruction. No unknown LP2 plaintext, key, cipher inverse, or destination is recovered.

## Exclusions and source boundaries

- Do **not** count the archived first-onion server.py or gematria.py as creator source. The repository's [source index](../resources/external/cicada-research-repositories.md) explicitly classifies them as community recreations from public behavior, not recovered original server code.
- Do **not** infer a Cicada convention from Python's zero-based list/string semantics. In the 2012 book-code positive control, the human-facing coordinates are one-based and the participant script subtracts one only at the implementation boundary.
- Do **not** infer a Stage10 square parser from the visible textarea order or from the returned image filenames. The actual CGI handler and exact successful POST body are not preserved.
- A printed 32×8 table has a visually obvious left-to-right, top-to-bottom reading order, but that physical presentation alone does not state that an address n means zero-based row*8+column.

## Consequence for the p57→p50 bridge

#1540's eight-way comparison found that zero-based row-major is the only tested natural convention making the DIUINITY-derived addresses yield decimal tokens. That is a real, reproducible **output discriminator**. This audit still finds no independent 2012–2014 Cicada precedent that selects that convention before observing the output.

A separate manuscript-internal cross-check now gives conditional support specifically to the **zero origin**. The still-conditional p0 red-title construction freezes additive sums `15,42,57,99,156`; extending the same recurrence one term gives **255**, exactly the terminal zero-based address of the original 256-cell pp49–51 table, whereas a one-based table terminates at 256. With the printed 8-column layout, those six row-major addresses are octal `017,052,071,143,234,377`, ending at row31/column7. The direct table readout remains nonlinguistic, so this supplies no decoder and does not by itself authenticate row-major linearization. See the [recurrence bridge](lp2-p0-red-heading-sequendi-ratio-route-check.md#prospective-recurrence-continuation-255-meets-the-p50-table-boundary) and [SFT](../sims/lp2_p0_title_recurrence_p50_255_sft.cjs).

A second conditional cross-source candidate now exists. LP2 p27 and p55 carry insect/cicada motifs plausibly pointing to Susan Milius's 13 July 2013 Science News cicada feature; its page-27 figure shows the lineage tree and brood map, and the article gives the 221-year coincidence plus the 2013–2015 brood sequence. Treating 221 as the first zero-based address in the 256-cell p50 table selects original p51 tokens 0q/0p/2V at cells 221–223, which decode to 52/51/151. BASE29 (52→1N, 51→1M, 151→56 in the signed 2013 digit alphabet) and the signed 2016 word register then yield THE ROAD / THE THE / EPIPHANY SEEKS under zero-based word indexing. This uses numeric BASE29 digits as word positions, not as GP29 rune symbols. This favors zero-based table and word origins, but the article-to-table address and word-map operation remain inferred; it is not an authenticated Cicada instruction or a decryption. See the cicada row27 word-map report.

Therefore the historical-source conclusion remains negative: no preserved Cicada-signed source explicitly specifies zero-based row-major addressing. The new article route is a promising conditional selector, not proof. The separate unresolved requirements remain a source rule selecting p50 as the receiver, GP-prime sums as literal addresses, the inner→outer operand order, and the p0-rune0/cell0 continuous-clock origin.

**Reopen only** if a previously unavailable original Cicada-signed instruction, source executable, or authenticated contemporaneous server implementation explicitly specifies both a zero origin and row-major linearization. A generic programming-language default, participant tool, static mirror, or later community explanation is insufficient.

# Original 2014 MP3: frozen p50 fifth-column Bitcoin-address OpenPuff receiver

**Agent 2, 23 November 2026. Original-source native test completed. Classification: one specific source-key/carrier negative. No recovered LP2 plaintext, key, hidden file or final destination.**

## Why test this particular original recipient

Original LP2 physical p49–p51 contain one continuous 32×8 table of printed base60-looking tokens, recorded in `resources/liber-primus/base60-grid.json`. The adjacent high-band tokens `48→49→4A→4B` and `4D→4E→4F`, with `4C` absent, conditionally select the fifth column as missing **L** in `HIJK[L]MNO`. Its exact original base60 32-byte scalar is

`61f7669636e6566ac772adec530e360da9f5f63469949026b0c2463a90ee16b4`.

The standard *compressed* Bitcoin secp256k1 P2PKH computation produces the exact address

`1Meanpng7jzYW69Cqmto1r2mGeEoynXdoK`.

[Source derivation, alternative encodings and look-elsewhere qualifications](lp2-p50-missing-l-secp256k1-address.md). Nothing signed by the creator specifically selects Bitcoin, a steganographic password, or this MP3; the address remains a striking but conditional output. This experiment tests the **entire literal address** once as an OpenPuff A password without trying substrings, altered letters or other depths.

The historical 2014 Cicada Stage07 *Interconnectedness* MP3 is an independently selected original carrier because a 745-byte plaintext `magicsquares.txt` was actually hidden there with OpenPuff v4.00. An MP3 already demonstrated to carry one source-authentic payload offers an especially clear negative or positive for a proposed *second* payload. That original success supplies a same-run control, not evidence that this later LP2 Bitcoin-derived password applies to it.

## Locked native contract and original result

- Input: published original `interconnected.mp3` (6,651,873 bytes; pinned Git blob `09fe068192b76a3697c47ec1d604b527703db798`), from the archived iBotPeaches Cicada 2014 repository, obtained unmodified.
- Decoder: pinned historical Windows OpenPuff v4.00 executable `466e03c792075313ce533a5dc7a789e8a41209f9` and libObfuscate.dll `f3b1c3315f8286346416fefd6141410f422f2454` (Git blob SHA-1), 32-bit Windows Python GUI driver.
- Identical settings for both runs: one original MP3 carrier; `Mp3 (Audio)`, `1/2 (50%) - Maximum`; password B/C disabled. Native GUI verified the selected bit-depth and the source capacity of **1,088 bytes**.
- Genuine same-run positive: historical password A `33011033` recovered a file with the expected **745 bytes** and OpenPuff CRC32 `6A8C41E3`. This precedes the candidate experiment and validates extraction under these settings.
- Frozen candidate password A: complete `1Meanpng7jzYW69Cqmto1r2mGeEoynXdoK`. The native *Unhide* operation returned **`Task stopped: corrupted stream`**, outcome `native-corrupted-stream`, **zero files**. The GUI's own message lists wrong password, carrier/order or bit depth as possible causes. The password is an unverified hypothesis, so we interpret this as rejection of this specific contract.

The independent original carrier positive and candidate both ran and terminated on Windows, with **completed successful workflow [45234552151](https://github.com/FlareZ123/liber-primus/actions/runs/45234552151)** and [native GUI/output evidence artifact 14850170219](https://github.com/FlareZ123/liber-primus/actions/runs/45234552151/artifacts/14850170219). The [manual reproducible workflow](../.github/workflows/agent2-p50-meanpng-mp3-original-manual.yml) pins the carrier and executable bytes, keeps all native settings fixed, demands the historical positive, and preserves original output evidence.

## Cryptanalytic decision

**Retire the complete compressed-P2PKH address as an A-only OpenPuff v4.00 password on this one 2014 original MP3 at Maximum depth.** The original audio's capacity, control and actual native corrupted-stream response rule out treating this as a hidden-file recovery, and no plausible manuscript plaintext follows. This says nothing about other source-selected consumers of the Bitcoin address, the table itself, other prior puzzle carriers or the origin of the apparently meaningful `Meanpng` prefix. A new receiver must be chosen by independent original evidence before further passwords or image/audio subsets are tested.

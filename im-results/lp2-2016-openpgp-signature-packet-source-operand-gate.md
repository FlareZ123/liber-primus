# 2016 Cicada OpenPGP packet: authentic operand gate (Issue #1368)

**Decision, 17 November 2026:** The exact author-signed 2016 clue identifies an OpenPGP *verification target*: the Cicada signing public key ending in **7A35090F**. The raw signature has exactly two standard metadata subpackets, a hashed signature-creation timestamp and an unhashed issuer key ID. Neither the signed wording nor the key/signature packet gives an authored operation that turns either metadata field, the signature MPI, or a public-key modulus into an LP2 GP29 key, state, page clock, or byte-stream receiver. **No unknown LP2 plaintext or cipher is recovered.** The packet-based key route stops at this missing selector, without scanning hashes, packet offsets, or key-ID-to-rune conversions.

## Source and concrete packet structure

- Preserved original OutGuess ASCII clear-signed extraction: [1,136-byte ASC](../resources/historical/cicada2016-4gq25-outguess.asc), Git blob **a0d8bd2d73613e01cd8a2103d5721b2b998ee482**, SHA-256 **fe89e77519dfaca998a257ed39c2861303029de2a49183db00eea0fda3a28010**. Its independent period witness and previously established good GPG verification are documented in [the source record](../resources/cicada2016-4gq25.md) and [whitespace audit](2016-signed-payload-whitespace-audit.md). The paper-raster image and OutGuess seed 230 are source-envelope data, not LP2 cipher operands.
- Armor decodes to **one old-format tag-2 signature packet** with three header bytes **89 02 1c** and a **540-byte body** (543 bytes including packet header). Body prefix **04 01 01 02** means OpenPGP v4, canonical-text signature class 0x01, RSA public-key algorithm 1, SHA-1 hash algorithm 2.
- **Only hashed subpacket:** six bytes of subpacket material **05 02 56 85 c1 c3**, where subpacket type 2 is standard creation time **2016-01-01T00:01:07Z**. This is signature-generation metadata, not the January 6 publication timestamp.
- **Only unhashed subpacket:** ten bytes of subpacket material **09 10 18 1f 01 e5 7a 35 09 0f**, where type 16 supplies the 64-bit issuer key ID **181F01E57A35090F**. The signed textual instruction supplies the corresponding short suffix **7A35090F** for key verification.
- Signature digest's stored two-byte prefix: **f0 65**; RSA signature MPI: **4,094 encoded significant bits in 512 bytes**. All 540 body bytes are accounted for by version/type/algorithms, lengths, subpackets, digest prefix and MPI; no residual extension or additional subpacket appears.
- Preserved [public-key armor](../resources/control/cicada-3301-public-key.asc) parses as packet tags **[6, 13, 2, 14, 2]**: 2012 original RSA primary key, user ID **Cicada 3301 (845145127)**, certification signature, RSA subkey and subkey-binding signature. Its primary RSA key was created **2012-01-05T03:39:43Z**, has a 4,096-bit modulus, and computes to the matching v4 fingerprint **6D854CD7933322A601C3286D181F01E57A35090F**.

All packets use defined OpenPGP fields. The timestamp's particular calendar value may reflect when the author prepared the clue; using it as a puzzle key would require an independent instruction choosing a date field and a serialization. The same holds for the digest prefix, the issuer ID, the 512-byte RSA signature, the 2012 key-creation date, the RSA modulus and the packet size.

## Independent positive, exact experiment and decision

[Node 22 CJS source-native SFT](../sims/lp2_2016_openpgp_packet_operand_sft.cjs) re-parses the existing preserved files with **no cipher-fit parameters**, checks the Git source SHA-256, independently computes the public key's v4 SHA-1 fingerprint, checks the complete packet-length and subpacket grammar, and asserts all fields above. Its source checks pass on an original Windows Git checkout after in-memory normalization of checkout-added CRLF to the preserved Git LF bytes. The authoritative signature-authenticity positive was already performed independently with GPG verify against the preserved public key, as detailed in the linked source record. [Passing Windows Node22 workflow](https://github.com/FlareZ123/liber-primus/actions/runs/44105875041). The earlier [test failure](https://github.com/FlareZ123/liber-primus/actions/runs/44105550796) arose solely because Git checkout expanded LF to CRLF, changing the temporary file from 1,136 to 1,174 bytes; the original Git blob and data were unchanged.

**Authorial instruction and strongest rival:** The sentence **“Beware false paths.  Verify OpenPGP 7A35090F.”** specifies a verifier and an identity. No first-party text inspected here instructs the solver to derive rune keys, parse signature timestamps as directions, hash the signature bytes, reinterpret the RSA modulus, or apply a packet-selected state machine to Liber Primus. The standard authentication interpretation explains the entire packet and the instruction without a new LP2 cryptographic layer.

**Predeclared stop gate met:** There is no source-selected field-to-GP29 operation or key clock to apply to even one unknown original page; evaluating candidate ciphertexts or calibration plants under arbitrary packet-byte mappings would violate the issue's discriminating test. The direct outcome is a bounded missing-selector decision, not a proof that public-key material could never be used elsewhere. If another independently sourced authorial LP2 instruction explicitly names a packet field and receiver, it could warrant a new frozen test. Until then this route should not be expanded.

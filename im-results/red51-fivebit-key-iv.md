# Source-packed red51 key and black128 IV: exact AES inversion gate

**Status (2026-11-10): completed, reproducible source-anchored hypothesis test.** No unknown LP2 plaintext, key, grid meaning, or destination was recovered. The outputs reject the tested straightforward direct interpretations as readable GP rune sequences or direct 0–28 byte arrays. They do not rule out a distinct input encoding, cryptographic key derivation, or non-AES mechanism.

## One manuscript-local key and IV construction

The original LP2 page 53, scan `70.jpg`, contains **128 black GP runes** followed by **51 contiguous red GP runes**. Both intervals have independent physical boundaries established in the corrected [red-span transcription](../resources/liber-primus/lp2-page53-red-span.json). These lengths suggest a deliberately finite, testable *hypothesis*, without supplying an original instruction to apply AES:

- Represent each red rune index in 0–28 by an unsigned **5-bit** field, yielding 255 bits from the exact 51-rune highlighted span. Insert one zero or one bit at either edge to form a 256-bit AES key. Test printed/reversed rune order, high-to-low/low-to-high bit order within each field, and normal/reversed key-byte order: **32 labeled key constructions**.
- Read each of the preceding **128 black rune indices** as one parity bit, retaining the source order or reversing it, and applying bit complement or not: **four 128-bit IVs**.
- The appearance of 255 packed bits does **not** imply 255 independent bits of entropy: 51 symbols from an alphabet of 29 carry at most `51*log2(29) ≈ 247.757` bits. The missing bit is a *model choice*, and the red/black lengths alone are insufficient to infer encryption.

This is deliberately different from the prior [red-span integer and SHA-256 derived key screen](red-marker-derived-key-probe.md), which did not combine direct five-bit red-symbol packing with a black-parity IV. All candidates are computed entirely from the source page before looking at the target.

## Exact target and completed tests

Input source is `resources/liber-primus/lp2-corpus.json` under physical page numbers. For **LP2 p52, p54, p55**, preserve 263+232+76 = **571** original ciphertext runes and apply AES-256-CTR generated bytes continuously, without page restarts. Evaluate three predeclared byte-to-GP reductions (byte modulo 29, `floor(29*byte/256)`, and reject all bytes ≥232 before modulo29), with both additive inverse signs. Total **32 × 4 × 3 × 2 = 768** candidate rune decodings.

For the separate **32×8 original base60-byte grid** across physical LP2 pages49–51, preserve the original **256-byte row-major order**. Try raw AES-256 decryption under CTR, CBC, CFB and OFB with the same 32 keys and four IVs: **512 grid outputs**, with no fitted grid permutation. Readable ASCII and literal 0–28 GP-byte counts are *necessary diagnostics only for the explicitly hypothesized direct byte encodings*. The grid could encode a cryptographic or compressed payload instead.

Selecting maxima across hundreds of configurations means neither modest score fluctuation is independent evidence.

# LP2 original grid-stream inversion as 28-symbol compressed binary

**Classification (Agent40, 10 November 2026):** executed original-source bounded negative with **byte-exact positive recovery**; no unknown LP2 plaintext, genuine key, binary payload, or Cicada destination identified. This combines two separately investigated components in a new test: predecessor-excluding 28-way ciphertext output and source-grid AES/ChaCha streams, looking for binary payloads independently of the plaintext's language.

## Explicit candidate forward mechanism

The manuscript's 32×8 printed numerical grid supplies eight genuine 32-byte keys, either its eight vertical columns or eight consecutive 32-byte row-major blocks. Original unsolved source data are all **12,956 ciphertext GP runes** on 55 rune-bearing physical pages, grouped at the eight canonical source section boundaries with runic lengths [729,1145,1738,1894,1021,1433,1680,3316].

For each source section, the first published rune initializes the output context. Every subsequent rune different from its immediately preceding published rune contributes a 28-way rank, using either (i) its sorted ordinal among the 28 GP glyphs other than the predecessor or (ii) its cyclic ordinal among the 28 nonzero successor differences. Every adjacent repeated rune is treated as a dropped/erased output exception. The rank is the sum of a source-key AES-256-CTR, AES-256-OFB, or ChaCha20 keystream symbol and an unknown 28-way message digit, modulo28; test both signs. The source keystream uses one of the eight grid-derived 32-byte keys, zero 16-byte IV, initial byte drop of 0 or 256, and either byte %28 or scaled integer floor(28×byte/256) mapping. Every source section restarts its keystream, and each source key is assigned to exactly one section.

The **testable binary-coding constraint** is strict: every five consecutive recovered base28 digits encode one unsigned **24-bit integer**, yielding precisely three binary bytes. Therefore a candidate five-digit group whose base28 integer is 16,777,216 or larger cannot have come from any three bytes under this model. This necessary-condition attack does not score English/Latin, guess compressed file contents, require known plaintext, or assume recognizable magic bytes.

There are **480** fixed global models (two grid layouts × three cipher algorithms × two byte maps × two drop amounts × two signs × two output ranks × five fixed block phases). For each model, the unique assignment of eight source grid keys to eight manuscript sections is optimized exactly using dynamic programming on **first400 nonrepeated ranks per section**, counting impossible 24-bit codewords. Freeze the configuration and key placement; independently test ranks400..699 of each section. The heldout excludes the training rank positions, but model configuration was motivated by source and historically explored predecessor-exclusion interpretations. No free per-section block phase or arbitrary key material is fitted.

## Scope and next decision

The test challenges **direct original-grid 256-bit stream keys plus predecessor-excluding fixed 5-base28-digit / 3-byte binary packing**. Exact 24-bit overflow detection is keyless once each candidate key is fixed and cannot be repaired by interpreting the bytes differently. Other possible binary formats, different ratios/radices, secret KDF/nonce or cipher state, variable-length entropy coding, hidden alphabet permutation, unknown extra rune/dummy insertion, or key-consumption changes following adjacent repeats are outside this finite search. It makes no claim that LP2 definitely contains a binary file or that the source grid is truly a stream key.

A useful successor must independently constrain a **new** cryptographic state or packetization mechanism, reconstruct binary or runic plaintext on untrained original positions, and exactly re-encode it. Merely increasing byte-drop or IV guesses after this controlled failure will be lower-value work.

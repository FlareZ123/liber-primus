The public-input counterfactual has an authentic positive example and a limit: the 2013 response is independently recoverable offline from archived **returned bytes**, although its preceding public hint does not supply those bytes. Therefore even the stronger historical phrase "already have everything" does not establish static-source completeness. The less explicit 2016 instruction cannot logically establish it either. Conversely, the signed 2012 and 2013 unique-instance wording is absent from the surviving 2014 LP2 reply. This absence is comparative evidence favoring a shared puzzle operand, not proof that no additional contact occurred.

**Key-role consequence.** Let a shared LP2 ciphertext C encode one intended plaintext P using a direct additive GP29 key tape K. At every consuming position K = C - P mod 29 (or its negation under the other fixed sign). Therefore every entrant who obtains that same P from the same C must have the identical *effective* tape on every used position. Different raw entrant-generated key bytes or independently chosen addresses cannot directly serve as different effective tapes for the one shared text. The same issue applies to any cipher in which the particular ciphertext/plaintext pair determines the effective key uniquely; general non-injective key parameterizations are not excluded. A personal GPG key could instead unlock a common separately distributed secret or instruction, or a deliberately personalized plaintext could be intended, but neither is established by the common signed pointer. This narrows the missing-input hypothesis to a **common decoder/operand distributed through individualized envelopes**, or an independently demonstrated personalized output architecture. Do not search arbitrary entrant-generated keys as candidate raw LP2 pads.

**Specific unresolved operand:** the common GP29 decoding instruction or shared key material in a separate returned payload, if such a payload existed. The known 2014 reply supplies only the onward address. A signature is verification data, not an encrypted group key; the public verification key cannot supply a hypothetical undisclosed secret. No exact bytes of this candidate operand follow from the form, the signed reply, or the 2016 message. No first-party rule selects treating the generic pointer as a GP29 receiver, so no new direct-key sweep is warranted. For the known LP2 controls, p56 is fully reproducible using the public prime-minus-one schedule with the one transparent F, and p57 is clear ([terminal control](lp2-p55-p56-p57-public-reset-backward-state-gate.md)); they demonstrate that private material is unnecessary for those pages, without constraining the secret of a distinct unknown-page regime.

**Decision for #2508:** favor internal decipherment and public, source-derived common operands over an unspecified individualized key. Preserve the private-return lane as a targeted, conditional dependency; revive only on a distinct original returned payload with exact bytes or an authentic instruction linking it to LP2. A common secret can always be posited mathematically, so public completeness is not decidable from the surviving evidence. No unknown plaintext, authenticated key or decoder was recovered. This is a dependency/operand decision, not a new exclusion of any unknown-page cipher family.

## Causal fork

There is no source-frozen LP2 operand to feed an original-cipher inverse. Stop this particular public-candidate search; revive **only** upon recovery of a genuinely new participant-upload file or dated original PGP acceptance with exact bytes and verifiable independent LP2 receiver. Without that, current action should turn to a mathematically distinct original-cipher mechanism or a genuinely new first-party artifact. No results/README.md change is warranted.

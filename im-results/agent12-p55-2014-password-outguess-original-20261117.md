# Original p55 (72.jpg): exact historical 33011033 OutGuess test

**Result, 17 November 2026: original-source negative.** Using the authentic 2014 OpenPuff password `33011033` as an OutGuess 0.4.0 extraction password on the original LP2 p55 JPEG yields a 24,438-byte high-entropy *pseudo-payload*, with no recognized file signature, PGP armor, coherent text or independent evidence of embedding. The identical `ffffffff` source-forced encrypted header already established for all 58 original LP2 JPEGs explains why a successful 24,438-byte extraction is **not** an identified hidden file. No unknown LP2 plaintext, cryptographic key or destination was recovered.

## Why this exact cross-codec key transfer was tested

The historical Cicada 2014 `Interconnectedness` audio used **original OpenPuff v4.00**, password **`33011033`**, with B/C disabled and MP3 Maximum 1/2 to hide a 745-byte `magicsquares.txt`. The repository previously recovered that exact published file, with independently authenticated original source and native CRC32 (documented in [OpenPuff original positive](openpuff-jpeg-capacity-gate.md)). The manuscript has a strongly marked original terminal p55 visual page with a tree, moth, one 13-dot red punctuation sign and repeated p27 footer. Separately, earlier Cicada releases historically used OutGuess to hide PGP messages in JPEGs, so testing the *fixed, historically successful literal password* across the alternative historic stego codec is an affordable original-source hypothesis. Neither the book nor a signed instruction assigns this password to p55 or says OpenPuff passwords are OutGuess passwords; this is a bounded transfer, not source-identified cipher architecture.

The original source and key were frozen before decoding: source-image scan **`resources/liber-primus/72.jpg`** (SHA-256 `a80191592add93a86ed3868f9e4e6ba3944ec20c9ffccc7d3e221b461344beba`), OutGuess 0.4.0 implementation `sims/outguess_extract.py` plus exact libjpeg quantized DCT bitmap compiler `sims/outguess_bitmap_dump.c`, and the single candidate password `33011033`. The source tool itself calls the scan's first 1,024 eligible bits forced, regardless of key. No other passphrase, payload offset, seed, compression or extraction version was tuned in response to target bytes.

The source program completed both extract calls and the first authentic 31,809-byte positive check exactly on the same original libjpeg/ARC4 code path. The original 72.jpg source reports a 78,648-byte eligible-bit bitmap. The purported p55 payload begins with bytes `f7a5765f9d86247bcd7de4e4466e144636816560bcec6b15c2bb56009fffd999` and is essentially maximally random at the byte level. It has no identified file type or valid PGP signature.

The `ffffffff` header is **mathematically forced by cover bytes**, as established across all LP2 images in [the original-header mechanism](lp2-outguess-universal-header-artifact.md): the 32 selected header bits always lie among the first 1,024 eligible bits, while this source image's initial eligible-bit run is far longer than 1,024 ones. For any password the apparent header is `ffffffff XOR ARC4_Encryption(password)[0:4]`. Thus the `f7a5765f` header, pseudo-seed and pseudo-length depend on the **password**, not on a deliberately embedded file. The high-entropy rest of the extraction and absence of a recognized content marker independently fail the payload test. Do not characterize the 24,438 bytes as an authenticated hidden message.

- A separate original **native OpenPuff v4.00 JPEG Maximum1/2**, single scan72 under the *same authored A-only password* was launched independently as [run 44024203669](https://github.com/FlareZ123/liber-primus/actions/runs/44024203669); its outcome must be judged on the real native program's extraction and independently published JPEG-positive control. **Decision:** Stop the `33011033` **OutGuess** cross-codec proposal for terminal p55 unless a separately authenticated source supplies an embedding format, unusual header consumer or valid file marker. The universal fake-header mechanism plus maximally random output provides no cryptographic reason to search further offsets or passwords on this page.

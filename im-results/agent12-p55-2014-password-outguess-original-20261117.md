# Original p55 (72.jpg): historical 33011033 under both OutGuess and native OpenPuff JPEG

**Decision (17 November 2026): both frozen historical-stego codec interpretations fail to recover any authentic original p55 payload.** The known Cicada 2014 password `33011033` on original scan `72.jpg` yields (a) an OutGuess 0.4.0 **24,438-byte high-entropy pseudo-payload** whose four-byte encrypted header is mathematically forced by source cover coefficients and (b) a **native OpenPuff v4.00 JPEG Maximum 1/2 corrupted-stream rejection**, with its real GUI reporting zero extracted files after a passing 35-byte published-JPEG control. These are separate codec-specific original negatives; neither supplies LP2 plaintext, a key or the destination.

## Why this exact cross-codec key transfer was tested

The historical Cicada 2014 `Interconnectedness` audio used **original OpenPuff v4.00**, password **`33011033`**, with B/C disabled and MP3 Maximum 1/2 to hide a 745-byte `magicsquares.txt`. The repository previously recovered that exact published file, with independently authenticated original source and native CRC32 (documented in [OpenPuff original positive](openpuff-jpeg-capacity-gate.md)). The manuscript has a strongly marked original terminal p55 visual page with a tree, moth, one 13-dot red punctuation sign and repeated p27 footer. Separately, earlier Cicada releases historically used OutGuess to hide PGP messages in JPEGs, so testing the *fixed, historically successful literal password* across the alternative historic stego codec is an affordable original-source hypothesis. Neither the book nor a signed instruction assigns this password to p55 or says OpenPuff passwords are OutGuess passwords; this is a bounded transfer, not source-identified cipher architecture.

The original source and key were frozen before decoding: source-image scan **`resources/liber-primus/72.jpg`** (SHA-256 `a80191592add93a86ed3868f9e4e6ba3944ec20c9ffccc7d3e221b461344beba`), OutGuess 0.4.0 implementation `sims/outguess_extract.py` plus exact libjpeg quantized DCT bitmap compiler `sims/outguess_bitmap_dump.c`, and the single candidate password `33011033`. The source tool itself calls the scan's first 1,024 eligible bits forced, regardless of key. No other passphrase, payload offset, seed, compression or extraction version was tuned in response to target bytes. Native OpenPuff uses the same historically attested A-only password, fixed standard JPEG Maximum 1/2 option and one original carrier, but has a distinct hidden-file wire format from OutGuess.

The source program completed both extract calls and the first authentic 31,809-byte positive check exactly on the same original libjpeg/ARC4 code path. The original 72.jpg source reports a 78,648-byte eligible-bit bitmap. The purported p55 payload begins with bytes `f7a5765f9d86247bcd7de4e4466e144636816560bcec6b15c2bb56009fffd999` and is essentially maximally random at the byte level. It has no identified file type or valid PGP signature.

The `ffffffff` header is **mathematically forced by cover bytes**, as established across all LP2 images in [the original-header mechanism](lp2-outguess-universal-header-artifact.md): the 32 selected header bits always lie among the first 1,024 eligible bits, while this source image's initial eligible-bit run is far longer than 1,024 ones. For any password the apparent header is `ffffffff XOR ARC4_Encryption(password)[0:4]`. Thus the `f7a5765f` header, pseudo-seed and pseudo-length depend on the **password**, not on a deliberately embedded file. The high-entropy rest of the extraction and absence of a recognized content marker independently fail the payload test. Do not characterize the 24,438 bytes as an authenticated hidden message.

## Distinct native OpenPuff 4.00 original p55 decision

The original [native OpenPuff source-pinned workflow](https://github.com/FlareZ123/liber-primus/blob/main/.github/workflows/agent12-p55-authored-password-openpuff-maximum.yml) used **Windows 32-bit** Python, the SHA-1 Git blob identity-checked historical `OpenPuff.exe`/`libObfuscate.dll` pair from archived ToolSuite, original image **`72.jpg`**, the exact 2014-authored A=`33011033` with B/C disabled, native `Jpeg (Image)` and **`1/2 (50%) - Maximum`**. Its first mandatory **independent positive** truly unhid the public JPEG's exact **35-byte** message under the published A=`12345678` using the *same* real native OpenPuff JPEG driver (log `NATIVE_ORIGINAL_PUBLISHED_35BYTE_POSITIVE_PASS`).

The subsequent original p55 run recorded **one carrier added, correct bit level verified, extraction actually attempted, native capacity 3,040 bytes**, then OpenPuff itself raised the modal **`Task interrupted - Error`** with message **`Task stopped: corrupted stream`** and explanations about possible wrong password, carrier ordering, or bit level. The extracted output file list was **empty**, `output_present=false`; its actual state was **`native-corrupted-stream`** rather than a timeout. These outcomes were captured in the [passing original Windows Actions run 44024203669](https://github.com/FlareZ123/liber-primus/actions/runs/44024203669) and [native GUI/screenshots and JSON artifact 14303017090](https://github.com/FlareZ123/liber-primus/actions/runs/44024203669/artifacts/14303017090).

This closes the **exact single-original-p55, historically attested A-password, native JPEG Maximum1/2** route after an independent genuine JPEG positive. It is distinct from earlier native tests of all 58 *individual* LP2 JPEGs at **Medium 1/5**, and the full 58-image **Maximum1/2 carrier chain**, both prior bounded negatives. Neither experiment excludes an independently instructed other password or hidden codec, but the primary source supplies no such selector.

**Decision:** Retire both original p55 `33011033` direct OutGuess and native OpenPuff Maximum1/2 interpretations. Do not infer a hidden message from OutGuess's forced `ffffffff` header or treat native OpenPuff's corrupted-stream modal as a valid file. No original plaintext, secret key or Cicada destination has been found by this route; any revival requires an independently authored source selecting different extraction parameters, rather than searching arbitrary passwords or offsets.

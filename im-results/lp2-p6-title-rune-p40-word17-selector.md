# P6 title-rune alignment selects p40 word17/start71 without exporting address71

**Agent19, 28 November 2026. Classification: materially strengthened target-blind receiver provenance for the existing p40 `PATHS` candidate.** The already source-selected p6 11-rune red title aligns in printed order with the already source-selected 11-word authenticated tail `YOU ... OPENPGP`. In the second q=4 block, the four red runes `[6,27,15,17]` therefore align with `LUCK BEWARE FALSE PATHS`; the PATHS-aligned rune is literal value **17**. Interpreted as a one-based local word ordinal on the independently selected physical p40, it chooses **word17**, whose canonical start is **71**—exactly the receiver previously reached only by exporting p6's self-address71 across pages.

This does not establish the corridor plaintext or a universal serializer. The ordinal interpretation was recognized after the p40 candidate existed, and most of the eleven title-rune/page pairings are not target-length compatible. It does, however, remove the need for the specific unsupported operation “copy p6 offset71 to p40” in the p40 receiver path. A broad target-blind control also shows that the already published exact p6 key `[20,20,12,6]` has only one authenticated four-rune output across every four-rune receiver addressed by any p6 red-rune value on p32–p42: the same p40 word17 -> `PATHS` event.

## Manuscript-wide exact-key receiver charge

The local corridor result survives progressively broader receiver freedom while keeping the already source-derived exact key `[20,20,12,6]` fixed.

1. Allow any distinct p6 red-rune value to address either zero- or one-based local words on **all 55 rune-bearing unknown physical pages**, retaining only four-rune receivers. This produces **174 labeled selectors / 149 distinct receivers**. Across both additive signs and all nine authenticated four-rune source spellings, **2,682 comparisons** give one event: `p40 start71`, subtraction, `PATHS`.
2. Remove the p6 address vocabulary entirely and test all **509 complete four-rune manuscript words**. Across both signs and the same nine targets, **9,162 comparisons** again give only `p40 start71 -> PATHS`.
3. Remove word boundaries as well. Across all **12,791 contiguous four-rune windows** contained within unknown physical pages, both signs and all nine targets, **230,238 comparisons** still give exactly one event: `p40 start71 -> PATHS`.

Thus, once the exact `[20,20,12,6]` key is accepted from its separate source/layout derivation, the manuscript itself leaves no receiver or segmentation ambiguity for an authenticated four-rune source output. This is stronger than the original offset71 receiver family and independent of the new rune17 ordinal interpretation.

## Key-family boundary

The result does **not** make the previously charged broad visual key family uniquely predictive. Widen the exact key back to all 1,389 coordinate permutations of the existing p6 visual family `[r,r,x,y]`, with `r in {20,22,24}` and `x,y` drawn from the nine distinct p6 title-rune values. Across the 26 distinct red-rune-addressed four-rune receivers, both signs and the nine authenticated four-rune targets, four distinct output events survive:

~~~text

p39 start22  add      -> SEEK
p40 start71  subtract -> PATHS
~~~

Therefore the new evidence strengthens **receiver provenance**, not arbitrary p6-key choice. The exact `[20,20,12,6]` key still needs its separate signed-tail/p6-layout derivation. This boundary is important because the broad key family is large enough to manufacture unrelated authenticated hits once the receiver family expands.

## Universal-serializer check

The eleven-rune alignment is not a complete p32–p42 receiver serializer. Under the literal forward/one-based pairing, most selected words do not even match their assigned authenticated target lengths. In particular, the rule should not be generalized to “every title rune is the receiver word number for its paired page.” Its value is narrower: within the W3 q-block, it supplies an independent, source-ordered numeric route to the already important p40 receiver.

This is consistent with the current frontier: p6 appears to encode a state/selection vocabulary, while the full per-page serializer remains unknown.

## Decision

Upgrade p40 receiver provenance from:

~~~text
p6 self-address71
-> retrospectively export same offset71 to p40
~~~

to the more local source-ordered route:

~~~text
p6 source-only 11-word selector
-> W3 aligns with LUCK / BEWARE / FALSE / PATHS
-> PATHS-aligned W3 rune = 17
-> p40 one-based word17
-> start71 [4,15,14,21]
-> existing source-derived key [20,20,12,6]
-> PATHS.
~~~

The ordinal operation itself was recognized after PATHS, so preserve candidate-level chronology. The broad controls show that the fixed exact key and p6 red-rune receiver-address family select only the p40 PATHS event, while the 1,389-key family does not remain unique after widening receivers.

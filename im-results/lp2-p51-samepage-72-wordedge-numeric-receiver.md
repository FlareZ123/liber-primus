# Physical p51's exact 72/72 local receiver and the original-cipher decision

**Agent6, 22 November 2026.** An exact, unique-in-manuscript source layout identifies a bounded 72-rune receiver directly below the last 72 tokens of the LP2 32×8 numeric table. **All directly motivated reversible interpretations tested so far fail to recover native GP plaintext.** This is an exploratory structural route, not an authenticated instruction or solved page.

## The source-selected alignment

The physical p51 scan `68.jpg` contains the final **9 rows × 8 columns = 72 two-character numeric tokens**, followed by **92 original GP29 runes in 20 printed words**, starting `WWP`. Shedding one *first* or one *last* rune from each of the 20 words leaves precisely **72** retained runes. One printed singleton word yields an empty retained word; do not silently replace its source boundary. Both readings and every numeric byte use untouched `resources/liber-primus/lp2-transcription.txt`, `lp2-corpus.json`, and `lp2-grid-256.json`, including the actual p50 table's page-split metadata.

In a separate manuscript-wide census of the **55 rune-bearing encrypted physical pages**, using the same literal printed punctuation and line-wrap rules, p51 is the **only page** whose local rune count minus the number of printed words is 72. The nearest other values are p55=59 and p49=48. P51 is also the only encrypted physical page printed directly under a **72-cell numeric panel**. This is a meaningful geometric selector for a further deciphering attempt, though the solved p57 invitation to “shed our own circumferences” might more naturally imply peeling **both** ends. The author has not explicitly selected first versus last, table/rune traversal, or an arithmetic operation. Treat this as a **candidate** human solve path.

The lossless word-edge receiver has a source-visible rationale: the 20 removed edges serve as initialization state for the 20 corresponding words, rather than being thrown away; the 72 numeric cells each key one retained rune. In mathematical terms, with transmitted edge state `s`, current rune `c` and next source table value `b`, the candidate reads `p=(c±(b mod29)−s) mod29`. The state is updated to the prior `c` or prior `p` within a word, then reset to the next printed edge. The exact inverse is a defined, reversible 92-symbol codec. Both feedback choices remain **hypotheses**: there is no authored rule selecting this arithmetic or proving that shed edges are IVs.

### Source-native plaintext calibration

To challenge the 72-rune frequency invariants without expecting *identical* English vocabulary, the reproducible test converts the pinned editor-normalized solved Cicada LP1 text `resources/liber-primus/lp1-plaintext-reference.txt` into **3,107 GP29 indices** using the published transliteration/digraph conventions. It measures **every one of 3,036 overlapping contiguous windows of 72 runes**, without fitting an inverse to the ciphertext. The *lowest* solved-reference IoC is **0.04577465**. **Zero of 3,036** controls are as flat as either shed p51 receiver or any of the eight lossless source-table word-IV outputs. The 24 contiguous solved p57 windows of length72 have minimum IoC **0.05790297**.

These overlapping windows are descriptive controls, **not independent random samples or a discovery-adjusted statistical p-value**. The LP1 reference is editor-normalized, and an unknown English text could be flatter; the result excludes the proposed **solved-control-shaped, permutation/bijection-only decoding path**, not all possible historical encodings. The original full p51 cipher (92 runes) is itself nearly uniform (IoC **0.03272814**), so an evolving alphabet, external key or other nonlinear structure is entirely possible.

## Reproducibility and research decision

The standalone, source-read-only [Windows Node.js 22 SFT](../sims/lp2_p51_samepage72_wordedge_numeric_receiver_sft.cjs) performs original rune/page assertions, exact duplicated-byte lookup upper bounds, all eight direct ± numeric masks, solved-native source frequency windows, 9×8 transposition and inverse, and the eight lossless 92-symbol original-replay/solved-plant word-IV codecs. Its latest revision passed [Windows Actions run 44978059310](https://github.com/FlareZ123/liber-primus/actions/runs/44978059310) at source commit `2fc4791a3d563f46ebebc84dcc335f2288957cf8`.

**Decision:** The original 72/72 geometry is worth retaining as a *potential* creator-chosen receiver. It is much more constrained than an arbitrary table-to-page pad alignment. Retire direct fixed substitutions, any mere 9×8 reshuffle/fixed alphabet, and both tested word-local feedback codecs as original plaintext decoders. They have explicit reversible positive controls and decisive original-input negatives. A successor must obtain an **independently specified changing substitution/state operation or missing external key**, predict a nontrivial untouched stretch of readable GP words, and reproduce the full original input. Counting additional numerical alignments or enlarging the same local affine/feedback family without a new source cue would be low-value.

# Original 256-byte page-grid as an RC4 source for reversible GP29/rank28 encryption

**Status, 10 November 2026:** a finite, fully executable original-ciphertext source-key challenge. No original LP2 plaintext, authentic cipher key, or destination recovered. This is an independently fixed key-source application to an actual invertible cipher, rather than a random search over learned plaintext-key words.

## Hypothesis and exact source

LP2 physical pages 49–51 show a 32×8 base-60 representation of **256 original byte values**. Use the [normalized page grid](../resources/liber-primus/base60-grid.json), serializing those bytes in either printed row-major or column-major order; reverse each serialization or retain it; feed the literal 256-byte vector into RC4's standard 256-entry KSA, or first hash that vector to a 32-byte SHA-256 key. This provides **eight precise original-image-derived key byte strings**. Generate RC4 stream bytes after one of **0, 256, 768, 3072** skipped PRGA bytes. Reinitialize at each physical rune-bearing page or continue globally. Pad each raw byte by the whole low eight-bit value or the high five-bit value (right shift by 3), with either key sign.

Two candidate transforms:

1. **Direct GP29 affine-pad encryption:** \(C_i=P_i+s K_i\bmod29\), with sign \(s\in\{-1,1\}\).
2. **Reversible exponent-step encryption:** for each page after the first rune, \(C_i=C_{i-1}\) iff \(P_i=EA\) (GP index 28), else \(C_i=C_{i-1}+15^{(P_i+sK_i)\bmod28}\bmod29\). The page first rune is an initialization symbol, and the stream clock nevertheless consumes its pad byte. This is the same lossless EA/field convention as in [the other source-blind attacks](reversible-exponent-feedback-lookup.md), tested with an independently determined source key rather than arbitrarily learned tables.

The Cartesian test covers exactly **512** configurations (eight source serializations, four drops, two page/global clocks, two transforms, two byte projections, two signs). Original untouched inputs are the canonical 12,956 ciphertext runes on p0–55. Training selects configurations by source IoC on physical pages0–27 (6,761 runes); the other 6,195 runes are evaluated only after selection. Both matrices are original source hypotheses; the key variants and RC4 itself are *not* historical facts.

## Executed original results

The highest original training IoC among 512 configurations is **0.03542931133922453**. Its source is *SHA256(column-major reversed grid)*, RC4 drop0, per-page reset, high-five-bit pad, positive sign, and the reversible F29 difference model. Its independent holdout IoC is only **0.03522260991982921**, close to the random 29-rune baseline 1/29. Other high-training variants (0.0354097, 0.0354028, 0.0353691) similarly have no source-English GP unigram concentration on the heldout pages. No credible runic plaintext resulted.

**Independent exact positive control:** encode the checked-in 218,800-GP-rune Shakespeare reference over the precise original 55 page shapes. Plant RC4 with the literal row-major table, drop768, page-reset, low-byte mod28 pad, positive sign, and reversible F29 difference. Blindly rescore the same 512 configurations. The planted true key is the **highest training candidate**, recovers **all 12,956 of 12,956** original-source-shaped plaintext runes, and has decoded train IoC **0.06199876773244391** and heldout IoC **0.060381743586375734**. The second-best planted variant has training IoC only **0.03619457749763917** and 1,212 exact matches. This establishes that the finite key-source test has genuine discrimination and an exact reversible positive control.

All numbers and encoded vectors are generated by [the single runnable Node script](../sims/grid_rc4_field_inverse.cjs), invoked manually by [successful GitHub Actions 42800026403](https://github.com/FlareZ123/liber-primus/actions/runs/42800026403). The code uses Node's standard library and the committed canonical corpus, grid and Shakespeare controls. The manual workflow does not run on git pushes.

## Scope and research decision

These results disfavor the **tested 512 deterministic grid-to-RC4 additive/field-difference pad families under a GP-English plaintext register**. They do not exclude altered KSA algorithms, red-runic or historical passphrase salts, different byte clocks, null insertion, compression, alternate plain languages, or other uses of the 256-byte table. Direct source-grid pads and SHA256/AES/ChaCha source keys have already been examined elsewhere in this repository; without a new source-constrained state clue, these RC4 variants should not be multiplied into additional arbitrary clock or KDF choices.

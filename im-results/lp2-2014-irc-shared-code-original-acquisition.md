## Restored period-original cluosh Git code: complete bounded unknown-page replay (Agent36)

An explicit GitHub repository-name search found surviving [`kenorb-contrib/cicada_toolset`](https://github.com/kenorb-contrib/cicada_toolset), retaining **25 first-party-authored Git commits dated 4 May–3 June 2014** under the historical `cluosh` name and `cluosh@shadow-code.org` address. These predate the verified 29 July 2014 IRC link to the then-live `cluosh/cicada_toolset`. The latest preserved commit is [`bd63ab1475e08b6125860f5c74f0271977ab8a69`](https://github.com/kenorb-contrib/cicada_toolset/commit/bd63ab1475e08b6125860f5c74f0271977ab8a69), at **2014-06-03 14:54:53 UTC**. Its exact 18,283-byte code object is Git blob **`9a82a844d8574d2040eed60de76f4becdd77a666`**, independent of the former repository's current 404. The original July state could have contained later unpreserved commits, so the source-preserved June snapshot is the precise supported version. There is no apparent redistribution license in the copied tree; the reproducer loads this immutable exact blob from the author-preserving public location and verifies its Git hash, rather than duplicating the source.

The original 704 lines define `RuneText`, all **29 canonical rune numbers**, 29 GP prime weights, file/word/rune parsing, letter counts, IoC, Friedman/Kasiski, autocorrelation, printable rune conversion, four Vigenère orientations, configurable masks, `vigenereDecrypt(cipher,key)=(cipher-key)%29`, and `key_from_primes`. They contain **no fixed key for page 0 or page 54, no file or block cipher, no decoder entry-point invoking those pages, and no authenticated unknown-page plaintext**. The default `vigenereTry(keyword="")` does not define a usable inverse; the caller must select an actual key. The source therefore resolves which *historical operation the July IRC URL offered* (an exploratory, parameterized GP29 toolkit), while withholding the operand essential to a genuine decipherment.

A [source-exact standalone original-code replay](../sims/lp2_2014_cluosh_original_tool_replay_sft.py) loads and executes the **unaltered 2014 class** after Git blob verification. Its original `vigenereDecrypt` primitive plus the independently documented May 25 p56 F-skip restores **all 85/85 authentic solved p56 GP runes**. The recovered 30 July 2014 participant sources and present original printed-cipher inputs are separately parsed with the genuine `RuneText` parser. The historical source's literal `key_from_primes` string also has a concrete parser defect: for prime 29, its intended key `-1` becomes the substring `--1` in a hyphen-separated key; `vigenereTry` discards the empty field and treats the residue as `+1` at zero-based position **9**. ## Genuine original-cipher test

The recovered `56.py` uses GP values 0–28, reads the next prime `q`, outputs `P=(C-q+1) mod 29`, and at original rune **position 56** copies the original F unchanged **without advancing the prime clock**. Its frozen 2014 `56.runes` corresponds to **all 85 original p56 ciphertext runes**, and the exact recovered algorithm restores **85/85 source-native GP plaintext runes** of the historically solved *AN END* text, including the skip. This is more informative than a synthetic cipher implementation: both original code and matching input were contemporaneously shared.

The [complete standalone source regression](../sims/lp2_2014_irc_recovered_files_source_sft.cjs) then applies the **same positional rule without fitting** to original p0 (262 runes) and p54 (232 runes). It produces IoC **0.0348044807** and **0.0361247947**, respectively, and neither yields English plaintext. More decisively, the position-56 cipher glyph on each unsolved page is **not F**: copying it unchanged is a page56-specific interruption with no source instruction to transfer the skip. This exact historical script therefore does **not** provide a valid source-selected decoder for either unknown page. The all-page prime-totient variants were previously tested; this result does not reopen a key sweep.

The independent July 30 participant transcriptions also differ from the shared original-image-derived corpus: page 0 has eight nonidentical GP values (zero-based positions **98, 99, 100, 104, 108, 131, 156, 209**), whereas the page54 paste contains **233** GP labels for the **232** physical page54 runes, with three differing common positions (**39, 134, 202**) plus an extra final `NG`. The final `NG` appears to belong to the cross-page continuation onto p55, rather than to p54's physical glyph sequence. These are diagnostic historical textual variants, not proof the modern source is wrong; investigate directly against original ink before using them as corrected ciphertext.

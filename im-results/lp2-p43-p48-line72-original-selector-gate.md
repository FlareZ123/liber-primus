# p43–48 -> p51 72-line cross-chapter proposal: original-image selector gate

**Agent50, 23 November 2026. Original-source structural audit; no unknown plaintext recovered.** Director [#2391](https://github.com/FlareZ123/liber-primus/issues/2391) proposed that six twelve-line flower pages (physical pp43–48, source scans 60–65.jpg) might supply a 72-symbol key for the 72 p51 runes left after taking one edge from each of its 20 words. The 72/72 alignment is arithmetically exact. The missing step is an authored command selecting *which six pages, which rune on each line, the traversal order, and a reversible p51 operator*. The original source does not uniquely select any of these.

## Original manuscript falsification of a unique 72-line source

Using physical-page indices and the repository's literal printed-line separators, **every physical page p41 through p48 has exactly twelve rune lines**, for eight consecutive pages. Thus, within the same uninterrupted floral text block, the equally viable six-page 72-line windows are **p41–46, p42–47 and p43–48**. The full p0–55 physical source contains two additional six-page windows totaling 72 lines: **p8–13 and p16–21**. These five matches are exhaustive under the explicit contiguous six-page/72-line criterion; p50 is correctly treated as runeless in the source transcription.

The proposed p43–48 choice is recognizable as the six pages *immediately before* the p49 numeric panel, which is a possible human heuristic, but there is no printed “previous six pages” instruction. The original page line endings are overwhelmingly typographic rather than word-final: **10 of the 72 p43–48 lines end at a printed word boundary; 62 end inside a word**. Therefore a first/last-rune-per-line key is highly sensitive to arbitrary line wrapping and needs an independent source command to become a meaningful cryptographic operation. This observation does not prohibit the creator from intentionally using typesetting as a key.

## Exact original art comparison

At native JPEG resolution 2400×3600, the **entire tested left floral side region** `(x0,y0,x1,y1)=(90,650,500,2650)` and the **entire tested right floral side region** `(1900,650,2300,2650)` are *pixel identical* across **all eleven images 58.jpg–68.jpg**, corresponding to physical pp41–51, including the three numeric panel pages. Each region contains extensive nonwhite flower and punctuation-dot pixels (the reference p41 left region has ~101,995 dark pixels, right ~100,056, using RGB channels <200). Hence the side leaves, curls and repeated dot clusters cannot distinguish p43–48 from the rival windows. This is an exact source-image crop equality, not a lossy perceptual-similarity judgment. The result says nothing about text glyphs or page-specific artwork outside the two explicit boxes.

The p57 cleartext instruction about shedding circumferences permits investigation of word-edge stripping, but does not name line extraction, a first-versus-last edge, six backward pages or a 72-value arithmetic consumer. P51's existing **72 local numeral cells → 72 one-edge-shed runes** is already a more immediate geometric match, and the relevant direct numeric masking, sorting and feedback inverse families were tested negatively in [the p51 same-page report](lp2-p51-samepage-72-wordedge-numeric-receiver.md). Applying the same families to an independently unselected line key would amount to choosing free parameters after observing ciphertext.

## Reproduction and decision

The read-only [Python/Pillow source audit](../sims/lp2_floral72_line_selector_sft.py) consumes the actual `resources/liber-primus/lp2-transcription.txt` and original JPEGs, verifies five six-page windows, the p43–48 line-boundary count and exact nonempty flower-region equality. Source originals are the comparison basis; no hypothetical plaintext or trained language model enters the result.

**Decision for #2391:** Close the proposed *authored cross-chapter selector* as **not established**. The 72/72 arithmetic survives, while no source-specific line extractor, key ordering, page selector or complete reversible p51 decoder is available. Do **not** open unconstrained 72-rune keystream fitting or reinterpret the identical flower pixels as page-specific symbols. Reopen only upon independent first-party evidence that names a definite six-page source, line/rune selector and consuming operation. The general possibility of a later-discovered line-dependent key remains open.

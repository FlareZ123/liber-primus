# The LP2 32×8 table excludes full-length printable 8-bit and 7-bit uppercase ASCII under static bit wiring

**Decision, 15 November 2026.** The original p49–p51 256-cell numerical table cannot supply **32 complete printable 8-bit ASCII characters** by assigning one source-derived Boolean property to each cell, reading each printed row's eight cells as one byte, and then applying any fixed permutation of the eight bit columns with arbitrary fixed bit inversions. A stronger all-secret original-source result also excludes **32 printable 7-bit ASCII characters in the range 32–95 (uppercase letters, numbers, punctuation and spaces)** even if one printed bit column is discarded. Positive constructions pass both exact invariants. **No unknown LP2 plaintext, key, or address was recovered.**

## Original clue and motivated candidate

The original manuscript prints **32 physical rows of eight two-character base60 tokens**, distributed across the three unchanged scans 66.jpg, 67.jpg and 68.jpg. Their canonical source-derived byte readings are [the 256-cell reference](../resources/liber-primus/lp2-grid-256.json). Grouping eight binary observations into one ASCII character is an understandable human-puzzle hypothesis; an earlier Cicada round also used an eight-bit whitespace text carrier. The historical whitespace source does not establish that this particular LP2 table is a binary message, so the test is a bounded *hypothesis*, not an author-authenticated decipherment instruction.

The [original-source CommonJS SFT](../sims/lp2_table_bit_column_ascii_exclusion_sft.cjs) tests fifteen fixed Boolean properties of each original table cell: every one of its eight numeric byte bits; quotient and remainder parity under division by 29; base60 second character lowercase/digit class and first character parity; 8-bit popcount parity; and ordinary integer primality. These are independent visible/source-arithmetic readings, without fitting a property after seeing any candidate text.

## Exact all-secret fixed-column obstruction

Let B(r,c) be a candidate property at one of the original 32 rows r and eight printed columns c. A fixed column-order mapping with a fixed XOR inversion mask creates an output byte per row. If all 32 bytes are ordinary 7-bit ASCII, **their most significant bit is zero for every row**. Whatever secret column supplies that output bit must therefore be all-zero or all-one across the 32 original rows. Inversion of a changing column cannot make it constant, and a permutation only moves that column.

For **all fifteen original-value selectors**, each of the **eight** source bit columns has at least one zero and at least one one among the 32 original rows. Consequently **no** fixed eight-bit column permutation or fixed XOR mask yields 32 complete ASCII bytes. This is an exact key-independent impossibility for the specified family; searching all 8! column orders and 2^8 inversion masks cannot rescue it. The SFT prints each source column's complete one-counts so the obstruction is independently auditable.

**Control:** a known source-length 32-character ASCII phrase is converted to eight bits per row, then its columns are permuted and individually inverted. The test recovers the required invariant of at least one constant source column. It therefore distinguishes a genuinely possible unknown-wiring ASCII plant from the original table's 15 candidates.

## Stronger exact 7-bit uppercase-ASCII obstruction with one spare column

A row containing any printable ASCII character with code 32–95 (uppercase letters, numbers, punctuation or space) has **bit5 XOR bit6 = 1**. Binary 32–63 has bits5=1,6=0; binary 64–95 has bits5=0,6=1. Thus even if one of the original eight printed columns is discarded as parity/checksum, the two distinct columns supplying these two ASCII bits must remain **exactly equal or exactly complementary across all 32 rows**, up to individual fixed inversions. No possible permutation or secret fixed XOR mask changes this requirement.

For all fifteen frozen original bit-source features, **zero out of the 28 distinct source-column pairs** is equal or complementary across the original 32 rows. This is an exact necessary-condition failure over the complete specified wiring family, independent of any brute-force key search. The planted phrase **WELCOME PILGRIM TO LIBER PRIMUS**, padded to 32 bytes, is subjected to a distinct global bit permutation and fixed XOR inversions: its original-space image contains **one** qualifying column pair, and the updated SFT asserts it. This also excludes full-length mixed uppercase/digits/space instructions, a natural intended printable register, while allowing messages containing lowercase and alternative phase-dependent or nonlinear bit encodings.

## Precise scope and research decision

This excludes **full-length 32-row printable 8-bit ASCII**, and the more permissive **7-bit uppercase/punctuation ASCII with one discarded column**, under the tested per-cell one-bit predicates and *row-independent* bit wiring. It says nothing about a shorter address padded with high-bit binary data, seven-bit lowercase or extended-ASCII text, variable row-dependent keys, external codebooks, another source-selected predicate, a reordered cell traversal, or a binary cryptographic key. None of those alternatives can be promoted without its own independent source clue. The printed 32×8 form alone does not supply a recovered address or plaintext; the next productive move requires identifying an author-selected property, route or additional key before using this table as a decoder.

# Historical source-PDF/PostScript gate for the original 2014 LP2 master

**Agent42, 17 November 2026 · Director [#1328](https://github.com/FlareZ123/liber-primus/issues/1328).** This is a bounded public-custody check of one missing *original source-object* hypothesis. **No eligible source PDF/PostScript bytes, original text objects, font map, new key or unknown-page plaintext were recovered.** Do not treat a Ghostscript signature in an existing JPEG as proof that a recoverable original PDF was publicly distributed.

## Exact independently preserved distribution archives

1. [Micheloosterhof 2014 stage11 Onion7 capture](https://github.com/micheloosterhof/cicada-2014/tree/master/stage11/ky2khlqdf7qdznac.onion), original HTML at [index.html](https://github.com/micheloosterhof/cicada-2014/blob/master/stage11/ky2khlqdf7qdznac.onion/index.html), Git blob SHA-1 `303db130705f0ef9be2a738f4336d5cfcebde80c`: the exact archived landing document is titled `133` and names only `0.jpg` through `57.jpg` in 58 `<img src="N.jpg" />` tags. Its preserved directory contains **58 JPEGs + one index.html**, and lists no PDF, PS, font file or source script. That does **not** prove the 2014 server had no unlinked private builder artifact.
2. [Krisyotam `liber-primus/original-onion7/`](https://github.com/krisyotam/cicada3301/tree/main/liber-primus/original-onion7) independently publishes the same **58 JPEGs, `index.html` and `message.txt.asc`**, exactly 60 named entries at repository tree inspection (the repository README calls it 61 raw files; its current visible directory table is 60). [The archived landing HTML](https://github.com/krisyotam/cicada3301/blob/main/liber-primus/original-onion7/index.html) again names only the 58 JPEGs. No PDF/PS, `/BaseFont`, `TJ`, or edit-level source file is among those named assets.
3. [2014-community transcription/preservation archive](https://github.com/cicada-solvers/documenting-cicada3301-scream314/blob/master/liber_primus.md) explicitly presents LP1/LP2 as **75 JPG images** and page-by-page original JPEG links. The published downstream records do not identify a May-2014 vector master as an original distribution file.
4. A concrete publicly retrievable PDF candidate, [`pnotisdev/cicada3301/LiberPrimus.pdf`](https://github.com/pnotisdev/cicada3301/blob/main/LiberPrimus.pdf), is documented by its own [source inventory](https://github.com/pnotisdev/cicada3301/blob/main/docs/SOURCES.md) as **“a print of those 75 images.”** Its origin is a later 75-image compilation, so the source owner himself disqualifies it from the requested contemporaneous vector/text-object analysis. No original `TJ` stream can be assumed from it.

## Source of the rendering-master hypothesis

[Dukotah/cicada3301 Round 30](https://github.com/Dukotah/cicada3301/blob/master/liber-primus/analysis/round30/SYNTHESIS.md), [AGENTS.md](https://github.com/Dukotah/cicada3301/blob/master/AGENTS.md) and [README](https://github.com/Dukotah/cicada3301/blob/master/README.md) independently analyze original JPEG rendering, reporting an embedded ICC profile byte-identical to Ghostscript's Artifex `srgb.icc`, plus image geometry consistent with a machine-rendered font. Later analysis narrows the rendering range to Ghostscript 9.05–9.14 (the toolchain's date-era subset). **These claims are evidence about rendered JPEGs and a rendering process.** They do not identify actual May-2014 PDF/PS source bytes, their original `/BaseFont`, their true `TJ` arrays or an alternate rune-order channel. The external Round 30 synthesis itself labels recovery of those bytes an *off-repository archival hunt*, and claims no plaintext or decipherment from the renderer facts.

## Decision and precise missing input

The **surviving source landing page offers only images**, and the specific public original-site captures and named later PDF wrapper checked above provide no author-era vector/text master. This is **a bounded negative for those repositories and candidates**, not a statement that a historical unpublished PDF/PS never existed or that any hidden server file was inaccessible. The proposal cannot currently choose a new original-cipher operation or make a held-out prediction. There is no justification for more Ghostscript release pinning, guessed BaseFont names, PDF raster reconstructions or kerning/stego sweeps from the same JPEGs.

Reopen the source-object channel only on a new primary lead providing an independently dated **pre-/at-May-2014 vector PDF, PS, EPS, original font, typesetting build source or a contemporaneous signed link**. For that artifact, retain exact URL/custody/date, actual bytes/size/SHA-256, and require original text/font objects distinct from JPEG-page wrappers before attempting a cryptographic decode. Redirect live effort to an original-cipher inverse with a source-selected key or recovered plaintext.

## Direct sum-rank transfer to the original 256-cell LP2 table (Agent33, #2448)

The historical 2012 operation is more specific than a generic musical key: for every note-off event take its pitch number plus delta time, sort distinct sums, and assign one alphabet character per rank. The exact source-native operation is reproduced from the pinned original `song.mid` using [the source decoder](https://github.com/neuroretransmit/cicada/blob/b13600373d3400d75ec4208198019f3d92a304dd/2012/009-midi-puzzle/decode.py). It recovers both 558- and 714-letter tracks with exactly 25 and 23 distinct sums respectively, including the exact first-track participant list and all three 238-letter chorus repetitions. The original decoded SHA-256 values are `8647147926d83ceb2ca73233121a35e5d9e8bbbbbbd8c709e747fb5ba8022d2f` and `2f5bd7c03e66177acefb26900eabe736378240089ad052f890d5868046ba9111`.

The only obvious new physical pair-valued LP2 receiver for this exact arity is the printed two-glyph numeric table across p49–51. The visible two-glyph cell structure licenses a test of the historical two-input sum, but there is no first-party instruction assigning the MIDI operation to these cells. No inferred plaintext or key is used. Freeze a direct sum of the two glyph digit values, followed by ranking distinct sums onto one GP29 symbol each, consuming every cell in printed order. Test both previously documented interpretations of the digit alphabet (conventional 60 and drop-`f` 59). The original token census gives:

| Register | Cells | Distinct digit sums, radix 60 | Distinct digit sums, radix 59 |
|---|---:|---:|---:|
| p49 | 80 | 43 | 43 |
| p50 | 104 | 48 | 48 |
| p51 | 72 | 40 | 40 |
| Whole table | 256 | 60 | 60 |

Each receiver contains more than 29 classes even when treated independently, so the direct historical rank-to-symbol bijection cannot emit native GP29. Furthermore, all conventional digit sums are at most 61, whereas the historical track sums begin at 67 and 79; **zero** original table sums match either actual historical lookup. Treating the table as a fixed shared two-field additive code with *arbitrary* digit values does not rescue the whole-table receiver: for first glyphs 0,1,2,3,4, the numbers of distinct second glyphs are 36,36,41,37,11. With any injective second-field labeling (B) and any first-field offsets (A), the 41 distinct second glyphs following prefix 2 necessarily produce 41 distinct values (A(2)+B(b)). Thus at least 41 output classes are needed independently of numerical radix, secret first-field offsets, and any secret permutation of second-field labels. This theorem requires a shared whole-table additive code, distinct second-field labels, and an injective rank-to-symbol mapping, exactly the direct historical construction. Noninjective label collapse, page-specific or context-dependent reassignments, modular addition, or additional packing are outside the theorem and would need a new independently selected operation.

[Single-file reproduction](../sims/lp2_2012_midi_sumrank_table_gate_sft.cjs) checks the pinned signed MIDI byte SHA-256, both full decoded tracks, all original table sum-class counts and the exact shared-label bound. The actual original inputs and computation were executed via the GitHub connector JavaScript runtime; the separately committed Node reproducer has not been CI-executed. To repeat locally, supply the pinned original archive `song.mid` as its sole argument.

**Transfer decision:** the 2012 note-plus-time rank opcode is authentic as a historically reproduced participant solve, but the most direct LP2 pair-valued receiver has the wrong output cardinality. Retain the historical operation as prior art; no unknown LP2 plaintext or key. Do not add an arbitrary modulo, compression or row-specific codebook merely to fit the alphabet.

**Decision:** close the MIDI-*container-metadata* channel. No uninspected LP2 location/rune can be predicted from the existing metadata without inventing an extra selector. Reopen only if an independently authentic new 2012 attachment or contemporaneous instruction specifically names the timestamp, 7/2 meter, or a distinct MIDI meta convention and fixes a reversible original-LP2 consumer. This is a negative channel finding, not a universal exclusion of uses for the decoded chorus and 49-word list. No new LP2 plaintext, authentic key or destination was recovered.

## Source-defined candidate

The [original ink annotation](../resources/liber-primus/lp2-ink-annotations.json) contains **225 red runes** and **31 occurrences of the same 13-dot punctuation stencil** across the complete 58 physical LP2 pages, including the only black 13-dot stencil on physical page 7. These form **256 ordered events**, numerically equal to the **256 bytes** of the manuscript's [32-row × 8-column base-60 table](../resources/liber-primus/base60-grid.json) on pages 49–51. Their common size admits a complete one-to-one positional pairing or an 8×32 key schedule. An independent [Agent 30 countercheck](../communications/agent3/20261110T1615Z_agent30_red256-event-block-boundary.md) counts the 32 red-rune intervals delimited by the 31 stencils: **15 are empty, and only one contains seven runes**. Thus the marks do **not** naturally delimit 32 contiguous groups of seven red runes plus one marker; the 8×32 correspondence remains numerical and requires a separate source-justified ordering rule. A separate natural reading takes each *interval length* as one byte or base-60 digit: exactly **32 nonnegative lengths**, summing to 225 and with maximum **59**, within the original grid's 60-digit alphabet. The 32-character base-60 string is `D0G030B00EC09B0G0J0A08030x905070`, source-key bytes `0d00100003000b00000e0c00090b00100013000a00080003003b090005000700`. This offers a source-fixed **32-byte key candidate** with no inferred cipher mapping yet.

The 13-dot stencil is one visually consistent symbol class; the source's four 10-dot and one 23-dot punctuation marks are separate classes. Including only the *red* 13-dot glyphs would yield 255 events, so the source-verified black exception matters.

This count is **retrospective**, and the rule 'red runes plus every 13-dot glyph' was constructed after seeing both source inventories. It establishes a possible *format*, with no evidence yet that either original colour or punctuation was intended as key material. The red-rune count includes solved pages 56–57; excluding those pages changes the total. The 31 stencils are mostly punctuation boundaries around isolated red spans, so the number could arise from manuscript layout.

The [runnable experiment](../sims/red_256_event_key_inverse.cjs) resolves ordering unambiguously. Events sort by physical page, rune offset, and punctuation before a rune at the same offset. Every red rune contributes its canonical GP index 0–28 and every 13-dot stencil a separate marker value 29. It checks the exact rune against the original canonical [corpus](../resources/liber-primus/lp2-corpus.json), checks the black mark, and hashes the 256 input bytes to SHA-256 `50f640c1d53b3df48a1bb6cacfb0892db26d32f54bfbef9e7c65c312ba422cae`. This digest is a reproducibility fingerprint **of the extracted event list**, not a claimed digest in the manuscript.

### All-secret ciphertext-feedback and top-k capacity

The static-substitution exclusion extends to an extremely permissive **one-rune ciphertext-feedback rule**, with every secret coefficient independently rekeyed by (fragment, position mod8):

    D_i = (C_i + a_(g,h) C_(i-1) + b_(g,h) C_(i-2)) mod29
    D_i = sigma_(g,h)(P_i).

The GP29 permutation and coefficient values may be **arbitrary secret choices**, independently in all 224 fragment/phase states; the two ciphertext predecessors are reset to zero at the start of each source-defined fragment. Because each output permutation is bijective and feedback is causal, this model has an exact encoder and decoder for every fixed key. A universal all-key bound on any specified plaintext rune follows by exhaustively enumerating each state's 29 possible coefficients a, 29 possible coefficients b where permitted, and all 29 resulting register values D. Maximizing within each state and summing over the independently keyed states is a *sharp* exact capacity for the single-rune count. No key fitting, language scoring, grid-byte selection, or stochastic null is involved.

| Feedback taps | Secret per-state coefficients | Maximum copies of any fixed plaintext rune on original | GP-E ceiling |
| --- | --- | ---: | ---: |
| 0 | a=b=0 | **989 / 12,956** | 7.6335% |
| 1 | Any a in F29, b=0 | **1,298 / 12,956** | 10.0185% |
| 2 | Any a,b in F29 | **1,548 / 12,956** | 11.9481% |

## Original-source inversions

- **Transparent GP-EA:** on each physical page's first rune, pass the symbol through. Otherwise if the published rune repeats its predecessor, decode GP EA=28. For a nonzero GP difference, `P_i = (log_15((C_i−C_(i−1)) mod 29) + s K_i) mod 28`. Generator 15 is the manuscript-linked primitive root of F29, and the forward mapping is exact.

The 256 events were serialized chronologically or read as a transposed 8×32 table. ## Exact capacity bound for the 32-run marker-position key

The 32-run source key is a structured sequence of **225 red-rune events and 31 indistinguishable 13-dot delimiters**. Ignoring individual red glyph identities, there are exactly `C(256,31) = 8283675595268374292919471912522442632960` possible placements of 31 delimiters in 256 event slots. Therefore this **marker-position-only register has at most 132.60547 bits of combinatorial input choice**, even though its literal byte serialization occupies 256 bits and a SHA-256 digest also occupies 256 bits. The observed maximum red-run length 59 imposes a further restriction; exactly `8247228282470386923261247318860927231744` such bounded weak compositions of 225 into 32 parts exist, giving **132.59911 bits** of combinatorial choice under that extra condition. Under the explicit **uniform 31-delimiter placement** null conditioned on 256 total events, their ratio gives `P(max run ≤ 59) = 0.9956001038`, or approximately **99.56%**. Therefore the mere fact that all 32 run lengths fit base-60 single-digit values is **expected under this declared simple null**, providing no affirmative evidence for a base-60 encoding. This null does not model Cicada's editorial red-heading layout, so it is a bounded conditional calculation.

The independent [BigInt combinatorial reproducer](../sims/red_256_marker_capacity.cjs) computes both exact cardinalities via a binomial coefficient and dynamic programming over bounded compositions, and asserts their values against the canonical event source.

This bound is a mathematical fact about the input alphabet and event counts, **not an estimate of the historical key's entropy**. It does not constrain keys formed from the 225 actual *rune identities* or from independent secret material, and it leaves hypothetical 132-bit exhaustive search computationally impractical. It does prevent counting the direct delimiter-only 32-byte sequence as 256 independent bits of secret information.

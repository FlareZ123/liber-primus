## Original period-linked solver source, inspected as executable claims

A separately source-locked URL inventory in the same 2014–2016 exact-byte log found **1,069** source-context links to selected code/document hosts, **250 distinct URL strings**, in [successful CI 43609250218](https://github.com/FlareZ123/liber-primus/actions/runs/43609250218). It extends #881's May–August 2014 linked-operand recovery without retrying those links.

Two source-linked programs are immediately inspectable:

- **L262046, 15 January 2016:** [Be5haram/CICADA2K16/RuneSolver.py](https://github.com/Be5haram/CICADA2K16/blob/master/RuneSolver.py). The version that actually existed at the IRC date is [commit 4338b03, 14 January 2016](https://github.com/Be5haram/CICADA2K16/blob/4338b032c082dafcbe0c57f110b28cb5102d7fa5/RuneSolver.py), **26,004 bytes**, Git blob **c77a33e6e224db547c43dc74f9f4d7f18701928b**. It offers interactive additive stream/Vigenère, skip-and-stream, rune counting and raw GP29 transliteration, with user-selected reversals/prime-Fibonacci streams. The present **42,209-byte** file is a later [10 February 2016 revision](https://github.com/Be5haram/CICADA2K16/blob/7529449a8252d681604e81e3d3b52128ce01a0f2/RuneSolver.py), blob **ef2f76065a3ea25e21dbb3614b444fee77d5a73e**, introducing an adjustable **Alberti rotating-disk** option; **that option must not be backdated to the 15 January IRC link**. In both revisions most page variables are empty, some are original ciphertext and p57 is already solved. Neither version contains a key that deciphers original unknown LP2 pages.
- **L264768, 15 January 2016:** [resvolver/c1cada/repeatcrack.pl](https://github.com/resvolver/c1cada/blob/master/repeatcrack.pl). This script constructs orthographically normalized dictionary n-grams and nests 29-way key-letter loops to look for English word shapes. Its embedded runic examples are ciphertext and crib guesses. No source-selected key or complete original rune-to-plaintext example appears.

**Concrete period-tool page-index defect, corrected for Unicode:** In **both** dated RuneSolver.py versions, variables Page0 and Page54 hold **identical 232-rune** ciphertext after correctly normalizing historical J rune **ᛂ** to canonical corpus J rune **ᛄ**. Both spellings transliterate to the same GP29 **J** at index 11. The historical text has **nine** such J glyphs; an initial parser that accepted only the canonical glyph falsely reported **223 runes and nine deletions**. Those false deletion and Levenshtein claims are **withdrawn**. After adding the explicit J alias, **every one of the 232 historical source runes matches canonical LP2 p54 exactly**; the historical p54 transcription is complete and correct. Original LP2 p0 remains a different **262-rune** ciphertext. Therefore the genuine historical defect is a **mislabelled Page0 selector** pointing to the full p54 ciphertext. Any reported output from that Page0 menu cannot count as an original-p0 decrypt without rerunning from native p0. This Unicode-level correction matters for period GP29 transcription comparisons.

Other period-linked files have separable roles: [tevaum/lpt/data/liberprimus.js](https://github.com/tevaum/lpt/blob/master/data/liberprimus.js) (L302306, 23 February 2016) stores raw GP29 transcriptions, and the historical [rtkd/idkfa assets/docs/liber-primus-translation.txt](https://github.com/rtkd/idkfa/blob/master/assets/docs/liber-primus-translation.txt) (L283806, 27 January 2016) is not accessible at that exact present-day path. The IRC link alone does not establish that a file called “translation” contains recovered plaintext. The dated [AlexBoyle/CicadaDecoder source reference](https://github.com/AlexBoyle/CicadaDecoder/blob/master/src/Decrypter/Main.java) (L327318, 10 April 2016) also returns 404 today. Retrieval of such missing original code is a possible historical follow-up **only if it yields a frozen decoder and a checkable unknown-page prediction**.

This source acquisition is not authorial evidence for the 2016 workbench's freely configurable operations. Running its full menu on the original book without an independently selected input would reproduce old unconstrained key searches. The direct GP29 punctuation-sensitive one-step Alberti default was additionally read against original p0 and p32; its two additive directions remain uniform and unreadable, a limited exploratory screen rather than a broad cipher exclusion.

## Independent 2015 prime-difference experiment with original-cipher phase

The same exact original 2015–16 Freenode source contains a more precise, bounded original-input experiment at **4 February 2015, L89874 and L89887–905**. A participant proposed shifting original pp0–2's 729 GP29 runes by consecutive primes, imagining F as the first preceding rune, and then differencing adjacent shifted runes. Another message explicitly reports **40 adjacent derived equalities**. Reconstructing the source-specified F→prime2, first-real-rune→prime3, subtractive direction yields exactly **40/728** derived same-symbol adjacencies, versus only **4/728** in source ciphertext. This source-conditioned transform **can be inverted on every original rune**, but its GP29 IoC is **0.03450459**, not English-like plaintext.

The original phase uniquely maximizes this metric among **729 source-preserving cyclic alignments** (with both signs and first-prime2/3 allowed, **2/729** alignments match); its eight predeclared original visual-chapter holdouts lack any comparable phase preference and remain near-uniform. This is an exact 2015 historical numerical reconstruction, **not an authenticated unknown-page decoder, a discovery-adjusted p-value or a universal stream**.

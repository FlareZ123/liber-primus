# Original p49–51 repeated-token partition versus the 95-rune PARABLE

**Research decision (15 November 2026):** The printed 256-cell numeric table has exactly **161 distinct literal numeral tokens** and **95 later occurrences** when the cells are visited in the printed row-major order. The last three manuscript pages have **76 unknown p55**, **85 solved p56**, and **95 clear p57** runes. The numerical agreement `161=76+85` and `95=95` permits a specific, source-measurable *first occurrence / repeated token* framing that is different from the previously investigated direct 256-position p55–57 framing. **It does not select a decryption.** Its simplest reversible lookup consumer is decisively impossible on the original known PARABLE runes.

## Actual source, precise model, competing explanation

The original LP2 physical pp49–51 (JPEG scans 66–68) print a 32×8 grid of two-character numeral tokens. Use its **literal source token strings**, not presumed base60 bytes, and visit cells in displayed row-major order. For each string, its **first** occurrence joins register A; every **later** occurrence joins register B. Register A contains 161 positions; register B contains 95. Independently, physical LP2 p55+p56 contains 76+85=161 GP29 runes, and original clear LP2 p57 contains 95 runes including PARABLE. The 2014 printing contains no explicit instruction to pair these lists, no source-authenticated map, and no information identifying first/duplicate-token status as ciphertext classes. This is therefore only a bounded hypothetical consumer.

The **candidate lossless stationary consumer** maps each literal two-character numeral token to one GP29 plaintext rune through an arbitrary, completely secret but **fixed** token-to-rune function `T(token)`; its register-B outputs are required, in source order, to equal the **95 actual p57 clear runes**. This grants all codebook entries for free. The only invariant is: repeated instances of the **same printed token** must produce identical known outputs. The source's hypothetical register A could then encode p55+p56 through the same dictionary, but the authentic p57 output must fit first.

## Key-independent original contradiction

The original printed 256 tokens contain **161** distinct strings and **95** repeat occurrences. Among those 95 repeat positions, **69** token classes occur, with repeated-class sizes: 49 classes of one, 14 classes of two, and six classes of three. Pairing them position-for-position with original clear p57 gives **19 token classes** with contradictory required rune outputs. Even after choosing the best arbitrary GP29 output for every one of the 69 classes, the minimum number of known p57 rune positions that would have to change is **23 of 95**. Thus **no static numeral-token-to-rune codebook** can encode authentic p57 under this source order, regardless of key size, secret alphabet permutation, numeric base, or treatment of the first 161 table occurrences.

A positive control constructs an arbitrary fixed secret token-to-GP29 mapping and generates 95 planted outputs at precisely those repeat positions. The same exhaustive minimum-correction test returns **zero contradictions** on that plant. It therefore tests the specific claimed invertibility condition rather than a language score.

The exact match of the two length partitions is independently weak evidence: if 256 byte tokens were drawn independently and uniformly from 256 possible byte values, an exact occupancy dynamic program gives `E[unique]=162.0071027478`, standard deviation `4.9904497338`, and **P(exactly 161 unique)=0.07822643713**. The purported `95` repeat-count match is therefore ordinary under a simple random-byte alternative. This probability applies to the *conditional 256-byte interpretation* and must not be used as an author-provenance claim for the literal two-character numeral alphabet.

## What remains unknown

The contradiction rejects this **one** same-token stationary lookup and exact original order. A context-dependent code, additional state, a different original output assignment, or an independently prescribed traversal is unconstrained. No unknown page was decrypted, no original key/operation was found, and no deep-web address follows. The two register lengths should **not** prompt searches over unselected ciphers, rotations, or sample-fit exceptions. The missing prerequisite is an independently visible instruction defining how table-token recurrence is consumed and checked against known original plaintext.

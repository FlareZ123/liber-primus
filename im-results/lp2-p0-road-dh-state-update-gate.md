# P0 THE ROAD DH state-update gate

**Agent3, 19 November 2026. Classification: bounded negative for a natural H/cube state update. The upstream p0 receiver and DH state remain conditional/source-linked evidence. No new plaintext, key stream, or global LP2 inverse is claimed.**

## Frozen input

The independently selected conditional p0 receiver places `THE ROAD` at zero-based offsets103..108. Original ciphertext values there are

```text
[8,12,16,8,25,27]
```

and native-GP `THE ROAD` is

```text
[2,18,4,3,24,23].
```

The exact additive key required under `C-P mod29` is therefore

```text
THE  = [6,23]
ROAD = [12,5,1,4].
```

The first pair is already the authenticated p28 DH pair `[a,p]=[6,23]`. Independently, the one-based p50 cells selected by ROAD are105..108 and their byte residues modulo29 are

```text
[a,g,K,b] = [6,5,2,15].
```

The missing operation is a source-selected update from that four-value state to ROAD's key.

## Existing manuscript operations do not supply the update

The two strongest value-changing operations already selected by the p28 route are:

- `H(x,y)=(x-y,x+y) mod29`, with the exact inverse fixed by determinant2;
- the cube permutation `x -> x^3 mod29`, with inverse `x -> x^19 mod29`.

The SFT closes the finite orbit generated by these operations when H is applied as a whole-layer transform under all three natural perfect matchings of four ray entries:

- adjacent pairs `(0,1)(2,3)`;
- nested pairs `(0,3)(1,2)`;
- alternating pairs `(0,2)(1,3)`.

Both H and H inverse are admitted for every matching, together with cube and inverse cube. From the forward state `[6,5,2,15]`, the complete orbit has **2,688 states**. The reversed ray has the same 2,688-state orbit. **Neither contains `[12,5,1,4]`.**

Thus the already selected reversible p28 operations do not produce the ROAD key under a low-description whole-ray update.

## How free fitting can manufacture the target

As an explicit overfitting control, the SFT then allows H or H inverse on any single one of the six coordinate pairs while leaving the other coordinates untouched, plus whole-vector cube/inverse-cube.

That much freer grammar eventually reaches the target, but the shortest path has depth **6** and changes the chosen coordinate pair/inverse at every step:

```text
H02
Hinv13
H01
Hinv12
H01
Hinv23
```

This path is a fitted construction, not a puzzle instruction. No original clue chooses those six pair operations.

## Postselected DH identities

After the target is known, its values can be rewritten compactly in the DH23 field:

```text
[12,5,1,4] = [K^-1, g, 1, a^-1] mod23.
```

The full six-rune phrase key is therefore

```text
[a, p, K^-1, g, 1, a^-1].
```

This is worth preserving because every ROAD key value is a standard DH-derived quantity. It is **not** an authenticated generator: the field-term sequence was selected after seeing the required key, and no source clue currently chooses that ordering or explains how it should continue to another untouched target.

A concurrent p0 READ OUT result strengthens the local DH context: applying the already selected H shell transform to the prospectively selected p0 offsets80..102 exposes all seven DH23 state values immediately before THE ROAD. That makes a DH consumer more plausible, while leaving the consumer itself unresolved.

## Decision

Retain:

- the exact THE key `[a,p]`;
- the ROAD p50 ray `[a,g,K,b]`;
- the compact postselected ROAD identity `[K^-1,g,1,a^-1]`;
- the concurrent p0 H-shell complete-state echo.

Reject as currently motivated updates:

- any composition of the existing whole-ray H/cube operations;
- the six-step changing-coordinate H fit;
- promotion of the compact DH identity into a key generator without an independent rule or held-out prediction.

The next useful advance must specify the DH-state consumer before reading another target, or predict an untouched p0 value under one frozen rule.

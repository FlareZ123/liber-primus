# January–May 2014 epoch-seeded byte generators against two original 256-byte sources

**13 November 2026, Agent31. Scope: finite, source-first negative. No unknown Liber Primus plaintext, authenticated secret or author-selected cipher was recovered.**

## Why this might have led to a key

Two historical artifacts contain exactly 256 high-entropy byte values: the January 2014 second-onion growing string and the LP2 printed 32×8 grid at physical pages 49–51. A plausible economy for their creator would be to publish a byte stream generated by a standard 2014-era PRNG from a contemporary timestamp. If an entire published stream could be reproduced from a timestamp seed, the inferred generator could produce additional secret outputs for a hypothesized LP2 decipherment. This is conditional on the creator intentionally using that generator and the published text being a direct stream, neither of which is established. Previous grid-specific PHP-MT seed scans already exist; the test below is explicitly limited to other direct historical generator/byte conventions and a smaller date domain.

Source bytes are pinned by the repository:
- The original manuscript [256-cell grid](../resources/liber-primus/base60-grid.json) is interpreted in previously documented source-row-major base60 byte order, with SHA-256 \`3b9b07d9a26e6d55c432d94d2661fdff3c2b348daed06821f2bdb23184a4b290\`. First six bytes \`cb e7 a7 ba 61 ed\`.
- The 2014 second-onion 256-byte growing string is preserved in [the historical timing corpus](../resources/cicada2014-onion2-timing.json), source SHA-256 \`05acf0d8e2ba7d851e2b4bbc32b85e461a1bd41576a50504487f33d4c1522c56\`. First six bytes \`63 42 92 ba 49 fe\`.

The source does **not** instruct a player to use a Unix timestamp, seed a generator, or transfer a continuous byte pad to LP2. This original-byte test rules on a sharply specified hypothesis rather than interpreting coincidental numeric alignments as keys.

## Complete finite test

Freeze the 10,713,600 possible **whole Unix seconds** in [2014-01-01 00:00:00 UTC, 2014-05-05 00:00:00 UTC), encoded as an unsigned 32-bit integer. For every candidate second and **both published byte sources**, test six consecutive source-order emitted bytes under:

1. Standard MT19937 seeded with that 32-bit second, each 32-bit output reduced to the top eight bits or lowest eight bits.
2. Java \`java.util.Random\` seeded with that second, with either \`nextInt(256)\` (31-bit-high byte) or the contiguous little-endian bytes of \`nextBytes()\` (four from each 32-bit draw).
3. The POSIX-style \`srand48\`/ \`drand48\` 48-bit linear congruential generator, each value mapped through \`floor(256*x)\`.
4. Microsoft Visual C++ legacy 15-bit \`rand()\` initialized with that second, taking either the high eight or low eight bits.

This gives **14 source/projection combinations per seed** across the two source registers. Each candidate is rejected immediately if its first output byte differs; a six-byte exact match is required to record any hit. A genuine entire-stream generator match necessarily matches those first six bytes, so the prefix test is an exact necessary-condition sieve without scoring language, guessing a phase, or decrypting any LP2 rune.

The self-contained [C++17 reproducer](../sims/epoch_original_sources_2014.cpp) includes independent published MT19937 and Java first-output vectors and an MSVC first-output check. The actual program was compiled with an optimizing C++17 compiler and executed against the full frozen range. **Every one of the 14 categories returned 0 six-byte matches.** Exact stdout contains \`SEEDS 1388534400..1399248000 exclusive: 10713600\` followed by \`HITCOUNT 0 0\` through \`HITCOUNT 13 0\`.

## Decision

No direct 2014 Unix-second seed in the specified January-through-early-May window generates **either** source's published first six bytes under these standard conversions. A complete 256-byte source identity in this family is consequently impossible. This does not disprove a source-generated byte stream under a different seed epoch, key, custom PRNG, byte-skip, time base, derivation, nonstandard byte projection or later encryption. Searching those freely would have no independent historical selector.

The earlier specific grid PHP-MT all-32-bit-seed search and onion-2 timing-key LP2 inversions are separate negatives and were not repeated. The practical next requirement remains an actual signed or image-derived instruction that identifies a generator or decoder. This result supplies no evidence for treating either source as an LP2 key.

# Exact seed-free MT19937 GP28 gates: 32-bit modulo and historical Python 2.7 float selection

**Agent26, 13 November; expanded by Agent3, 15 November 2026. Classification:** original-input exact **all-initial-state impossibility** for two distinct no-repeat GP29 radix28 generator families: one using 32-bit MT19937 output modulo28 and a second using historically valid **CPython 2.7 `randrange(28)`, i.e. `int(random()*28)`** with paired 32-bit MT outputs making a 53-bit floating-point sample. Both fail exact GF(2) constraints on unchanged ciphertext under two original rune rank conventions and both literal per-doublet consumption policies, while independent full-length planted streams remain consistent. This is a conditional rejection of specified direct-output encoders, **without unknown LP2 plaintext, key or authorial cipher identification**.

## Causal route and precise hypothesis

The actual unsolved physical LP2 pages 0–55 (excluding the rune-free p50) contain **12,956 GP29 runes** and only **86 equal adjacent pairs** when the pages are concatenated in source order. A human coder may avoid repeated output glyphs by allowing exactly 28 legal next runes, indexed from 0 through 27, and may choose MT19937 as a period-available (1998) generator. The old Python-based Cicada 2013 material and already documented original-source byte ciphers make a pseudorandom generator technologically plausible, although there is **no recovered source instruction to use MT19937 here**.

The proposed model is deliberately narrow and fully specified:

1. Preserve the first original rune as an explicit seed context. For every subsequent unequal rune pair, invert the predecessor-excluding 28-way alphabet by either **ascending skipped-GP** rank `d_i=C_i-[C_i>C_(i-1)]` or **cyclic** rank `d_i=((C_i-C_(i-1)) mod29)-1`.
2. At each of the **86** immediate repeat positions, treat the repeated glyph as an explicit exceptional symbol, preserve the previous ciphertext rune and test **two fixed key-consumption contracts**: the repeat consumes **zero** random draws or consumes **exactly one** random draw whose output is hidden. Neither contract changes the original repeat sites.
3. For every ordinary unequal successor, take exactly one 32-bit **tempered MT19937** output from the source-consumption clock `y_i` and set the selected output rank `d_i=y_i%28`. No rejection draws, independent page reset, extra skips, secret output permutation, per-word rekey, XOR mask or byte/field transform is permitted.

These rules give **12,869 ordinary rank28 digits** with all exception positions fixed from the untouched source. An exhaustive seed search would be hopeless; modulo28 instead leaks two *exact output bits* because `28%4=0`:

`(y_i % 28) & 3 == y_i & 3 == d_i & 3.`

The MT19937 twist and tempering are **GF(2)-linear** in the complete 624×32-bit start state. Thus every observed rank supplies two equations in at most **19,968 unknown initial state bits**. A contradictory equation rejects **every possible initial MT state**, a result stronger than checking any finite key/seed dictionary.

## Additional historical Python 2.7 float53 direct-selection gate (Agent3, 15 November 2026)

**Independent source reason to test this distinct route.** The literal [Python 2.7 `Lib/random.py` implementation](https://github.com/certik/python-2.7/blob/master/Lib/random.py) uses `int(self.random()*istart)` for single-argument `randrange(istart)` when `0 < istart < 2^53`. Its [`Modules/_randommodule.c`](https://github.com/certik/python-2.7/blob/master/Modules/_randommodule.c) defines `random()` by combining **two consecutive tempered MT19937 32-bit words** `a=genrand_int32()>>5` and `b=genrand_int32()>>6` into the exactly representable 53-bit numerator `U=(a<<26)|b`, then returning `U/2^53`. Thus the intended real-number rule is `d=floor(28U/2^53)`, implemented by actual Python 2.7 as `d=int(float(U/2^53)*28.0)`, rather than the preceding C++ `uint32%28` family. IEEE-754 rounding may shift a rare 28-bin endpoint, but cannot cross a **7/14/21** group boundary: the closest numerator step is `28/2^53`, exceeding half the maximum below-28 binary64 ULP `2^-49=16/2^53`. Standard `randrange(28)` uses the float method, whereas `_randbelow`'s getrandbits/rejection path is reserved for much larger arguments; no historical Cicada source is yet known to specify this candidate generator for unknown LP2.

**Exact bit disclosure, no guessed MT seed:** for every `0 ≤ U < 2^53`, `d=floor(28U/2^53)` implies `floor(d/7)=floor(4U/2^53)`. So each original nonrepeat rank in `0..27` discloses exactly the **two most significant bits of the first 32-bit MT output**: bit 30 and bit 31 are the binary digits of `floor(d/7)`. The remaining 51 bits of `U`, including all information from the second MT word, remain unobserved. The SFT asserts all exact integer-bin endpoints and separately checks the historically correct binary64 multiply within **512 numerator values on either side of every 7/14/21 boundary**; the preceding ULP inequality proves that the two revealed bits remain exact even for potentially rounded individual rank bins. A source-position uses **two MT draws per rank**, and any one repeated rune either consumes zero 53-bit `random()` values or one full, unobserved 53-bit value. The same two original rank conventions, complete 12,956-rune original sequence, 86 original doublet exceptions, and 624×32 arbitrary symbolic initial state are retained without fitting a numeric key.

Under exact symbolic MT state evolution and tempered high-output-bit GF(2) equations, the untouched 12,869 original rank digits produce:

## Decision and limits

This **eliminates direct MT19937 `uint32 % 28` output as the entire 28-choice source register** under either literal zero- or one-draw repeat policy, even allowing every mathematically possible 624-word initial generator state and granting all 86 repeated ciphertext runes as transparent exceptional events. It is an exact algebraic exclusion within the declared encipherment contract, independent of the original language and of MT seed size or initialization procedure.

The complementary exact original-input 53-bit **Python 2.7 `randrange(28)` float** branch was tested and rejected in the immediately preceding section. The combined gates **do not exclude** `getrandbits(5)` with rejection, discarded random draws not visible in the ciphertext, unknown further consumed draws, a ciphertext-dependent keystream clock, a source-independent starting word-index/phase or unknown preamble, noncanonical GP output permutations, independently reset generator states, or another cipher layer. None of those has a source-selected full original-cipher operation here. A subsequent promising route needs *source-authenticated key/state and consumption rules* rather than new seed brute force on this mathematically impossible class. No unknown original-LP2 rune has been decrypted.

This is complementary to [the earlier seeded/skip-aware MT attack](grid-mt-keyskip-inversion.md), which tried concrete original grid-column seed candidates and key-skips on short original prefixes. Unlike that finite seed search, this test simultaneously rules out **every possible start state** for its exact 28-rank output family.

# Seven-rune p55/p56 ↔ p27 echo as an OpenPuff password on the original Cicada audio files

**Agent 37, 15 November 2026. Original-source direct-decryption test; bounded negative.** The exact eight-ASCII-character `DJUBEIAE` key was executed through the original OpenPuff 4.00 Windows application against **two different original Cicada MP3 carriers**. The original known 2014 hidden-message positive was first recovered exactly. Both new original-carrier operations terminated in OpenPuff's own **corrupted-stream** outcome and produced no extracted file. There is no recovered LP2 unknown plaintext, key mechanism, or destination. This closes a different receiver family from the already completed native JPEG wing/moth tests.

## Exact original player path and weakest premise

The original LP2 p55 ends with the six physical GP29 runes `D J U – B E I` (source scan `72.jpg`, final physical rune offsets 70–75). Original physical p27 (`44.jpg`) contains those six identical symbols at offsets 28–33, followed by `AE F`. Solved p56 opens on the same `AE`. The combined **seven-rune** exact seam is `D J U B E I AE`, transliterated to **`DJUBEIAE` (eight ASCII characters)**, satisfying OpenPuff's documented historical 8-character minimum without truncation or extra guesses. P27 visibly has an insect wing, and p55 has a moth.

Two surviving media operands are genuinely historical. The original 2013 `761.MP3` is titled **The Instar Emergence** in its ID3 tags, is associated with the CicadaOS insect/emergence puzzle, and already exposes the later solved p57 PARABLE in its metadata. The original 2014 `interconnected.mp3` actually carries an OpenPuff 4.00 message under the independent historical password `33011033`. Thus the cross-round key on these original media is a concrete, new plaintext-producing hypothesis. The **unproved premise** is whether the author intended a 2014 OpenPuff receiver for the **2013** file or planted a second payload in the **2014** carrier; no signed message says either.

The exact original seven-rune link, all physical indices, and prior completed single-/paired-JPEG key probes are independently recorded in [the p55/p27 seven-rune source study](lp2-p55-p27-seam-native-stego-and-backward-wrap-gate.md). This test moves to the separate earlier **MP3** media, not another original JPEG or an OpenPuff password variant.

Use the **unmodified OpenPuff.exe v4.00 and libObfuscate.dll** pinned to historical Git blobs, execute 32-bit Python Windows GUI automation, choose native `Mp3 (Audio)` and **`1/2 (50%) - Maximum`**, put only `DJUBEIAE` in the primary A-password field, leave B/C blank, and add **one original carrier** at a time. There is no file re-encoding, stream offset, source byte mutation, key-case variant, secret choice of another tool, or guessed companion file.

## Research decision

The **MP3 OpenPuff** route under the uniquely short p55/p56–p27 eight-character key fails on both historical carriers at the authentic 2014 payload's working Maximum setting. Do not infer an LP2 cipher or repeat these two key/media combinations. Further bit-level/decoder searches require another independent authored selector, because the key's source-repeat rarity is already recognized but does not specify a medium, decoding format or even whether the echo is intentional. An actual recovered message, externally selected cipher mechanism or plaintext island remains required to change the solution frontier.

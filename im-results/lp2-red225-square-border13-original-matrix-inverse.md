## Candidate original clue, and strongest alternative

The source-visible ink inventory has **225 red runes**, exactly \(15^2\). It also has **31 physical thirteen-dot marks**, including the black p7 occurrence: \(225+31=256=16^2\), and \(31=16^2-15^2\). Therefore an *unprinted* 16×16 square can contain the 225 red-rune values as a row-major 15×15 upper-left field, with the final row/column occupied by 31 identical thirteen-dot cells. Independently, physical p50's printed 32×8 table contains exactly 256 two-character numerals; its source-derived byte interpretation is a 16×16 array when pairs of rows are joined.

A complete 15×15 numerical key is also available by reading the red runes in original page/offset order. Tree-associated ciphertext p32 has 121 runes (one + eight 15-symbol blocks) and p55 has 76 (one + five blocks). This suggests two finite direct matrix inverses if one rune is treated as a header/trailer. The original manuscript gives **no matrix multiplication opcode, modulus, 16×16 reflow, upper-left placement, or header rule**. These are *candidate* source-shaped constructions, with a rival explanation of postselected counts and encrypted text with different mechanisms. In particular, a 16×16 square with a 15×15 upper-left field does not create a symmetric concentric ring: the 31-cell complement is one final row plus one final column.

## Frozen original inverse

The [single dependency-free Windows-compatible CommonJS source test](../sims/lp2_red225_15square_16border_source_hill_sft.cjs) uses exact original source-file contents, page order and red-span offsets. No output-dependent ordering, starting phase, key search, word scoring or additional layer is fitted.

1. **16×16 numerical test, GF(257):** each upper-left key entry is the genuine GP prime weight of the matching red rune in published order; the remaining 31 entries are the printed thirteen-dot value 13. Treat the base60 source table bytes in printed order as a 16×16 ciphertext matrix and left-multiply by the inverse source key over the prime field 257. This inverse exists and the exact key determinant is **44 mod257**. The 256 original inverse residues include only **31/256** GP29-range values, **103/256** conventional ASCII printables (including HT/LF/CR), and have a longest contiguous printable graphic run of **7**. The first 32 residues are reproduced by the SFT. Exact reencryption recovers all 256 original bytes. A separately planted coherent 256-value ASCII text re-inverts **256/256**, so the decoder itself is functional.
2. **15×15 tree-page test, GF(29):** use the 225 original red rune indices in natural row-major order as an entire Hill key. This is invertible, with determinant **8 mod29**. The source's actual GP prime weights reduced mod29 form a second, independently chart-defined 15×15 key with determinant **16 mod29**. Without adjusting the source key, apply both inverse matrices to the full 75/120 positions of p55/p32 after reserving either the first or last rune. All eight complete original readouts are nonlinguistic under the source's GP transliteration, and IoCs lie in **0.0322–0.0389**. Exact planted native-GP controls round-trip under both matrices. The SFT prints each frozen first-55-rune transliteration and IoC so apparent short words can be assessed in their full context.

This is a **direct-consumer exclusion**, not a proof that 225+31 lacks hidden purpose. The 31-event inventory itself is not uniquely author-specified: contemporary artifact classes A/B/C can each supply 256 events by different selections (see [integrated original inversion challenge](../workplace/integrated-original-inversion-challenge.md) and [historical original-class audit #1282](https://github.com/FlareZ123/liber-primus/issues/1282)). The field and border placement here are selected by a mathematical convenience, not image geometry.

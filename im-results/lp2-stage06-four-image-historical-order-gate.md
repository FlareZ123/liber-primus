# Original 2014 Stage06 four-image sequence: exact LP1 mapping and LP2 operation gate

**Agent9, 12 November 2026. Decision:** The original pre-LP2 Stage06 four-JPEG sequence is **byte-identical to already solved LP1 pages 06, 07, 09, 08**, in that *source extraction order*. The last two are each stored **with their entire JPEG byte stream reversed** in the original concatenated source. Three original same-length, nontext OutGuess extracts additionally have **identical initial byte runs** and fail a source-fixed two-/three-way XOR readout. These give an exact historical mapping and bounded extract/share result, but **no original LP2 plaintext, source-selected runic key, or complete ciphertext inverse**. It does not justify applying the same byte operation to GP29 runes.

## Independently selected original source

The preserved original-stage file directory is [krisyotam/cicada3301, pinned commit 76d3ee8](https://github.com/krisyotam/cicada3301/tree/76d3ee8c762f60025822c8c05edbf31351636469/puzzles/2014/assets/stage06). Its [README](https://github.com/krisyotam/cicada3301/blob/76d3ee8c762f60025822c8c05edbf31351636469/puzzles/2014/assets/stage06/README.md) documents conversion of original onion hex to gzip, then extraction of one **3,010,703-byte** concatenated binary comprising four JPEGs in this order. It specifies source start offsets **0, 823807, 1647321, 2371898** with respective sizes **823807, 823514, 724577, 638805**, and literal byte reversal of fragments three and four. The first two images can be read directly.

The same pinned archive preserves [the fourth image's 140-byte OutGuess text](https://github.com/krisyotam/cicada3301/blob/76d3ee8c762f60025822c8c05edbf31351636469/puzzles/2014/assets/stage06/index.4.outguess), introducing a two-character block rearrangement to a contemporary onion address and the phrase **“TO BELIEVE TRUTH IS TO DESTROY POSSIBILITY.”** The deciphered string is [index.4.decrypted](https://github.com/krisyotam/cicada3301/blob/76d3ee8c762f60025822c8c05edbf31351636469/puzzles/2014/assets/stage06/index.4.decrypted). The original printed runes in this stage are the already documented **A KOAN** and **DO FOUR UNREASONABLE THINGS EACH DAY**, not a recovered LP2-unknown quotation.

## Source-exact three 58,152-byte OutGuess extractions: shared-prefix and XOR gate

The preserved Stage06 directory also contains `index.1.outguess`, `index.2.outguess` and `index.3.outguess`, **58,152 bytes each**, independently distinct archival Git blobs (`29d8fe5c4b6f2b245e367077dc6c752204707c7e`, `fc8bc6ff96e8c1078d9a231e89e18d56c708708f`, `d7844fa0bbedfcf4e9862a1d43f565717789cb86`). The known 2014 Cicada puzzle later uses separately obtained byte shares, so these three extracts have a specific prior-authored reason to test one simple XOR composition. However the original Stage06 README does **not** direct a player to XOR them, and the fourth image instead contains a readable 140-byte OutGuess text.

The [standalone source-exact CommonJS test](../sims/lp2_stage06_three_outguess_xor_sft.cjs), executed in [manual original-source CI 43283077346](https://github.com/FlareZ123/liber-primus/actions/runs/43283077346), downloads and verifies all three immutable Git blob SHA-1s, compares original bytes, and tests each single stream, each pairwise XOR, and the three-way XOR without any fitted offset, guessed stage or content score. A planted three-share XOR of source-independent random bytes recovers the exact known sentence.

**The common lengths are misleading:** all three original extracts share exactly **1,571 initial bytes**, and extracts 1–2 share **7,707 consecutive initial bytes**. Pairwise same-position equality is **9,306 / 58,152 = 16.00%** for extracts 1–2 and **2,534 / 58,152 = 4.36%** and **2,580 / 58,152 = 4.44%** for the other two pairings. All three raw extractions start with the identical 48-byte hex prefix `c0a128e346d23572fe62822e50f70d8aed61d93bc607ca31e7c6f64ed9d3c20fcf41c78c1bdc42eb9daebf9de4ccc9d1`. The shared template is compatible with an OutGuess extractor returning common cover-dependent prefix rather than three independent author-chosen pads. The fact of identical prefix alone does not prove there are no embedded bits later.

All three inputs have byte entropy **7.9968–7.9972 bits/byte**; the two-/three-way XOR candidates have no printable ASCII run of at least **16** characters, no tested obvious file header (JPEG, PNG, gzip, bzip2, ZIP, PDF or PGP armor), and no readable plaintext. Their exact original XOR SHA-256s are **977b778df8f28ddf7844513cddcc8d2f169efeac7055d72752d399e9e8224235**, **751952334d150ec91f22a468e8e54321f83686ee6197c3ee0502a57346bde3d1**, **88f5ec4f34e38ace9dd44dde2c8e2670553d63975f39bcf84fe21a6c77900adb**, and three-way **5fda2f44ec28cd71df4edf4d93c212b578ab5e1aa0845beb4034c3fbd4b96cb3**. Pairwise XOR begins with all zeroes because of the common prefix; the three-way XOR retains the shared nontext prefix. These observations reject the **literal raw two-/three-way XOR producing an immediately readable text or common file**, not all arbitrary combinations. A non-XOR codec or an additional missing key would require an independently authored instruction; it is unsupported to reclassify arbitrary high-entropy residual as manuscript plaintext.

## Full original 12,956-rune GP29 inverse from the three preserved Stage06 binary streams

The **source-first, zero-offset** historical-key hypothesis has now also been attempted directly against **all 56 original unsolved pages**, rather than stopping at ASCII/XOR file signatures. Three original 58,152-byte OutGuess streams and their three pairwise and one three-way XOR combination form seven explicit byte keys. The source-preserving codec maps byte `k_i` to `k_i mod 29`, consumes **one original key byte per ciphertext rune** across the original complete-book stream, and applies one of four minimal common GP29 inverses: `P_i = C_i ± k_i` or `P_i = C_i − C_(i−1) ± k_i`, all mod29. The feedback clock is continuous across original page boundaries with `C_(−1)=0` for the very first rune; neither key offset nor per-page phase is tuned. These are **candidate operations**, not historically authenticated creator instructions.

The [standalone original-source inverse](../sims/lp2_stage06_original_outguess_fullbook_pad_sft.cjs) was run successfully in [manual CI run 43286594065](https://github.com/FlareZ123/liber-primus/actions/runs/43286594065). It checks original Git blob identities, original corpus 12,956-rune count and exact 95/95 encoding/decoding recovery on the solved p57 plaintext for **all 28 combinations**. Every resulting unknown-book output stays near random GP29 frequency. Original ciphertext full-book IoC is **0.0344783979**; the highest full-book post-inverse IoC is **0.0347674503** (pairwise original 1⊕2 key under previous-ciphertext feedback, subtractive sign). **No page in any of the 28 trials has rune-index IoC ≥0.05**; the greatest page-level value observed across trials is **0.04385965**. The maximal-IoC output begins `SOEIXOPHTHSJNGOPYNAMRJJIGOEWNEIWLWMIAJNHTIRNGGNNGESRNGOEALOE` in GP transliteration, which is no authored sentence. Thus none yields a recognizable contiguous original plaintext or a decoded section under the source-frozen operations.

**Decision:** Retire Stage06 OutGuess `byte mod29` under direct continuous GP29 additive pad and the simple previous-ciphertext-feedback equivalent, including source-native 2-/3-stream XOR. This is a bounded 28-case negative with a strict planted original-p57 control. It cannot exclude an independently instructed extraction window, per-page key clock, literal-F skipping, other symbol encodings or a different original cipher; these require a new **source-visible selection rule**, since searching extra offsets/signs/frames is not itself a solve path.

## Does this supply an original LP2 decoder?

The source itself supplies three precise operations: parse a gzip-wrapped JPEG concatenation, reverse the raw bytes of images three and four, and solve an independent two-character-text rearrangement from the fourth image's OutGuess message. These operations acted on specifically marked **JPEG and ASCII payloads**, with their own recognized magic bytes and an immediately checkable onion destination. The four images are earlier LP1 text, already solved and available in the original 75-image archive. There is **no instruction in this original source to apply one of these operations to LP2 GP29 ciphertext, select a runic alphabet transform, or set a cipher-state clock**.

A potentially helpful visible connection already exists: the p09 LP1 insect appears horizontally reflected in unknown LP2 p2, but it is also reused in LP1 pp13 and16, and the [original full p2 literal reflection gate](lp2-p2-literal-rune-reflection-gate.md) and [original art/cipher-transfer gate](lp1-lp2-illustration-reuse-and-cipher-transfer-gate.md) rejected direct reflection and source-native LP1 inverse variants. The historical Stage06 ordering makes p09 a *contemporary player-visible image* and explains its earlier authorship; it **does not select p09's cipher rule as LP2 p2's inverse** or restore English under already tested operations. A new source selector, not a rearranged source-image manifest, is the necessary missing input.

**Decision for #636:** Retire Stage06's raw four-JPEG order/reversal and fourth-OutGuess-text rearrangement as *direct complete-LP2 decoder sources*. Keep the exact mapping for historical reconstruction and cross-release artwork comparison. Only reopen if a contemporaneous authenticated document ties a specific Stage06 operation/figure to a definite LP2 page and complete reversible runic codec with an untouched-passage prediction. The three non-text Stage06 OutGuess binary streams now have a bounded original-source XOR result above; a further key, stage or decoder needs a distinct authored clue. The unchanged physical LP2 ciphertext remains unsolved.

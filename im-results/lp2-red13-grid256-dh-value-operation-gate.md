# Red/13-dot 256-event tape × p50 × DH value-operation gate

**Agent8, 18 November 2026. Director #1652. Classification: source-binding negative; combined-register hypothesis retired. No unknown plaintext, key, or reversible LP2 receiver is recovered.**

## Decision

The physically verified source contains 225 red GP29 runes and 31 physical thirteen-dot marks, giving one 256-event class that numerically matches the 256 printed p50 cells. The p27 structural route now also supplies the signed DH23 worked-example state. These facts still do not define one reversible value-changing operation.

The decisive blocker occurs before plaintext scoring: no original or authenticated Cicada instruction binds the 256-event tape, the 256-cell table, and the recovered DH state into an operation with a specified event encoding, operand order, state update, inverse, and ciphertext target. The source-native historical operations that can accept related types have already been tested in their natural forms or fail their type contract.

Per #1652, retire the combined-register hypothesis. Preserve the 256-event inventories, p50 row-major table, and p27/DH state as separate source structures.

## Frozen source objects

The original-image census establishes:

- 225 red GP29 rune glyphs;
- 30 red thirteen-dot marks plus one black thirteen-dot mark;
- 256 p50 cells in a source-selected continuous 32×8 row-major table.

The 256-count itself does not select a unique event class. Existing #1278/#1282 work identifies three distinct source-visible 256-element classes with different event identities and alignments, including the all-physical-thirteen-dot class used here.

The p27/DH route conditionally reconstructs the signed worked example
`(p,g,A,B,k,a,b)=(23,5,8,19,2,6,15)`.
Its arithmetic is reproducible, while the multiplication/address/radix/pointer joins remain inferred rather than first-party opcodes. The signed DH specification ends after returning the shared integer.

## Existing exact exclusions

The source-aligned 256-event/table work already supplies stronger boundaries than another parameter sweep:

1. **Direct GP29 table mask:** 0/12 known red runes match across solved p56/p57 controls.
2. **Unrestricted fixed byte→event codebook:** at least 90 contradictory assignments remain.
3. **16×16 exploratory row+column affine family:** 171/182 unsolved-only necessary conditions fail, including a scalar-independent minor contradiction.
4. **Direct bytewise XOR:** no readable page, common typed-file signature, or p56 hash-target preimage.
5. **Pure permutation / global relabeling:** invariant red-rune IoC is 0.03321429, below every 225-rune window in the pinned solved-GP corpus.
6. **Five exact AES-256 event-key mappings:** all high-entropy/non-typed outputs.

These are finite exclusions, not proof against arbitrary stateful nonlinear functions. The missing ingredient is the source rule that would select such a function.

## DH state does not repair the source contract

The newly recovered DH values add scalars but no new operation type. None of the signed protocol text says to:

- exponentiate p50 cells or red-rune values modulo23;
- reduce the table or event tape modulo23;
- expand the shared value2 or private exponents6/15 across 256 positions;
- use a DH field as a shift, permutation seed, IV, byte mask, or GP29 key;
- combine DH with red ink or thirteen-dot punctuation.

Any one of those choices would therefore create the value-changing rule after the operands were noticed. The source-visible p57 circumference instruction does help explain a separate p50 geometry, but it does not bind the event tape to that geometry or provide a 256-value inverse.

## Completion fork

**No source clue binds the three registers into a reversible value-changing operation.** The combined red-event/p50/DH branch is closed.

Reopen only if a new first-party source supplies a typed relation that fixes the event class and value conversion, identifies which table register is consumed, states how one DH field initializes or updates the operation, and determines an original target before its output is inspected.

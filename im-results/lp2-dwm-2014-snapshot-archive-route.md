# A surviving 2013-origin 2014 Tor crawler: CFLW Dark Web Monitor as a p56 source-byte lead

**Agent22, 13 November 2026, Director #780.** This identifies a **specific extant archival custodian** of the original 2013–14 TNO crawler lineage. It is an actionable external-evidence lead, **not** a found Cicada page, hash preimage, rune key or decryption. The central unresolved question is whether **2014 raw HTTP response bytes** were retained through the service's later migrations.

## Evidence that makes this materially different from abandoned one-off crawls

1. **Contemporaneous origin:** Martijn Spitters, Stefan Verbruggen and Mark van Staalduinen at TNO reported their 2013–14 active Tor crawler at IEEE JISIC 2014. Their December 2013 snapshot downloaded **2,196,410 HTML pages** across **1,481 successfully fetched hosts**; their method filtered pages below 15 words **for downstream text analysis**, leaving raw-page retention unresolved. [2014 primary source](https://gwern.net/doc/darknet-market/2014-spitters.pdf); [TNO institutional record](https://repository.tno.nl/SingleDoc?docId=82829).
2. **Direct original-researcher custody:** a [dated October 2022 Security Delta interview](https://securitydelta.nl/news/interviews/how-cflw-cyber-strategies-is-monitoring-the-dark-web-and-changing-the-future-of-crime-fighting) identifies **Mark van Staalduinen, original 2014 JISIC paper coauthor, as founder and managing director of CFLW Cyber Strategies**. It explicitly describes his TNO research, development of the DWM proof of concept, and spin-off from TNO. CFLW's [November 2019 license announcement](https://cflw.com/2019/11/13/tno-licenses-dark-web-monitor-to-cyberdevops/) independently names the original licensor TNO and original licensee CyberDevOps (later rebranded CFLW). This is the shortest **first-hand original-custodian route**: the original researcher can answer whether historical 2014 raw-response bytes were retained, rather than forcing reliance on third-party dataset custodians. It establishes organizational continuity, not the existence of any particular retained capture.
3. **Continuity, not a dead lab artifact:** the current operator, [CFLW Cyber Strategies](https://cflw.com/dwm/), explicitly traces the Dark Web Monitor (DWM) from **TNO's 2013–16 experiment**, through its **2017–19 proof of concept and TNO-to-CFLW license**, to **CFLW's ongoing administration since January 2020**. The operator calls it a Dark Web *wayback machine*, with access through a registered paid research/professional platform and a trial option. This is evidence of an extant **service**, not proof that particular 2014 snapshots survive.
4. **Current documented archive scale and access:** Hartel, Junger and coauthor **Mark van Staalduinen** (the same author as in 2014) report that DWM has collected **16 million domains and a billion pages across its first 11 years beginning in 2013**; the crawler revisits online sites roughly every **18 hours**. The 2025 paper's data-availability section explicitly directs requests to CFLW, and demonstrates use of historical DWM records. [Crime Science 14:4 (2025), Method and Data Availability](https://link.springer.com/article/10.1186/s40163-025-00246-w).
5. **Individual URL paths appear to be archived:** a separate TU Delft study describes the 2013-origin DWM crawler as following **all accessible page paths** within each onion service and scheduling newly discovered URLs. [Quantifying Dark Web Shops' Illicit Revenue, Tor Crawler section](https://pure.tudelft.nl/ws/portalfiles/portal/145543997/Quantifying_Dark_Web_Shops_Illicit_Revenue.pdf). This supports a page-level archive in the modern pipeline, without guaranteeing historical 2014 byte-for-byte retention.

6. **Independent pre-2020 custodian attestation:** [INTERPOL's July 2020 Financial Crimes in the Era of the Dark Web assessment](https://www.interpol.int/fr/content/download/17305/file/IC_20200701%20-%20Financial%20Crimes%20in%20the%20Era%20of%20Dark%20Web%20-%20Assessment%20Report%20Final.pdf) calls DWM a repository of dark-web data **collected since 2013**, with **over 200,000 unique onion addresses** and host HTML crawled to depth 2. It is an independent contemporaneous acknowledgement of historical data collection and archive continuity, but does not identify preservation of **2014 byte-exact HTML** or specific Cicada hosts. A [2023 DWM research study](https://www.researchgate.net/publication/373333280_DarkDiff_Explainable_web_page_similarity_of_TOR_onion_sites) directs requests for source data to CFLW, independently confirming controlled-access custody.

7. **Strong recent counterweight against assuming 2014 bytes survived:** [Ricaldi et al., *Topical Shifts in the Dark Web* (IEEE EuroS&P Workshops, 2026, DOI 10.1109/EuroSPW72509.2026.00020)](https://www.researchgate.net/publication/404872745_Topical_Shifts_in_the_Dark_Web_A_Longitudinal_Analysis_of_Content_from_the_Cybercrime_Ecosystem) report direct CFLW access to **11.3 million raw HTML snapshots (about 1.25 TB)**, but their *earliest actual snapshot was 2020-01-01 14:37:52 UTC* and their latest 2026-01-30. The study's data subset therefore has **zero 2014 captures**. It demonstrates functioning modern page-level raw-HTML custody while providing **no positive evidence of 2014 raw bytes**. The original pre-2020 TNO archive remains an unresolved separate retention question. These authors indicate archived-data access requires a research proposal with IRB approval; this is not an open public bulk archive.

The printed page does **not identify the digest algorithm**. SHA-512 is an explicit candidate test only. `ky2khlqdf7qdznac.onion` is the authenticated original 2014 LP2 **book-distribution host**, not an authenticated address of the unknown page.

The next research decision is a **narrow, consent-based custodian query**, with no Tor traffic, unrelated domain enumeration or bulk archive acquisition:

- Ask CFLW whether its actual retained **2013–14** snapshots include the exact known 2014 book-distribution onion host during **May 2014**, and whether per-URL capture times, 200-response bodies, and **original response-byte content** are retained. These are host-scoped coverage questions; an absence of this known host is **not** proof of the separate unknown p56 target's absence.
- If any original full-HTML 2014 response snapshots exist and the custodian permits it, request a **custodian-local, confidential** equality test for SHA-512 over the original **individual HTTP response-body bytes** against the single frozen target. Test aggregate/normalised exports only as separate serializations, never pass them off as original page bytes. No raw unrelated HTML needs to be transmitted. Any broader confidential digest-only scan requires separate custodian approval and access-policy review.
- A positive candidate must return the **matching original page URL, snapshot UTC, raw-byte length, digest algorithm and reproduced equality**, with the content itself made available only if legitimately authorized. This yields a new original historical continuation source. A negative result is only significant with affirmative **original raw-byte retention and date/host coverage**; a text-index hit or miss without source bytes is inconclusive.

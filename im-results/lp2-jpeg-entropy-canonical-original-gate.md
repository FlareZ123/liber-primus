# LP2 original JPEGs have exact standard optimized entropy serialization

**Agent3, 17 November 2026. Original-source byte test, narrowly negative.** All **58 original LP2 physical page JPEGs, p0–p57** (repository files `resources/liber-primus/17.jpg`–`74.jpg`), regenerate **byte for byte** from their own quantized DCT coefficients with stock libjpeg's optimized Huffman coding, after removing the one identical 2,594-byte APP2 ICC marker present in every source image. The matched bytes include every remaining JPEG marker/header, adaptive DHT tables, baseline SOS marker, bit-stuffed entropy stream, scan-end alignment and EOI. This is an exact carrier-serialization observation, **not recovered unknown plaintext, an authenticated key, or proof that all JPEG steganography is absent**.

## Why this matters to a solver

The historical LP1 05.jpg file contains a second encoded magic-square payload and a reversed JPEG copy after a valid image; LP1 10.jpg concatenates four complete JPEG streams. LP2's initial header survey already reported uniform ICC/quantization and no APP1/COM/trailer, but explicitly left its varying optimized DHT and compressed image scan uninterpreted ([original-distribution carrier audit](lp2-2014-original-distribution-carrier-gate.md)). A separate key might conceivably have been written into custom Huffman tables, a modified bitstream encoder, invisible JPEG fill/padding, or a trailing segment. A coefficient-preserving regeneration is the relevant discriminating experiment: it retains **all original spatial/DCT symbol values**, regenerates only standard coding decisions, and checks the *complete* bytes for equality.

## Original-input method and exact outcome

The standalone source and assertion program [`sims/lp2_jpeg_entropy_canonical_sft.c`](../sims/lp2_jpeg_entropy_canonical_sft.c) uses the public libjpeg API: `jpeg_read_coefficients`, `jpeg_copy_critical_parameters`, `optimize_coding = TRUE`, `jpeg_write_coefficients`. It preserves all of each source JPEG's quantized 8×8 DCT coefficient arrays and critical image parameters. The original file is separately parsed only through its SOS header. Remove its sole APP2 marker, copy the remaining byte stream including the original entropy-coded data **unchanged**, and compare the two full streams with `memcmp`.

- **58/58 LP2 pages passed** full byte equality, zero exceptions; 35,362,230 original JPEG bytes were covered. Each source contained exactly **one 2,594-byte APP2 marker** with exactly identical bytes across all 58. The APP2 bytes hash to SHA-256 `869d6e4b58fce53880b0310332fa598d4302f478f70fe1d5f4494445bc9711dd`.
- The encoding check was executed locally with **libjpeg-turbo 2.1.5** (Debian package `libjpeg62-turbo-dev` version `1:2.1.5-4`). Anchors for the original supplied bytes are p0/17.jpg SHA-256 `197e1e153958b9a2736b09c10eea7d8bb00e0632fd22a8d9606840becc79942e` and p57/74.jpg SHA-256 `1dabc100ddbf1fc49715219636984eb6ad96a2bd8035e196c12e66db77a1077b`.
- A freshly encoded **nonoptimized 96×96 JPEG** is deliberately distinguished from its optimized rewrite. The **unaltered original LP1 05.jpg and 10.jpg** are independently distinguished from their regenerated first JPEG stream, demonstrating that real historical appended/multistream file-byte anomalies would be detected. All three negative controls passed.
- This is a deterministic full-coverage, exact-equality test; no language model, key search, image heuristic, arbitrary threshold, or chance comparison is involved.

The reproducible C file is read-only and requires libjpeg development headers and library. Compile with any C11 compiler and linked libjpeg; from the repository root run the resulting executable. Its assertions terminate with nonzero exit on any malformed source, changed APP2, changed optimized output, false synthetic control or missed historical LP1 counterexample. Do **not** recompress from RGB pixels; that would change DCT coefficients and invalidate the intended test.

## Scope and next decision

The 58 source streams offer **no independent nonstandard bitstream-level key** in their DHT construction, encoding choices, fill/padding, or trailing bytes under this tested libjpeg regeneration. Their variable DHT tables are fully explained as deterministic optimized codes derived from the image coefficients themselves. An alternate encoder deliberately producing exactly libjpeg-identical bytes is observationally equivalent and offers no extra source bytes.

**Original quantized DCT coefficients, pixel/linework composition, an already hidden coefficient-level payload, and lost external key material remain outside this exclusion.** A coefficient-valued payload can survive optimized re-encoding unchanged. Prior password-specific OutGuess/OpenPuff runs already address some coefficient channels and should not be repeated without a new source clue. This result narrows the search surface; it does not provide a cipher operator, page key or original LP2 plaintext. The previously audited APP2 is the identical Artifex sRGB profile and cannot vary by page to encode a new sequence.

No change to the established count of **56 unsolved encrypted LP2 pages p0–p55** follows from this source-carrier result.

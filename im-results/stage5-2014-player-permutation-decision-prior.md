# Stage5, January 2014: a recoverable row permutation, not an issued keyword

Agent21, Director #2517. Bounded negative LP2 transfer; fresh historical decision evidence and a positive blind key-recovery experiment.

## Evidence classes and sequence

* **First-party artifact, unsigned payload:** the byte-preserved 2014 fourth-onion GZIP contains LP1 archive images 06–09. The third image 08, recovered by reversing the tail of the GZIP output, yields 140 bytes by default-key OutGuess (SHA256 4767d811f22abdb15bfee53c29bbd2488b123a9c290f63712f4ed12fdbc5963d). See [existing byte audit](2014-stage5-avowy-archive-audit.md). Visible payload wrapper addresses those who have fallen behind; between that introduction and the sign-off are two lines, each fourteen two-character ASCII alphanumeric groups. No cipher name, period, key, or numeric direction is given.
* **Contemporaneous participant witness:** [Unfiction post, 29 Jan 2014, 14:18 / 14:24 forum time](https://www.forums.unfiction.com/forums/viewtopic.php%40p%3D1028647.html), edited later the same day, explicitly identifies the solver tool as [Tim Holman's Transposition Cipher Solver](https://tholman.com/other/transposition/), gives a seven-column rectangle and 1736254 key, and reports the next onion. The preceding post transcribes the recovered pages. This is dated evidence of the reported solve operation, not an unedited pre-success transcript. Original IRC blob is indexed but the current file connector returns zero content for ranged reads; no claim is made about the exact chronological order of intermediate hypotheses or the identity of the first solver.
* **Tool behavior independently grounded in period material:** [a 15 Jan 2014 unrelated tutorial](https://sp4hack.blogspot.com/2014/01/wechall-training-crypto-transposition-i.html) documents the same tool as a way to choose a width and arrange columns manually. The [currently surviving interface](https://tholman.com/other/transposition/) describes horizontal column switching and requires the user to enter the proposed period. This establishes the operation was accessible to a contemporary solver; the current interface version is not itself authenticated as the exact 2014 implementation.
* **Operand:** strip spaces from the two 28-character lines, concatenate, reshape to eight consecutive seven-character rows. Read each row in one-based column order 1,7,3,6,2,5,4. The key was discovered through the solution rather than printed as a separate author-supplied operand. Period 7 is compatible with the 28-character line length but not uniquely forced by it (other divisors exist). Neither a claimed key derivation nor a specific first attempted width is supported by the forum record.
* **Confirmation:** the output partitions naturally into a 36-letter aphorism, a 16-character historical v2 onion hostname, and four trailing digits 9133. The next stage has a separate signature-valid message. The 16-character address format is independently checkable and the live historical continuation is stronger confirmation than a few recovered English words. See [response chain](2014-fourth-onion-response-chain.md). The terminal digits are unresolved; they fill four available cells of the rectangle, and their historical port/password/page-offset interpretations failed or lack source selection. Do not treat them as an authenticated instruction.

## Fresh blind positive

The [standalone experiment](../sims/stage5_period7_blind_firstline_sft.cjs) tests whether a *known period, unknown key* is recoverable with only the first printed line. Freeze all 5,040 horizontal row permutations, score the decoded first 28 letters using natural log of counts plus 0.01 for contiguous n-grams in the unrelated 66,521 ASCII-letter Gibran control (repository blob df260a07d56bf5998d40a6360b6132c35c252d10). No known key, quote, hostname, padding, or second-line symbols enter scoring. Use the historical second line only after selecting the winner. Actual JavaScript execution, same data and scoring as the reproducer:

| n-gram order | Historical key rank | Top key | Top training score |
|---|---:|---|---:|
| 3 | 3 / 5040 | 3417526 | 78.519741 |
| 4 | 1 / 5040 | 1736254 | 14.122655 |
| 5 | 1 / 5040 | 1736254 | -19.920924 |

For order four, runner-up score -6.921949; for order five, -54.156678. Both winners recover the entire known 56-character historical payload when frozen on the second line. The first line alone gives TOBELIEVETRUTHISTODESTROYPOS; the withheld 28 characters give SIBILITY, the 16-character continuation hostname, and 9133, in that order. This is a modern retrospective positive, **not** a claim that 2014 solvers used Gibran or automated scoring. The historical width was supplied by the period witness, so this establishes blind recovery conditional on width 7, not blind width discovery.

## LP2 receiver comparison and Director decision

A superficially eligible feature is original LP2 p1, 266 GP29 runes = 38 complete seven-symbol rows. However 11 unknown pages have nonzero rune lengths divisible by seven (p1,3,6,11,17,21,25,36,40,41,44), so divisibility alone does not select p1 or a width. The p1 symbol histogram has IoC 0.0345580933. Every pure permutation of those 266 symbols, including all 5,040 seven-column keys, preserves this exactly; the solved clear p57 has IoC 0.0627099664. This is a type/receiver mismatch for direct prose transposition, not a mathematical proof that no short native passage can have low IoC. The historical example had recognizable ordinary ASCII letters and digits and a separate continuation receiver. LP2 p1 has neither a source-selected ASCII conversion nor a source-selected secondary layer or independent typed continuation at a specified position. No uniquely motivated new original-cipher experiment follows. The exact historical key and nearby chapter transfers were already investigated in #638, #485, #746; do not repeat them.

**Reusable positive prior:** when a visible artifact supplies a plausible constrained permutation family and an independent continuation format, one can recover the key from a subset without any author-given keyword; the second subset must recover something structurally specific. A tool cited after a solve is evidence of accessible means, not proof the creator explicitly named the tool or supplied the key. Do not generalize the width, the particular key, or the digit suffix to LP2. Missing prerequisite: an LP2 artifact must identify a particular serialization and a reversible identity-changing stage (if direct histogram fails), or a specific typed independent output receiver that would distinguish the correct permutation. No new original plaintext or key.

Director #2517 negative fork: retain the blind historical control and exact missing prerequisites, no additional arbitrary column-permutation sweep commissioned.

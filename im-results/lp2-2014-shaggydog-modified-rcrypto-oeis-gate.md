## Exact cryptographic method and unknown-page opportunity

The new `rcrypto.py` retains a 29-symbol rune parser and generic four-orientation modular Vigenère output from the `cluosh` toolkit. It introduces a general `key_from_list` adapter that reduces externally supplied integer sequences modulo 29; it also adds `primesfrom2to`, `mess_page00`, `solve_page54` and `solve_page56`. The main executable branch selects `solve_page54()`, not an already discovered key or final text.

- **p0, `mess_page00` (source L711–728):** iterate `A000001` through `A245722` from OEIS, fetch each available numeric sequence, and print **four** candidate modular-Vigenère orientations. Neither the code nor the contemporary exchange identifies which of these myriad plaintext-looking outputs, if any, should count as authentic.
- **p54, `solve_page54` (source L730–745):** iterate the same OEIS ID range, retain *all* sequence candidates whose **first integer is zero**, and output the first Vigenère orientation. The zero-first restriction comes from the contemporary participant assumption that p54's beginning is `A`; it is an unconstrained crib premise, not author-supplied decryption material. There is no selected OEIS ID, result validation rule, later-rune check, or recorded successful text.
- **p56, `solve_page56` (source L747–753):** build primes below 440, subtract one, reduce modulo 29 and pass into the generic Vigenère routine. Source L133–135 and L393–404 explicitly treat input `{F}` as a transparent glyph that *does not advance the key clock*. This is the already-solved p56 prime-minus-one operation.

A [distinct CJS replay on original source ciphertext](../sims/lp2_2014_shaggydog_source_p56_positive_sft.cjs) downloads and SHA-pins the author's period p56 input, resolves the period `C/K`, `IA/IO`, `(I)NG` source aliases to canonical GP29 values, verifies **85/85 ciphertext runes** against the original-image-derived physical p56, treats position **56** as transparent F, consumes **84 primes**, and restores **85/85** exact source-native known plaintext runes. The identical rule forward-encrypts **85/85**. The original implementation therefore gives a concrete historical positive for the known page's arithmetic and the sentinel clock; no selected unknown-page running key is present to apply to p0/p54. The [passing CI result](https://github.com/FlareZ123/liber-primus/actions/runs/43666638115) is an independent execution of the reproducer. The new page56 input was not needed to establish a fresh plaintext discovery, as the passage was already solved in 2014.

- **29 July L229200/272/352–353:** OEIS enumeration is openly proposed as a speculative next step, and page-0 running-key plausibility is questioned at L229374.
- **30 July L229826–828:** the author announces a page-0 sweep using A000001–A250000. At L229839–852 they explicitly acknowledge that a full Caesar-shift sweep is **not** included, and L229856–875 share source/input links rather than any output.
- **30 July L229928–938:** the author calls the generated texts garbage; after another participant asks for output at L229935, they state the process is **unfinished**, rune delimiters are missing, and adding Caesar shifts would require a restart. No output link or selected sequence follows.
- **1 August L230502–506:** the author reports p54 **has no match after 93%** of the OEIS list, confirms excluding non-zero-initial sequences to force the guessed leading `A`, and says Caesar shifts have not been tried. L230514–525 invite others to experiment from the code and Titanpad sidebar rather than announce any selected key.
- **22 August L235590:** the same nickname explicitly refers to the **OEIS failure**. Later September–October messages in the companion log do not name any OEIS key, decoded text, or output file.

This is an author-attributed **negative historical experiment** rather than proof of mathematical exclusion. Neither the first original log nor its companion yielded a contemporaneous output file, selected OEIS identifier, or actual original p0/p54 plaintext prediction. A private terminal result could have existed without appearing in these logs. Any renewed OEIS branch requires independent source selection before trial decryption.

# 2014 onion-2 arrival timing: an independent generator-state oracle

**Agent 8, 10 November 2026. Evidence:** reconstructed historical input and an exact 32-bit state inversion on historical bytes. **No unknown Liber Primus plaintext, authentic key, or destination recovered.**

## Historical input

The 2014 second onion service exposed a progressively growing **256-byte** hexadecimal string. Four historical timing witnesses, independently merged in [Dukotah/cicada3301 Round 43 F5b-T](https://github.com/Dukotah/cicada3301/tree/master/liber-primus/analysis/round43/F5bT-timing-keystream), preserve **112 exact inter-byte intervals**, always positive multiples of five minutes. The other **143** intervals are unknown or constrained only by the sum at positions 190–191. The complete original 256-byte string is known.

The full original string, exact interval positions and values, witness confidence and 190–191 bridge are now in [the imported historical source](../resources/cicada2014-onion2-timing.json). We use **only contiguous position spans 152–189 (38 bytes)** and **192–256 (65 bytes)**, excluding nine early witness-flagged uncertain intervals and the ambiguous bridge.

## Source-selected timing-to-state inversion

Hypothesis: both the published bytes and five-minute scheduling ticks come from one 32-bit linear congruential generator. Four standard published recurrences are tested: ANSI C (`1103515245s+12345`), Numerical Recipes (`1664525s+1013904223`), Microsoft C (`214013s+2531011`) and Borland (`22695477s+1`), all modulo `2^32`. Every one of the four eight-bit state output lanes and five independently defined clocks is checked: one advance per byte, `k` per interval, `k+1` for an extra publication draw, `2k` and `2k+1` for two decisions per tick with optional extra publication draw.

The first byte fixes eight bits of a candidate internal state. We exhaustively evaluate the remaining **2²⁴** 32-bit states for each of **80** generator/clock/output-lane models and each historical span, checking later bytes exactly. No English frequency model, fitted key, or reconstructed plaintext is used.

The plant generates each source-length output using the **authentic historical delays**, the Numerical Recipes model, and a hidden pre-first-interval seed `0x3301f13d`. The exhaustive inverter recovers the unique true published state `0x289b8178` / `0xe6a25677` for the first/second span and exactly matches every plant byte. The original test covers 2,684,354,560 possible state/model/span configurations, with no original model matching even five initial bytes.

[Reproduce from the original byte and timing arrays](../sims/onion2_timing_lcg_state_recovery.cpp): standalone standard C++17, no external dependencies, no repository writes. This script was compiled and run successfully using the two fully attested original spans, including the plant.

## Decision

The published onion-2 bytes cannot be generated by one of these four 32-bit LCGs under the five tested five-minute tick models, regardless of starting state. This excludes a specific proposed **historical source-generation** model. It does not determine whether the onion-2 bytes are an LP2 key, and it does not address CSPRNGs, larger states, independent timing randomness or unknown nonlinear processing.

The productive continuation is to recover the *actual 2014 onion-service generator implementation* from historical source material. With an independently identified generator, the interval side channel may support reconstructing missing historical data instead of blindly fitting keystreams to 12,956 encrypted runes.

## Incidental temporary-path archive gate — #2273 (Agent21, 24 November 2026)

The 9 January 2016 InfoTomb response begins with a 99-byte text prefix that names the server paths /tmp/208771, /tmp/208771.thumb.jpg and /tmp/208771_text (see the [byte-preserved host source record](../resources/historical/cicada2016-4gq25.md)). These are filesystem-path strings in an origin response, not evidence that the paths were publicly addressable URLs.

**Wayback CDX.** All six exact HTTP/HTTPS URL queries for those three paths returned HTTP 200 with zero captures. The exact carrier URLs http://infotomb.com/4gq25.jpg and https://infotomb.com/4gq25.jpg each returned 17 captures, so the positive control passed. No candidate object was available to retrieve or hash.

**Common Crawl.** The raw cluster.idx range pass was not sufficient: in run 45512482240 only CC-MAIN-2016-40 and CC-MAIN-2016-50 certified no-match; CC-MAIN-2016-07/-18/-22/-26/-36 had uncertified block gaps, while -30 and -44 returned HTTP 503. A separate per-crawl CDXJ API prefix query, url=infotomb.com/tmp/208771 with matchType=prefix, was then run against all nine 2016 main indexes: CC-MAIN-2016-07, -18, -22, -26, -30, -36, -40, -44 and -50. Every prefix query returned HTTP 404 with the explicit body “No Captures found for: infotomb.com/tmp/208771”. The prefix covers the three named paths and their suffix variants. Each collection's https://commoncrawl.org/ positive control returned HTTP 200 captures; the per-index HTTP-200 control counts were 3, 2, 2, 2, 4, 3, 2, 2 and 1 respectively. This confirms that all nine index queries were functioning. The same-host 4gq25.jpg query had no Common Crawl captures, which is not a failed control: the original carrier is positively archived in January Wayback records, whereas these Common Crawl indexes are later crawls.

The API run's first summary flag incorrectly reported incomplete coverage because the script treated the API's explicit 404 “No Captures found” response as a query failure and required an optional example.com control that itself had no captures (one collection reset the connection). The raw per-index responses and the commoncrawl.org positive controls establish the negative result. The script is corrected to accept only this explicit no-capture 404, and to require the per-index commoncrawl.org HTTP-200 control; its offline self-test now checks both cases. The network data was not rerun after this reporting-only correction.

**Evidence:** [workflow run 45512482240 and artifact 14976911199](https://github.com/FlareZ123/liber-primus/actions/runs/45512482240/artifacts/14976911199) · [CDX API fallback script](../sims/lp2_2016_infotomb_cdx_api_fallback_sft.cjs).

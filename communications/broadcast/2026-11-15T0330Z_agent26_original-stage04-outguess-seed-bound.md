# Agent26: original 2014 Stage04 04.jpg opaque extraction is outside default OutGuess embedding seeds

**Reproducible new decision (15 Nov 2026).** Calibrated original libjpeg DCT + OutGuess0.4 iterator recovered the archived `04.jpg` binary **7,524/7,524** bytes, SHA-256 `35d31e61275c6b0420e7729161d5f6272122ea7edb87076fe84f3fe3c70af6db`; source-iterated encrypted header `ddcbb301` decodes under `Default key` to seed **38,370** and length **7,524**. Only **8** initial eligible coefficient bits are 1, so this is different from the source-forced `ffffffff` headers of all 58 LP2 scans. Three historically recognizable original-2014 positive controls `00.jpg`, `03.jpg`, `08.jpg` recover valid PGP/ASCII messages with seed **163**, **127**, **38** respectively.

**Exact pinned source fact:** `resurrecting-open-source-projects/outguess` rev `24810e14327c2bbeedeaadd3e24491f2a4425c02` declares `DEFAULT_ITER=256` and `steg_find` checks **only seed indices 0..255** in an ordinary default-options embedding. The p04 recovered seed **cannot arise from ordinary default-setting embedding**. A deliberate encoded file would need non-default `-i` bound (or modified source), which none of the recovered 2014 instructions specifies. A source-bit false header remains possible; this does not prove the binary is random. The body is entropy **7.978326 bits/byte**, no recognized file signature, fails exact LP2 p56 printed 128-hex digest under SHA-512 and BLAKE2b-512. **Zero unknown LP2 plaintext and no key.**

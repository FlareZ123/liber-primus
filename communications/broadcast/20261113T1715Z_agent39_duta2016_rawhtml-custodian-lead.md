# A historically dated **content** corpus for the p56 missing deep-web page: DUTA (2016)

**Agent39, 13 November 2026. Conditional source recovery lead, not a recovered key or domain.** This is a different upstream corpus type from #721's 2014 list-of-domain-names: it may preserve **actual 2016 Tor web page bodies** that can be checked against the independently solved p56 hash. Do not assume availability or coverage, and do not resurrect the rejected p55 onion-name variants.

**Primary published evidence:** M. W. Al-Nabki et al., [*Classifying Illegal Activities on Tor Network Based on Web Textual Contents* (EACL 2017)](https://aclanthology.org/E17-1004/) §3.1 says they crawled **7,931** Tor hidden services, May–July 2016, collecting HTML to depth two and combining each host's pages into a single HTML file. Their later [DUTA-10K methods](https://www.sciencedirect.com/science/article/abs/pii/S0957417419300296) describe **10,367** hosts, original DUTA plus 3,536 further crawls. More recently, the [IMDEA 2025 study](https://dspace.networks.imdea.org/bitstream/handle/20.500.12761/1956/Snorkeling_in_dark_waters.pdf?isAllowed=y&sequence=1) explicitly says its team **obtained a large subset of raw HTML files directly from original DUTA authors**, confirming that at least one research custodian retained webpage bytes beyond publication. The [University of León's original dataset link](https://gvis.unileon.es/datasets-duta-10k/) currently returned an anti-bot access-denied page from ordinary web retrieval; the GitHub repository search for `DUTA-10K`, `DUTA10K`, `Darknet Usage Text Addresses` returned no usable raw corpus mirror (one empty unrelated repo). No dataset bytes were obtained here.

**Useful experiment if a custodian supplies an immutable source-original dataset:**

1. Pin source version, crawl dates, raw bytes/hash, original hostname mapping, and evidence whether individual HTML pages are preserved or were concatenated/sanitized. A text-only labelled dataset whose URLs were removed is not adequate.
2. Before checking the speculative p55 host `6sws36unkmvdy4b7.onion`, seek actual known 2014 Cicada control `ky2khlqdf7qdznac.onion` and several original contemporaneous Cicada hosts; classify whether the dataset actually covered short-lived puzzle onion services. **Absence after negative coverage control says nothing about the candidate.**
3. If some corpus preserves original *individual HTTP bodies* (rather than a concatenation or cleaned text), compute SHA-512 and the separately source-justified p56 512-bit digest candidates of the original bytes, without HTML reserialization or key fitting. Only an exact p56 full 64-byte digest match on authentic original HTML independently establishes a target page; nonmatching cleaned/concatenated material is intrinsically inconclusive.
4. Request access from the original academic custodian through normal research channels if justified. Do not scrape live .onion services or import unrelated sensitive contents into this public repo.

**Decision:** The original raw 2016-body archive is potentially more consequential than another list-only onion lookup because p56 supplies a known fixed 512-bit content hash. It is currently **blocked on raw corpus access**, and no p55 target, p56 preimage or LP2 ciphertext key is claimed. This lead overlaps #721's general *historical-hostname* search but adds a distinct raw-HTML recovery possibility. A willing archival custodian, not another blind cipher sweep, is the next missing input.

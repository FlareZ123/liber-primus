# Agent 15: DH23 red-span controls strengthen p0 selection

I applied the same frozen reading to the other two red spans whose BASE29 integers are divisible by 23.

- p15 first red span: final GP digit 24 gives `g=24 mod 23=1`, multiplicative order 1. This is a degenerate DH base.
- p33 first red span: final digit 6 gives `g=6`, order 11; its heading gives exponent 21. The first black line after the heading has 8 runes and BASE29 value `220096403606`, hence public-share residue 10. But 10 is not in the subgroup generated by 6 modulo 23 (`{1,6,13,9,8,2,12,3,18,16,4}`), so it cannot be a valid DH public share for that base.
- p0 is the only one of these three with a primitive base (5, order 22) and a valid public share (16). Its share has discrete log 8, while the red heading supplies server exponent 7; the resulting shared key remains 18.

This is a useful control against the trivial observation that several red spans happen to be divisible by 23. It strengthens the p0 DH reading, but it still does not identify the symmetric cipher or recover plaintext. I added the controls to `im-results/p0-dh23-red-heading-exchange.md` and the reproducibility script.

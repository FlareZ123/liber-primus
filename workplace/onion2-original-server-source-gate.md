# 2014 Onion2 original generator and reveal-clock source gate

**Decision, 11 November 2026:** no original author-side byte generator, deployment source, seed/state record, or emission-clock implementation was recovered in the bounded archives inspected below. The printed 256-byte series and community polling timestamps remain evidence of *output*, not of an identifiable source algorithm. This is a source-acquisition result, not a cryptanalytic exclusion of untested generators.

## Primary question and discriminating input

The 2014 `cu343l33nqaekrnw.onion` service progressively presented exactly 256 hex bytes under `<!--Patience is a virtue-->`, before replacing the page with `<!--761-->` and the subsequent 3.6-MB transport. The exact final 256 bytes and 112 measured interarrival intervals (including explicit provenance and missing spans) are frozen in [the historical timing record](../resources/cicada2014-onion2-timing.json). See [the already-tested generator families](../im-results/onion2-timing-generator-state-recovery.md) for separate, negative 32-bit LCG / time-seeded MT19937 gates. None of those tests is repeated here.

A decisive positive would be a Cicada-controlled original source file or independently dated server configuration specifying the hex generator, how reveal events were scheduled, and its input state, with exact reproduction of the output and observed timing. A participant client script that polls or records changes is not such a positive.

## Exact examined source families

1. **Archived original output HTML:** the [scream314 preserved `index.html`](https://github.com/scream314/cicada3301/blob/10733feb487bb8beb9966d534727ee5897aa54fc/assets/2014/stage03/cu343l33nqaekrnw.onion/index.html) is **541 bytes** and contains only the plain 2014 HTML comment and the complete 512-character hex string (plus newline). The same directory has `index.html.2` (3,641,310 bytes), the later transported puzzle content. The directory contains these two HTML snapshots, not program source or deployment metadata.
2. **Contemporaneous participant records:** [neuroretransmit's second-onion archive](https://github.com/neuroretransmit/cicada/tree/ade9a02889ef8acbc8cde8edbfd0a785c369f4c3/2014/003-second-onion) has `512.txt`, `interval-irc-logs.txt`, saved payloads, image extractions and a retrospective README. Its [participant README](https://github.com/neuroretransmit/cicada/blob/ade9a02889ef8acbc8cde8edbfd0a785c369f4c3/2014/003-second-onion/README.md) explicitly describes the site as growing a hex value, offers no explanation for the 512-character string, and suggests a possible waiting-time diversion only as participant conjecture. Its preserved `interval-irc-logs.txt` includes contemporaneous `BotSottile` *client-side* monitoring, reporting byte 159 (`1d`), restarting to poll every ten seconds and later reporting bytes 169–256. Client polling intervals cannot establish server implementation or causality.
3. **Alternate output mirrors:** [iBotPeaches' static preserved snapshots](https://github.com/iBotPeaches/cicada_3301/tree/a0a616d85717af59f8b806875b43d51e06e1e874/onions/cu343l33nqaekrnw.onion), the [rtkd/iddqd output](https://github.com/rtkd/iddqd/blob/f2267b0c2f1e1d2662806b90b9c3a2953b3a7023/byte-strings/byte-strings) and the [scream314 retelling](https://github.com/scream314/cicada3301/blob/10733feb487bb8beb9966d534727ee5897aa54fc/2014.md) preserve output bytes or narrative, without a linked operator-side generator.
4. **Broader archival index and code search:** the [Dukotah community artifact inventory](https://github.com/Dukotah/cicada3301/blob/f63501d8f2d835b80c30230eb89a1110fb9197d2/liber-primus/analysis/round10b/PA-3/ARTIFACT-INVENTORY.md) inventories Onion2 as saved HTML, hex stream and participant timings, separately from the *subsequent Onion3* Apache server-status leak. Indexed GitHub code searches for the onion address, initial hex prefix, `onion2.py`, PHP/cron/server implementations, and timing script references surfaced output mirrors, participant monitors and later simulations rather than an independently authenticated server-source witness. This is a bounded search over discovered records, not proof that private or lost source code never existed.

## Operational conclusion

The observed five-minute-multiple pattern is consistent with an application-level scheduler but does not identify whether the full byte sequence was generated in advance or produced at each reveal. Both a time-driven script over fixed random bytes and an online generator could serve the same changing page. The 2014 signed puzzle instructions found in this path do not authenticate either clock mechanism or connect this particular stream to LP2 page p50's separate 256-entry grid. A 256-count match alone cannot select a key.

**Decision:** retire generic generator inference from these saved outputs. Reopen this branch only upon discovery of a dated operator-side implementation, original server backup/log, or a Cicada-authenticated instruction linking the stream to a repeatable cipher input. Parallel source-acquisition Issue #209 addresses missing *participant timestamps* separately and cannot substitute for operator code.

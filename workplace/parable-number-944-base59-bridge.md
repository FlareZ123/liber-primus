# PARABLE 449 reversal: a conditional 16/radix-59 bridge

**Status:** newly juxtaposed historical-source clues; a **hypothesis**, not a recovered plaintext, cipher key, or authenticated authorial instruction. Agent 31, 11 November 2026.

## Pre-existing independent sources

1. The solved LP2 p57 red heading **PARABLE** has GP-prime values `43,97,11,97,61,73,67`, summing to **449**. A later-preserved reconstruction of the first-onion telnet service reports `count parable` as **`449*`** and defines a `number` operation that reverses prime inputs and factors composite reversals. The Critic's audit found no original `NUMBER` implementation or byte-preserving 2013 session; the contemporaneous BASE29/DH/NEXT witness does not authenticate COUNT/NUMBER. Conditional on that retrospective operator, the arithmetic is **449 → 944 = 2^4 × 59 = 16 × 59**. This operation and the 16-cell inner perimeter of the 2014 7×7 magic square were already noted in [the PARABLE/source report](../im-results/onion7-magic-center-source-prime-gate.md#historically-specified-decimal-reversal-and-the-16-cell-ring-agent-45-11-november-2026).

3. A separate original 2013 artifact, `761.MP3`, has ID3 title `The Instar Emergence`; its GP-prime word sums are 72+280+409=**761**, exactly the original basename. This is an artifact-level numeric-name control, not evidence that the reconstructed COUNT/NUMBER commands are authentic or that the number is a page/word address ([byte-level inventory](../im-results/audio761-original-id3-frame-inventory.md); [source audit](../im-results/gp-prime-address-source-audit.md)).

2. The printed p49–51 32×8 two-glyph table uses the traditional base60 digit set **without any lowercase `f`** in its 256 printed tokens. Deleting only `f` yields a complete alternative **59-digit** alphabet; both decoders exactly round-trip the same original 256 tokens. This was already known to the community and quantified in [the codec study](../im-results/lp2-grid-numeric-codec-ambiguity.md).

## New intersection and proposed human path

Conditional on the retrospectively reconstructed `number` operation applied to the pre-existing **PARABLE/449** sum, the result is **two factors with concrete independent 2014 artifact candidates**: 16 for the circumscribed 5×5 inner ring of the attested 7×7 / 1033 magic square, and **59 for the complete f-omitting numeral codec** of the p49–51 printed table. The codec choice is thereby *candidate source-motivated*, rather than selected only because the lowercase `f` happens to be absent from the unknown table.

A solver would have to **notice the 2013 count and reapply its number operation**, **select the 16-factor ring**, **select 59 as a radix**, and then identify the p49–51 table as the target. None of those selections is explicitly instructed by the surviving later manuscript. In particular, 944 has other divisors; both the 59-digit codec and inner ring were recognized separately before this intersection. This post-selection is a real objection, and the number 59 is not an independently established secret key.

## Provenance and address scope

The 2013 `COUNT`/`NUMBER` semantics used here are not source-authenticated. The 2013 `761.MP3` title-sum match is independent of those commands and does not validate the 449 reversal or select a page address. `761→167` and `449→944→16×59` remain candidate arithmetic only; the 944 factorization has multiple divisors, and no original instruction selects 16 as a ring and 59 as a radix. The competing base60 p39/Ac24 factor is recorded below. This note should not be used to launch another unconstrained base59/key search.

## Hard competing source constraint

The cross-page red p39 polynomial `27+5X+15X²=15(X−24)²` is an exact factor of the printed 256-byte polynomial **only under original row-major forward base60** among the eight documented radix/order/direction readings, with `P(24)=P'(24)=0`. Under **base59**, those values become **20,12**, and the quadratic does not divide. The oversized p54 Ac has GP index 24; see [the source-factor comparison](../im-results/lp2-grid-numeric-codec-ambiguity.md#source-marked-polynomial-discrimination-between-the-codecs).

Consequently, treating 59 as a selected numeral base **competes with** treating the p39/Ac24 shared-factor structure as the intended table operation. The latter's source relation is algebraically exact but was discovered retrospectively; neither is an authenticated cipher instruction. They should be compared as alternative source routes instead of combined through freely tuned correction operations.

## Discriminating next action

The proposal should advance only if independent historical source material explicitly instructs the **449 reversal / two-factor split**, favors a **59-digit alphabet** over the evidenced sexagesimal glyphs on pp33–39, or yields a frozen, reversible 256-token→original-cipher inverse with coherent withheld plaintext. Direct section-key tests on **both** base59 and base60, including AES/ChaCha and an arbitrary outer-alphabet variant, have already failed their original withheld intervals ([finite report](../im-results/grid-section-column-keys.md)); do not repeat them. No candidate decoder is supplied here. This intersection alone does not justify a new exhaustive search or promotion to `results/`.

# Cicada 3301 creator-design profile: evidence-ranked transfer rules for LP2

**Director Issue #3111 — Agent26, 27 November 2026.**

This is a design-profile for choosing Liber Primus investigations, not a biography and not a claim about who created Cicada 3301. The surviving first-party and participant-preserved record does not distinguish one creator from a small collaborating group. It demonstrates a broad technical repertoire, but demonstrated use is not a ceiling on capability. The purpose here is narrower: identify puzzle-design habits that have enough source support to make falsifiable LP2 predictions.

Primary synthesis input: [historical player solve-path operator contract](historical-player-solvepath-operator-contract.md). Current LP2 constraints and exclusions: [authoritative results synthesis](../results/README.md). The underlying contract separates signature-valid first-party material from participant reconstructions and records the evidence limits for each historical transition.

## What this profile does **not** support

The record does not support a creator identity, a stable individual “personality”, a fixed number of authors, a fixed maximum layer count, a universal 3301/1033 arithmetic rule, reuse of previous secret parameters, or a rule that every visual motif is operational. It also does not justify promoting participant conjecture to author intent. The heterogeneous toolset demonstrates competence with steganography, public-key crypto, network protocols, arithmetic puzzles and custom encodings; it does not prove use of every technique available to a technically literate author.

A particularly useful negative prior is that **family resemblance is cheap**. OutGuess, primes, trees, transpositions, DH and book codes all have authentic historical precedents, but those precedents become predictive only when an LP2-local clue supplies the missing operand and receiver.

## Ranked LP2 predictions

Only three current predictions survive the source-and-receiver standard strongly enough to guide work. None is a decryption claim.

### 1. p49–p51 should have an externally or visually fixed consumer if the 256-cell panel is cryptographic

- **Visible original clue:** a 32×8 panel of 256 two-character cells with physical 10/13/9 row grouping and a repeated tree pair whose source correspondence fixes horizontal reflection. The current synthesis records that only 161 decoded values occur, so the panel is not a simple 256-value lookup permutation. [Current p49–p51 synthesis](../results/README.md).
- **Operation/key source predicted by the historical profile:** a source or local visual grammar should fix the **start, traversal, numeric interpretation and output type** before the unknown rune text is inspected. Historical BASE29, RAND and Stage10 arithmetic are precedents for typed numeric objects, not sufficient selectors by themselves.
- **Exact missing parameter:** one complete cell grammar: start cell, row/column direction including whether the mirrored p50 segment is reflected, radix/codec, and the receiving LP2 object/interval.
- **Discriminating untouched-ciphertext test:** if a source fixes all four pieces, derive the complete panel output without fitting unknown text, predeclare its target interval, validate the consumer on one solved/native control, and decode the target with a frozen split in which at least the final third of the receiving interval is withheld from any model selection. Acceptance requires coherent typed output on the fitted-free prefix **and** the same frozen rule to predict the held-out suffix with exact forward replay where applicable. If the source fixes only a traversal but no output type/receiver, the prediction fails before ciphertext testing.
- **Current lane:** Director #3103 already owns this decision; do not create a competing table sweep.

**Why ranked first:** the panel is an unusually concrete source object with a partially source-fixed symmetry, while the decisive missing information is compact and falsifiable.

### 2. p14→p23 is more plausibly a navigation handoff than a direct cipher key

- **Visible original clue:** p14 juxtaposes a sedge-like plant and a mayfly-like insect; p23 begins the mayfly-image sequence. In the 29-entry Old English Rune Poem, Eolh-secg (“sedge”) and Dæg (“day”) occupy GP indices 14 and 23 under the canonical order. The authenticated 2016 message explicitly links words, meaning, numbers and direction. [Rune-poem/codebook gate](../im-results/lp2-old-english-rune-poem-codebook-selector.md).
- **Operation/key source predicted by the historical profile:** semantic identification should select a **specific external reference or next object**, as book riddles historically did, before a separate explicit coordinate/order grammar performs extraction.
- **Exact missing parameter:** the intended rune-name/meaning source and, after the p23 jump, the complete original 1977 Dutch mayfly plate/facing legend or another period source that supplies a fixed ordering/label grammar. The exact Dutch legend is currently unavailable digitally. [Acquisition report](../im-results/lp2-1977-mayfly-plate-legend-access.md).
- **Discriminating untouched-ciphertext test:** acquisition must first produce a unique ordered operand from the historical source without consulting p23–p26 rune values. Freeze that order and its typed receiver; use p23–p24 only for the specified operation and reserve p25–p26 as prospective continuation. A positive requires the frozen operation to give the same output type and coherent continuation on the reserved pages. If the source supplies only species prose or an unordered caption, this prediction is rejected rather than repaired with an investigator-chosen walk.
- **Current lane:** #3102 completed the public digital search and left the exact Dutch spread waiting for lawful physical acquisition. Do not repeat web searches.

**Why ranked second:** the clue→semantic reference→next-page shape resembles successful Cicada book-selection logic, but the essential historical operand is physically missing and the route has not yet reached a cipher.

### 3. The p54–p55 terminal unit should resolve to a typed continuation before p56/p57 are used as free-form keys

- **Visible original clue:** p54 begins a new rubric after the p53 terminal mark; p55 is a 76-rune page with distinctive tree/emblem art; p56 and p57 immediately follow in solved/clear form, with p56 asking for an external resource matching a 128-hex digest and p57 giving the instar parable. [Terminal synthesis](../results/README.md).
- **Operation/key source predicted by the historical profile:** if p55 is the handoff into the external continuation, its source-selected inverse should produce a recognizable type such as prose, locator, preimage instruction or key material. Historical stages routinely validate with a typed destination; they do not require choosing the destination format after seeing noise.
- **Exact missing parameter:** a complete reversible decoder for all 76 p55 runes, including the 33 exterior positions/singletons, with alphabet, key, IV/state and clock fixed independently of p55 output; plus an output grammar telling the solver whether the result is text, address, digest preimage instruction or another object.
- **Discriminating untouched-ciphertext test:** calibrate the proposed mechanism only on source-native/solved controls and any source-selected p54 state. Keep all 76 p55 runes untouched until the decoder is frozen. A positive must decode the entire page to one typed object and, if it names/retrieves a resource or digest preimage, independently validate that object against the p56 continuation. Exact re-encryption alone is not evidence because every wrong key in a bijective family can round-trip its own decode.
- **Current lane:** #41 correctly remains waiting for a complete frozen handoff; do not search p55 under free keys while that prerequisite is absent.

**Why ranked third:** the output type is strongly constrained by manuscript position, but no local source presently fixes the inverse.

## Routes the profile actively downranks

- **p3/p39 SKY/UDP as a live network key:** a period UDP/7 or UDP/17 receiver was already searched in bounded contemporaneous sources and no host/author response was found; UDP/7 would only echo the input. Preserve the red-fragment observation, but require a newly recovered capture before reopening. [Closed #660](https://github.com/FlareZ123/liber-primus/issues/660).

[p15 result](../results/lp2-p15-fibonacci-prime-spiral.md) and [source gate](../im-results/p15-fibonacci-prime-spiral-historical-source-gate.md).
- **Stage11 133/331 as a free numerical key:** the values are authentic static HTML metadata and unique among the inspected archived 2014 stage indexes, but no original template/HTTP source identifies the target object or operation. The public Onion7 companion search is closed negative. [Onion7 gate](../im-results/lp2-onion7-2014-firsthand-capture-gate.md).
- **Direct old-key reuse:** historical tool recurrence does not justify carrying old secret values into LP2. Existing literal transfers have repeatedly failed; a new one needs an LP2-local selector first.

## Decision

The strongest supported creator-design prior is not “Cicada used simple ciphers.” It is:

> **A successful route normally makes the next operation executable from player-visible evidence and gives the solver a recognizable success condition. Complexity can be high, but hidden freedom should decrease at each step rather than increase.**

Applied to the current frontier, this makes the p49–p51 consumer problem the strongest executable source-selection question already in progress (#3103). The p14→p23 route is the strongest missing-operand acquisition question but is blocked on the exact 1977 Dutch source. The p55 terminal route is the strongest typed-output target but is correctly waiting for a fully source-selected inverse.

No additional Director issue is justified from this profile. It sharpens prioritization of existing lanes and rejects using creator-style speculation to authorize another unconstrained cipher or key search. No unknown LP2 plaintext, authentic key, complete inverse or final destination is recovered here.

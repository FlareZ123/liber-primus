# Historical Tor-page recovery: Dark Web Monitor (2013 onward)

**Agent 23, 14 November 2026. Research status: independently identified historical original-page custodian; zero retrieved 2014 response bodies, zero p56 digest matches, zero plaintext.** This is a candidate *source* for the unknown page, not a claim that Dark Web Monitor captured the target. It is distinct from the historical public Ahmia fixture (Director #792), 2014 Common Crawl WARC index (#786), 2015 OnionCity (#794), and EURECOM 2016 (#793).

## Direct route to the unsolved page

The verified solved physical LP2 p56, *AN END*, prints the 512-bit hexadecimal target
`36367763ab73783c7af284446c59466b4cd653239a311cb7116d4618dee09a8425893dc7500b464fdaf1672d7bef5e891c6e2274568926a49fb4f45132c2a8b4`
and says that a deep-web page hashes to it. The original p56 specifies neither the hostname nor the digest algorithm or page byte canonicalization. A dated, byte-exact source page, an original outgoing URL from an actual 2014 Cicada page, or an authentic key/instruction attached to that page would be substantive progress. The known `ky2khlqdf7qdznac.onion` distributed LP2 but is not thereby identified as the digest target.

**Identified archive:** The Netherlands Organisation for Applied Scientific Research (TNO) initiated the Dark Web Monitor (DWM) experiment in **2013**, and its official custodian's [history](https://cflw.com/dwm/) displays early **2014** prototype work. A contemporaneous [2014 technical paper](https://repository.tno.nl/SingleDoc?docId=82829) reports a Tor crawler harvesting HTML pages and discovering host links, with a cited **December 2013** snapshot of **2,196,410 downloaded page URLs from 1,481 active onion services**. This December 2013 data *predates* the May 2014 LP2 release and does not on its own cover the target. However, the [2025 peer-reviewed retrospective](https://link.springer.com/article/10.1186/s40163-025-00246-w) states that DWM's collection has been maintained since 2013, recording approximately **a billion pages over eleven years**, checking live onion services around **every 18 hours** and retrying offline services around every ten days. Those are provider-reported cross-period aggregate counts and schedule, not observed 2014 Cicada coverage.

**Original page-version retention is at least technically plausible.** The independent [2023 DarkDiff paper](https://www.researchgate.net/publication/373333280_DarkDiff_Explainable_web_page_similarity_of_TOR_onion_sites) describes DWM storing a new webpage version when its fetched content changes and retaining per-page metadata. A [2026 longitudinal study](https://www.researchgate.net/publication/404872745_Topical_Shifts_in_the_Dark_Web_A_Longitudinal_Analysis_of_Content_from_the_Cybercrime_Ecosystem) directly reports access to **HTML snapshots** from the same CFLW provider for **2020–2026**, after removing many content classes for its research dataset. Such snapshots demonstrate current provider-side historical-body capabilities, **not the survival, raw-byte fidelity or topical coverage of any specific May–December 2014 page**.

**Public access status:** The [DWM official product page](https://cflw.com/dwm/) gives `Register and Request Access`, a trial offer, account plans and premium API access; it describes the platform as a “wayback machine” for the Dark Web. The [2025 paper's data-availability statement](https://link.springer.com/article/10.1186/s40163-025-00246-w) directs data requests to CFLW. No free unauthenticated download endpoint or public 2014 HTML dump was documented by these sources. Searches combining the known LP2 host with DWM, CFLW and Spitters returned no public original 2014 body or archived result. **No registration, subscription, external query, or custodian contact has been performed.**

## Locked discriminating recovery procedure, conditional on owner authorization

1. **Metadata-only, coverage-first control:** Ask whether DWM still retains *any* timestamped **11 May–31 December 2014** HTTP page-version entry for the publicly established LP2 distributor `ky2khlqdf7qdznac.onion`, and whether 2014 raw response *entity bytes*, URLs and capture dates are retained. This known-host control tests whether the crawler's 2014 corpus even covers this particular original puzzle before searching for an unknown host. A negative known-host result is a coverage limitation, **not** a negative on all unknown Tor pages.
2. **If a positive control exists:** With permitted access, compare a retrieved distributor index *byte for byte* to the preserved original [stage11 HTML index](../resources/external/cicada2014-stage11-onion7-original-index.html), acknowledging that the independent archive may itself omit original transfer framing; preserve both SHA-256 values, exact length and fetch timestamps. Establish whether DWM returns raw HTML or an already-normalized text extraction before computing any digest.
3. **Only after the positive control:** Search the original 2014 snapshot URL graph and page/title metadata for source-evidenced anchors `cicada`, `3301`, `Liber Primus`, the seven known historic 2014 Cicada v2 hosts listed in [Ahmia's scoped census](ahmia-2014-onion-index-original-era-recovery.md), and the full printed p56 digest if indexed. Any candidate must be dated and traced to its actual 2014 entity bytes, not a 2020+ copy or a later description.
4. **Success criterion:** An attributable 2014 source supplies a previously unknown creator-linked URL/key, or raw captured bytes hash **exactly** to the original printed 128 hex under a historically justified 512-bit algorithm. Preserve the original entity bytes (if distributable), exact serialization and algorithm. Failure to get archive access, a 2014 known-host match or raw body bytes does **not** establish that the unknown deep-web page never existed.

## Permissions and limits

DWM is a restricted third-party intelligence archive, and its historical snapshots could contain sensitive third-party information. Keep the request limited to the **public historical Cicada service and metadata-only coverage** unless the maintainer explicitly authorizes broader access and any release satisfies the custodian's conditions. The existing [Director owner-permission gate #784](https://github.com/FlareZ123/liber-primus/issues/784) controls whether even a narrowly worded external custodian inquiry is sent. **Do not contact CFLW automatically** or infer consent from the public trial offer. A future Director may fold this source into that permission-gated custodian queue; it does not create an executable public corpus today.

**Research decision:** Preserve DWM as a distinct **2013-origin continuous Tor archive** with 2014-era acquisition evidence and a current custodial path. It is a concrete, physically plausible route to period plaintext/key material but **requires retention-and-access confirmation**. This closes only the public discoverability step, not the p56 preimage search or the Liber Primus decryption.

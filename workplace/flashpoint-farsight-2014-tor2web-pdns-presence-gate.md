# 2014 Tor2web passive-DNS history: a bounded host-witness lead, not a p56 body archive

**14 November 2026, Agent10.** This is a newly identified historical **host observation** route for the original May 2014 Liber Primus continuation, separate from 2014 Ahmia Solr, ArchiveBot/Common Crawl, 2015 OnionCity and the 2017 KAIST HTTP crawl. **No original LP2 page, confirmed service descriptor, decoder, decryption key or plaintext was recovered.** No database access or custodian contact occurred.

## Source that establishes the historical time window

The original **February 2016 Flashpoint** report, [2015 Highlights & Trends in the Deep & Dark Web, page 27](https://a51.nl/sites/default/files/pdf/Flashpoint_2015_Highlights_and_Trends.pdf), states that its Tor hidden-service survey used **passive DNS data supplied by Farsight Security** from requests for *multiple publicly available Tor2web proxy services*. It explicitly dates the collected observation period to **1 January 2011–31 December 2015**, including the 2014 LP2 publication window. This supplies an original-era measurement source. The published graph aggregates counts; it exposes **no hostname-level timestamp record, HTTP path, content bytes or response body**.

The [9 November 2021 original acquisition announcement](https://www.domaintools.com/press/domaintools-announces-acquisition-of-farsight-security) confirms that Farsight became part of DomainTools. Current [DomainTools DNSDB documentation](https://docs.domaintools.com/dnsdb/) describes historical passive DNS and a licensed query product, while its [user guide](https://docs.domaintools.com/api/dnsdb/userguide/) describes historical lookups from 2010 onward. This establishes a named plausible **metadata custodian**, but **does not** establish that the specific 2011–2015 Flashpoint Tor2web-derived subdomain records remain present, indexed with exact labels, licensed for a particular user or available without permission.

## Hard limits of the possible witness

The target **deep-web host named implicitly by solved LP2 p56 is unknown**. The confirmed 2014 distribution host `ky2khlqdf7qdznac.onion` is only a **specific query/control candidate**, not guaranteed to have been visited through any listed proxy. A separately published speculative p55 prime-sum/Base32 decoder produces `6sws36unkmvdy4b7.onion`; even a historical Tor2web DNS subdomain label containing this candidate would show only a **client-side attempt to resolve a proxy name**, and could arise from a mistyped/generated string or a nonfunctional original onion. **Neither positive DNS observation proves an actual Tor hidden service was operating or that the p56 target matches.** Historical Tor2web proxy wildcard DNS can return addresses for invalid .onion labels.

A 2014 DNS observation can give at most one dated occurrence of an **originally sought hostname** under a named proxy, and may justify searching separate period-matched **actual web/index files** for paths and content. It cannot provide a byte-identical HTTP response entity, and therefore **cannot be compared to the printed 128-hex p56 target**. A negative record in partial passive DNS sensors, even with a working control, also does not prove the service was absent: users may access Tor directly or another proxy, and sensor coverage is not complete. No bulk list of unrelated clients, packet logs or third-party browsing is necessary or appropriate.

## Narrow future owner decision

If the owner separately authorizes a domain-specific metadata inquiry, ask only whether the **specific Flashpoint-2015-derived 2014 proxy-subdomain observation series** survived at DomainTools/Farsight or Flashpoint, whether its original 2014 capture dates and full queried proxy subdomains can be checked, and whether **one or two predeclared historical host labels** were observed from **May–December 2014**. Request **only boolean presence and first/last observation UTC** for the frozen label(s), plus a known period-positive proxy host separately demonstrated in the same dataset to calibrate coverage. No visitor IPs, query logs, bulk records, Tor browsing, or arbitrary Tor2web host enumeration. Neither this public study nor present DNSDB advertisements grant access to the historical data.

**Priority:** below any archival route providing a source-original continuation URL or raw HTTP response bytes; above new untethered cipher-key brute force only if a frozen domain witness can discriminate an already-motivated locator. The project owner authorization prerequisite is tracked in [Issue #784](https://github.com/FlareZ123/liber-primus/issues/784); no third party was contacted. A historical confirmed hostname query remains a **locator gate**, with source-original HTTP bytes and the page56 digest required to authenticate any missing page.

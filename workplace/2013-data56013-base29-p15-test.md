# 2013 DATA/560.13 → BASE29 → GP29: source-fixed test

## Hypothesis

The 2013 TCP protocol exposes BASE29 as integer radix conversion (the protocol example is BASE29 3301 → 3QO). The 2013 CicadaOS DATA/560.13 file is an author-published random byte stream already used as a one-time XOR pad in the 2013 puzzle. Liber Primus uses a 29-symbol Gematria Primus alphabet. A simple, human-reproducible transfer is therefore to convert each source byte independently to its minimal BASE29 representation and use the resulting digits as GP29 key symbols.

This is deliberately narrower than a generic PRNG/key search. It does not claim that the 2013 pad is intended for LP2; it tests one exact, source-motivated byte-to-symbol operation.

## Locked operation and selector

For each byte b:
- if b < 29, emit [b];
- otherwise emit [floor(b/29), b mod 29].

Digits 0–28 are used directly as GP29 indices. The 3301 → [3,26,24] (3QO) self-test locks the radix convention. Byte offsets remain offsets in the original file; expansion occurs only after the byte offset is selected.

The start offsets are frozen from the existing p15 source construction:
- the p15 red-heading GP29 integer divided by 3301 gives byte offset 8,952,964 and remainder 560;
- the 16 printed Fibonacci-prime spiral values are relative offsets;
- the single infinity-mark continuation is F17=1597, prime index 1598, prime value 13,477.

No offset search, nearby-offset tuning, alternate radix, arbitrary reset, or post-result key expansion is allowed. Test both raw-file directions, both additive signs, and the existing keyskip1/keyskip2 relations. Use the pinned R40-B3 decoder, its 12-register panel, natural-rate L120/L240 bars, planted-text/decoy controls, and two fixed continuous windows (whole p0–55 and p15 body through p22).

## Evidence and completion rule

- Verify the 118,818,811-byte original file SHA-256 and the published 2013 XOR known-plaintext control at offset 12,821.
- Require all R40-B3 planted-control licensing and decoy gates to pass; otherwise the result is inconclusive.
- A candidate counts only if it clears both frozen L120 and L240 natural-rate bars on a predeclared offset and the untouched 120-rune continuation. Any apparent survivor must then be independently forward-re-encrypted against the original ciphertext before promotion.
- If no candidate passes, retire this per-byte-minimal-BASE29 mapping for the locked p15 offsets. Do not rescue it with new offsets or encodings.

## Distinction from existing work

The existing p15/560.13 continuation test uses the frozen R40-B3 engine with bytewise builders. Existing CicadaOS pad tests cover mod29, nibble, byte-scaled, prime-index, and bits5-reject reductions at selected offsets. The p50 table has been converted to base29 in both byte orders, but that is a different source object. This test is specifically per-byte minimal BASE29 expansion of the original 560.13 pad, with p15-selected byte offsets.

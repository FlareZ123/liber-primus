# P50 32×8 table: source-native eight-way local injectivity

**23 November 2026, Agent18. Classification: provisional structural affordance and source-conditioned negative control. No new LP2 plaintext, creator key or decoded instruction.**

## What a person can read

The original p49–51 numeric panel, in source scans `66.jpg`–`68.jpg`, has **32 printed rows of eight two-character numerals**. The exact 256 tokens and their independently original-image-audited glyphs appear in [the pinned table](../resources/liber-primus/lp2-grid-256.json). The conventional radix60 reading yields 256 one-byte values, with **161 distinct values overall**. Its original row-major bytes have SHA-256 `3b9b07d9a26e6d55c432d94d2661fdff3c2b348daed06821f2bdb23184a4b290`.

**New limited observation:** each of the **32 original eight-entry rows contains eight pairwise *distinct* bytes**. There are exactly **zero within-row repeated-value pairs**, despite **127 equal-value pairs across the entire table**. Seven alternative complete 8-cell groupings, obtained by shifting the first group boundary one through seven cells, have **1, 2, 2, 4, 3, 1, 3** duplicate pairs respectively (31 complete groups per shifted phase). Printed phase zero is the only collision-free phase under this finite shift comparison. This is a descriptive original-artifact property, neither a key nor decrypted text.

The original table's second-digit glyph inventory also contains all but one of its 60 allowable symbols: **lowercase `f` is the only unused second glyph**. That glyph represents index41 in the printed radix60 alphabet, so original byte values **41,101,161,221** are all absent. The lowercase numeral glyph is **not** the GP29 rune F or the uppercase radix60 `F`, which *does* appear; treating them as the same exception would be an unsupported extra cipher rule. Absence of `f` was already investigated in previous base59 versus base60 decisions, and is listed here only to keep the table's independent features visible.

## Frozen null and calibrated strength

An eight-choice output table could have been constructed by sampling **without replacement within each row**. Under the competing model of the exact original 256-byte multiset shuffled uniformly into eight-wide printed rows, expected repeated-value pairs are `127 × 896 / 32640 = 3.4862745098039216`. A deterministic Fisher–Yates comparison using xorshift32 seed `0x33012026` and **150,000** whole-table rearrangements produced **4,238** collision-free rearrangements, mean **3.49417333** within-row collision pairs, and plus-one fraction **0.02825981** for the observed zero-pair property. A random arrangement can therefore produce this property at about the 2.8% rate. The choice to examine row uniqueness was made after extensive earlier investigations; **the probability is descriptive, not corrected for the project's many possible postselected patterns**.

The source counts, alternative phases, missing symbol, full byte hash, planted duplicate detector, exact multiset expectation and fixed-seed shuffle are all asserted by [one read-only Windows Node22 CommonJS SFT](../sims/lp2_p50_row_local_injectivity_sft.cjs). Its input is only the already established source table.

## Mechanistic fork and why it matters little without another instruction

One specific puzzle-design interpretation of 32 source rows × eight columns is an **eight-action lookup**: a known row state and a selected three-bit action would yield one of eight distinct output bytes, allowing that action to be recovered uniquely if its row state and output are both known. The row-distinct property is a *necessary local condition* for that style of decoder. The signed 2016 continuation's wording about numbers and direction is thematically compatible with a directional action, but does not specify the row alphabet, action selector, input clock or byte receiver. The source also gives 29 GP rune types and several distinct large ink marks; identifying these as 32 coded states is a separate unproved guess.

A critical competing interpretation is simpler: the original printed entries occupy precisely the ordinary byte range0–255, and their 161-value diversity fits iid byte-like data. Random bytes have a non-negligible probability of forming locally distinct rows. Worse for the direct direction decoder, the prior [all-secret eight-column GP29 row receiver](../im-results/lp2-gp29-three-mark-fivebit-original-binary-gate.md) already proves that taking the preceding GP29 ciphertext rune as a row and any of the eight columns as the next byte modulo29 fails **9,667 of 12,901** original adjacent-rune constraints. Other simple direct p50 key/readout families have also failed in this repo. This note does **not** reopen them.

**Decision:** retain the eight-way local-injectivity observation as a weak, source-local fact. Do not promote it to `results/` or invest in row/column permutation searches. A viable successor would need an independently authored way to choose the row and action, and an exact inverse that predicts previously unread original runes or a typed external payload. Neither exists here. The manuscript's 56 unresolved LP2 pages remain unresolved.

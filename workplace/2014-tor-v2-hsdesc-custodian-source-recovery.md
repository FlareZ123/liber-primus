# Original 2014 Tor-v2 hidden-service archive route for the Cicada LP2 continuation

**Classification, 13 November 2026, Agent 10: actionable external-source acquisition hypothesis.** No unknown LP2 rune plaintext, source-selected cryptographic key, original Cicada service descriptor, or matching deep-web hash preimage was obtained. The distinctive evidence is that one independent 2014 scientific collection observed **full hidden-service descriptors** from ~80,000 services during the original Cicada LP2 period and also later crawled their HTML; a second 2014 project separately crawled original HTML. Neither project is known to have included the relevant Cicada targets or preserved the needed raw records.

## First route: a public Tor-v2 RSA identity key from a 2014 HSDir capture

Original 2014 Cicada Stage11 LP2 book endpoint: `ky2khlqdf7qdznac.onion`. The repository holds its original HTML index and archived 58 JPEGs; the site itself no longer operates under the deprecated v2 onion protocol. A Tor-v2 descriptor for this service, if obtained from an authentic 2014 HSDir, would contain the 1024-bit RSA **public** `permanent-key`. This public identity can be checked cryptographically: the first 80 bits of SHA-1 over the historically specified RSA public key encoding determine the 16-character onion name. Its corpus applicability as an LP2 decryption key would remain a *separate open cryptanalytic hypothesis* until original instructions or a decisive decoder select it.

Gareth Owen and Nick Savage, [*Empirical analysis of Tor Hidden Services*, IET Information Security 10(3), 113–118 (2016), DOI 10.1049/iet-ifs.2015.0121](https://doi.org/10.1049/iet-ifs.2015.0121), ran **40** Tor HSDir-capable relays across **six months of 2014**, observing about **80,000** Tor-v2 onion services. Their source explicitly describes modifying Tor to log descriptor publications and requests. Stronger than an address-only census, section 4.2 reports **examining every HSDesc's introduction-points field** to determine whether it carried encrypted client authorization (0.6% of their observed sample), confirming the collection had access to full descriptor content **at acquisition time**. The available paper does not say whether original descriptor bytes were *retained*, whether publication metadata can still be queried, or whether the target was among the services observed. **The same study also crawled HTML from observed services for one month near the end of its six-month period**, storing parsed data in a database while deliberately excluding images, other media and JavaScript. Its HTML-collection window is later than many of the descriptor observations. If raw HTTP body bytes were saved and the Cicada site remained accessible that late, this would independently support the same exact p56 continuation-hash inquiry as the TNO collection below; the publication confirms neither raw-body retention nor host coverage. [Original published methodology](https://doi.org/10.1049/iet-ifs.2015.0121), section 3.

Calendar corroboration:
- [Tor Project announcement dated 30 December 2014](https://blog.torproject.org/tor-80-percent-percent-1-2-percent-abusive/) reports Owen's completed six-month relay study presented that day at 31C3.
- [University of Portsmouth 2018 follow-up](https://pure.port.ac.uk/ws/files/11523722/paper.pdf) explicitly describes the original Owen/Savage six months as occurring **during 2014**.
- [Research author's publication contact](https://ietresearch.onlinelibrary.wiley.com/doi/abs/10.1049/iet-ifs.2015.0121) lists `gareth.owen@port.ac.uk`, without establishing that the address remains deliverable in 2026.

**Exact proposed acquisition query:** search any lawfully retained **2014** descriptor corpus solely for original site `ky2khlqdf7qdznac.onion`, or for the two previously derived historical 2014-05-11 descriptor IDs `epyxr4qiy5sshxxkzsesuavvysp3hrwd` and `ou4lvuwwa7tyqtbdiwzjhkowq2oqzvbb` (those daily IDs require correct date/replica and are *not* universal IDs). Ask for only the corresponding *public* Tor-v2 RSA `permanent-key`, its publication UTC timestamp and matched original identifier. Separately inquire whether the study's end-of-period HTML crawler preserved the original HTTP body from this one Cicada site; request a locally tested digest match or its exact non-sensitive matching body only if retained. Query other dates if the author's collection overlaps the host. Do not request unrelated logs, users' visits, host identities, or private keys. A matching authentic RSA public key would give a new, checkable 2014 Cicada cryptographic artifact. A database miss is **inconclusive** unless the archived collection's date and host coverage are established.

## Second route: original 2014 HTML bodies from a contemporaneous crawler

Martijn Spitters, Stefan Verbruggen and Mark van Staalduinen, [*Towards a Comprehensive Insight into the Thematic Organization of the Tor Hidden Services*, IEEE JISIC 2014, DOI 10.1109/JISIC.2014.40](https://doi.org/10.1109/JISIC.2014.40), document an active 2014 Tor crawler and an original December 2013 corpus of **2,196,410 downloaded HTML pages** across 1,481 successfully fetched services. Its published [2014 manuscript](https://gwern.net/doc/darknet-market/2014-spitters.pdf) reports nearly **2,000 new hidden-service addresses** in the subsequent five months and current network observations for **May 2014**. This is independently contemporaneous with LP2 release.

The crawler ignored media/image files and the researchers' *preprocessed text* excluded pages shorter than **15 words**. The known Cicada Stage11 HTML index has only `133` in its title and `331` in an element id, so a text-only extracted dataset would discard it. A retained raw HTTP/HTML archive, if any, could contain the original service index or a separately discovered web page referred to by solved p56's **128-hex-digit digest** `36367763ab73783c7af284446c59466b4cd653239a311cb7116d4618dee09a8425893dc7500b464fdaf1672d7bef5e891c6e2274568926a49fb4f45132c2a8b4`. The original p56 says only that a deep-web page **hashes** to this value. SHA-512 is the obvious 512-bit candidate, but the hash family and exact byte canonicalization are not explicitly supplied, and a text-only export cannot establish a source-object preimage.

**Exact proposed acquisition query:** ask whether an authorized, retained raw 2014 HTML response for *this exact onion host* survives, and if the custodians permit it, whether they can **locally** test the p56 128-hex digest against original 2014 HTTP body bytes under SHA-512. The target page may have been unlinked or outside the crawl: a null without source coverage is inconclusive. Raw data spanning unrelated Tor services may be sensitive, and should not be copied wholesale.

## Decision and downstream use

These historical collectors are distinct from the public 2020 reuploads, 2014-15 Tor2web WARC index, 2015 CARONTE database, and 2016 DUTA corpus already studied in the project. This route has a finite, independently specified **historical artifact predicate** and a clean success criterion, rather than a postchosen GP29 key or 29-symbol statistical alignment.

On a successful public-key retrieval: SHA-1/Onion-address authenticate it; preserve full byte encoding; only test an LP2 decoder if a source instruction or a discriminating locked prediction fixes its use. On a successful p56 preimage: exact-digest authenticate the original raw bytes and look for an actual continuation address, message or key; if it gives no cipher instructions, classify it as continuation evidence. On a confirmed no-archive result: retire this *specific* custodian route while preserving other historically independent source possibilities. No direct action requires another agent's cipher sweep today.

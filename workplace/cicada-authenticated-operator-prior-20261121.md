## Updated frontier: compare two genuinely independent explanations before assigning another decoder

### Route A: terminal source-table navigation to the p55 tree (currently worth a bounded opcode-discovery task)

**Starting operands, not guessed plaintext.** The genuine p57 PARABLE clause prime weights multiply to the historically printed 2013 `761.MP3` ID3 number; their prime ordinals [205,173,201] select p50 table addresses. On a **conditional global base60 reading**, their reverse-reachable component sizes are exactly **58 / 8 / 56** and 201's immediate branch census is **50+1+5**, matching the manuscript's actual 50 rune pages, numeric p50 and remaining five unknown pages. Independently, source-pinned GP0(`DIRECTION`)=98 selects table token `1C`=72, the physical p55 scan; the original p32 blurred tree is visually related to p55's sharp tree. [Existing full structural account](../im-results/lp2-parable-threeprime-whole-graph-58-8-56.md), [original tree holdout](../im-results/lp2-p32-p55-blurred-tree-correspondence.md).

**Why this could be creator-plausible:** historically verified GP prime sums and named-number lookups have actually been used. The source objects form an understandable player path from a final clear paragraph to an unexplained earlier object and an illustrated page. The strongest alternate explanation is postselection: the source does not specify prime *ordinal* addressing, base60, graph reverse-closure, or leaf-to-root page assignment.

**Actionable next decision:** establish one first-party **graph-edge or tree-graphic operation** that specifies an ordered, state-recoverable GP29 readout on the physically intact p55 76 runes. Before an unknown-cipher test, it must predict an independently withheld solved p56/p57 field or an unfit graphical feature. Agent4's independent fixed twofold p56-phi consumer with two prime2 starts is already an **exact failure at p55 rune40** with original p56 and double-plant positives; it is fully retired, so varying its clocks would be unjustified. [Original complete negative and CI](../im-results/lp2-terminal-cde-conditional-two-layer-phi-gate.md).

### Route B: an unknown original-LP2 local instruction, without transferring the terminal table

**Independent premise:** first-party historical success may require an *operation written near the target*, as with the named 2013 DH/BASE29 request and the original 2014 RSA stage. Read the original p7/p8 red five-dot packet as a candidate of that type; the published GF29 quartic identity is exact but does not select its field, point grammar or p8 body receiver. [Current p7/p8 original-gate report](../im-results/lp2-p7-fivedot-shamir-dual-dh-source-gate.md), [bounded Director #2100](https://github.com/FlareZ123/liber-primus/issues/2100).

**Decision:** await an **independent, visibly printed opcode** selecting GF29, the four x-assignments and a reversible output. Existing original-cipher consumers of the quartic failed. This route is meaningfully separate from the p50/navigation hypothesis; a new instruction, if found, could unlock local p8 content without resolving any terminal page.

### Comparative choice

Route A offers a more specific first-party *operand path* and externally checkable manuscript-sized structural matches; it still lacks a cipher opcode. Route B has visible local red/dot operands and a candidate algebraic architecture, yet its field/coordinates are analyst-constructed. Neither merits a new key or phase sweep. In particular, **successful image or number registration is a pointer test, not plaintext**, and a historically used operation is not automatically applicable to a different page.

**New LP2 key/plaintext recovered by this decision: none.** The prioritized missing input is a single author-selected transformation and clock on untouched original runes. Only a fixed, complete inverse with source-selected parameters and independently checkable output qualifies as the next cryptanalytic handoff. Other route branches already excluded by the existing historical audit are intentionally omitted here.
